# 本机加密备份与域名迁移

入口为聊天窗口标题栏「备份」，或直接访问 `/backup/`。此页面独立于聊天、OJ 和后端连接，不会自动调用模型。需要站点暗号，不需要先解锁 API 保险箱。

## 旧域名导出

1. 等正在运行的任务结束，关闭该域名其他标签页，再进入备份页。
2. 设置至少 10 个字符的备份密码，重复输入后点击「加密并下载备份」。请保存密码；没有找回途径。
3. 在本页下方重新选择下载到本机的文件，输入备份密码，点击「校验文件（不写入）」。看到校验通过及正确计数后再切换域名。
4. 如果列出缺失附件，表示原浏览器已经没有对应站内文件，备份无法补回；保留原始文件以便重新上传。文件下载成功仍以浏览器实际保存结果为准。

## 新域名恢复

1. 在新域名访问 `/backup/`，输入站点暗号。
2. 选择备份文件，用同一备份密码校验，核对来源、记录数量、模型接口地址。
3. 关闭新域名其他标签页，勾选确认，点击「恢复到当前域名」。当前仅允许空白目标，已有有效记录不会被覆盖。
4. 成功后页面自动刷新；返回聊天，用原 API 保险箱密码解锁。备份密码与原保险箱密码是两个用途，备份不会更换它。

## 覆盖范围与边界

包括 `nanaly-vault-v1` 原密文、`nanaly-config-v1` 七个设置白名单字段、`nanaly-workspace-v1`、旧 `nanaly-history-v1`、`nanaly-memory-v1`、日程 `noimpty-schedule-cache-v1`（含未同步修改和合并基准）、练习 `noimpty-learning-v1`、已保存后端地址、文章检查任务 `nanaly.article-tasks.v1`、Mao 纸条与互动记录 `mao-play-v1`、模型用量账本 `nanaly-usage-v1`，以及 IndexedDB 的 `nanaly-images-v1/images`、`nanaly-files-v1/files`。

文件附件保存的是站内解析后的文字和页图，并非原 PDF / DOCX；图片为站内 JPEG。会话内明文 API Key、站点暗号、后端令牌、声音/外观偏好不导出。工作室「导出私有记录备份」是后端状态快照，和本页的浏览器本机迁移不同；后端目标、笔记及运行环境也不在本机备份中。

整个文件使用浏览器 Web Crypto 的 AES-256-GCM，随机 16 字节盐、12 字节 IV、PBKDF2-SHA256 250000 次派生，认证范围含固定格式版本；不绑定域名。API 保险箱原密文作为备份中的一个字段保持不变，备份功能不读取保险箱明文。正文上限 64MB、文件上限 90MB；过大、版本不支持、认证失败或结构无效时拒绝，不产生部分备份。

## 故障处理

导入先认证和完整校验，再验证目标为空。恢复日志保存原空白占位记录、本次写入键及摘要。两个附件库各自在同一事务中确认空库并插入随机所有权标记和附件；回滚只处理本次已提交且内容未被修改的记录，插入失败不会删除其他页面的冲突记录。本机键最后提交并读回核对；验证全部通过后先持久保存 committed 状态，再清理标记和日志。它们不是跨数据库原子事务；失败会回滚，若中断或回滚失败则保留日志，普通页面先转到独立备份页：未提交状态重试回滚，已提交状态只完成清理，避免继续读半恢复数据。支持 Web Locks 的浏览器会串行化本域名的备份页操作，仍须关闭其他普通标签页。

文件只能保存在你自己的可信位置，不要上传到仓库或聊天。原浏览器记录不会因导出而删除，确认新域名恢复成功前请保留原浏览器数据和备份文件。

## 发布顺序

先在旧 `github.io` 域名发布备份入口并保持 Pages 域名配置不变。旧站的 Hexo `url`、后台站点地址和链接检查目标仍应指向旧域名。用户实际下载并重新选择文件校验后，再把主域名绑定到 Pages 并同步正式域名配置。不要提前启用旧站到新域名的重定向，否则旧 origin 的浏览器数据将难以从页面访问。
