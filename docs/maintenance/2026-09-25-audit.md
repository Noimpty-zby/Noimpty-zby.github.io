## 1. AI 流式回复与请求边界

实现：`source/js/noimpty-ai.js`。

| 触发条件 | 原先的失败方式 | 本次修复 |
|---|---|---|
| SSE 连接在只收到部分内容后结束，既没有 `[DONE]` 也没有 `finish_reason: stop` | 半截回答可能被当作正常完成 | 将无完成标记的 EOF 视为失败，保留已经显示的文本并提示重试或继续 |
| 兼容网关发送 `finish_reason: stop` 后关闭连接，没有额外 `[DONE]` | 不能简单把所有缺少 `[DONE]` 的回复都判坏 | 接受明确的 `stop` 完成标记；长度截断和服务商过滤仍属于未完成 |
| 服务连续发送超大事件、长行、正文或推理片段 | 读取及字符串累加缺少上限 | 总接收量上限 4 MiB；单事件和未分行缓存上限 262144 字符；回答上限 128000 字符，推理上限 256000 字符。超过限制中止并释放流 |
| 模型、标题生成、研究调用或检索端点返回重定向 | 请求可能带着正文继续到另一个地址 | 相关请求使用 `redirect: error`、`credentials: omit`、`cache: no-store` |

回归入口：`chat-regression.test.mjs`。新增用例覆盖无标记 EOF、`stop` 后 EOF、超大事件/正文/推理、流取消和 reader 解锁，以及请求选项。UTF-8 分块、CRLF、多行事件、无末尾换行等既有回归继续保留。

边界：这些大小限制用于约束应用持有的数据，不等同于对浏览器网络栈内存或服务商行为的完整证明。拒绝重定向也不能保证用户主动配置的 API 地址可信。

## 2. 图片、文档与历史附件

实现：`noimpty-ai.js`、`nanaly-vision.js`、`nanaly-files.js`。

- 当前附件、历史图片与 PDF 扫描页共用一次请求的 **2 张图片**预算。当前附件先占用预算，历史回读只使用余量；未发送的图片或扫描页明确标为“未发送、未读取”。文档正文继续共用一次请求 **48000 字符**预算，不能因回读多个历史记录而重复放大。
- 从 IndexedDB 读回的图片必须匹配请求 ID，类型为 JPEG，且内容为受长度限制的 JPEG data URL。远端图片 URL、SVG data URL、超大或损坏记录不能直接进入预览或模型请求。
- 图片读取途中被删除时，迟到结果不能重新进入缓存。图片引用清理使用已访问对象集合，调用方传入循环对象也不会无限递归。
- 图片文件大小必须是正的安全整数，且不超过 10 MiB。压缩结果限制为 2600000 个 data URL 字符。图片内存缓存按 64 条和约 24 MiB 的编码字符串长度计数；本机持久化失败且暂存已满时拒绝新图，保留先前尚未落盘的图片。
- PDF 在启动解析任务前检查取消状态。文字提取达到 60000 字符预算后停止拼接该页后续文本，记录截断范围；解析取消或超过 45 秒时销毁任务，并避免销毁 Promise 的拒绝变成未处理异常。

现有附件范围继续保留：最多 2 个文档、单文件 10 MiB；PDF 最多处理 30 页、最多生成 2 张扫描图；DOCX 的 ZIP 检查保留展开体积和条目数量上限。这些原有约束不能单独证明任意恶意 PDF/DOCX 都可低成本解析。

回归入口：`nanaly-core-upgrade.test.mjs`、`nanaly-image-storage.test.mjs`、`nanaly-files.test.mjs`、`nanaly-provider-vision.test.mjs`。新用例核对当前/历史图片和扫描页共用预算、损坏存储拒绝、临时存储耗尽保全、取消后不启动 PDF worker，以及达到文本上限后不再遍历整页输出。

边界：附件先在浏览器本机解析/保存；发送问题时，实际选中的文本和图片仍会进入所配置的模型服务。未发送、已截断和读取失败的内容不能被描述为已经完整阅读。

## 3. 语音与音频资源

实现：`nanaly-voice.js`、`nanaly-audio.js`；手动检查入口整理后为 `tools/checks/voice-check.mjs`。

- 原先先读完整 `response.blob()` 再检查大小。现在优先检查 `Content-Length`，并在支持流式读取的响应上逐块累计，超过 **12 MiB** 立即取消；没有流 reader 的兼容分支仍在得到 Blob 后检查。空音频和异常文本/JSON 响应不能播放。
- 停止发生在音频下载等待期间时，主动取消 reader，使请求结束；被取消的结果不应随后开始播放。
- 可选的状态订阅者抛异常时，不再阻断主播放流程或停止操作。
- 朗读分段长度必须是至少 2 的整数，避免无效上限导致死循环或拆坏代理对。WAV 读取前检查输入体积；时长测量识别流式 WAV 的占位长度，避免把实际有数据的音频算成零时长。
- `voicecheck` 严格校验参数，`--help` 不读密钥、不请求服务。没有成功播放、仅完成部分轮次、无效时长或超时长，均不能被统计成通过。

回归入口：`nanaly-voice.test.mjs`、`nanaly-audio.test.mjs`、`manual-checks.test.mjs`。测试使用模拟响应与音频对象，覆盖无穷音频流、挂起时停止、订阅异常、无效分段长度和检查器误报通过。

边界：**没有执行付费语音检查，也没有据此确认真实听感、服务端发音、浏览器自动播放策略或所有设备的 AudioContext 表现。** `voicecheck` 默认是真实服务检查，不应作为普通离线测试运行。

## 5. 日程三方合并与自动完成

实现：`source/js/schedule.js`、`tools/daily-report/schedule-auto.mjs`、`tools/daily-report/sources.mjs`。

原来的任务级“我改过就整条用我的”会把互不冲突的更新覆盖。例如，本地只改任务文字，而后台把同一任务自动完成，保存时后台的 `done` 就可能消失。

当前代码按任务 ID 对齐基准、本地和远端版本，分别处理文字、日期与状态。文字编辑可以与远端完成或日期移动共存；同一字段冲突仍采用本地优先策略。`when`、`done`、`autoAt`、`autoWhy` 作为判据与完成证据的一组处理，更换判据时不能混入旧判据的自动完成证据。删除遇到另一侧修改时保留修改。

PJAX 进入日程时重新读取 `window.NOIMPTY_STUDY`，修复首次在首页加载脚本、之后进入日程仍一直使用空学习数据的问题。

后台同时修复三条路径：

1. 自动完成先调用已有 `validateScheduleData`。非法 JSON、无效日期、重复任务 ID 或错误的 `done` 类型会失败并保留文件，不能被当作“没有任务”。
2. 自动完成或提交失败会使对应命令返回失败，不能只打印日志后让工作流保持成功。
3. 评论采集保留不含正文的历史完成信号（文章路径、作者、时间），日报内容仍只取报告窗口。漏跑一两天后，符合任务日期的旧回复仍可用于完成任务。

回归入口：`schedule-merge.test.mjs`、`schedule-ui.test.mjs`、`schedule-auto.test.mjs`、`schedule-data.test.mjs`、`daily-regression.test.mjs`、`backend-audit-regression.test.mjs`。

最后复核补充：只移动日期时，保留远端新判据，只清除旧日期的自动完成证据；保留手动完成和新日期产生的有效证据。最终日程合并 19 项、日程 UI 10 项全部通过。同字段竞争仍有明确的取舍策略，不声称任意多端并发编辑都无冲突。

## 7. 本地模型导入与资源工具

实现：`tools/assets/build-live2d-model.mjs`；回归为 `tools/tests/tooling/live2d-import.test.mjs`。

原工具把输出名插入 shell 统计命令，并直接按模型包引用拷贝、写入。当前修复移除该 shell 调用，输出名限制为长度不超过 64 的小写字母、数字和单个连字符组合。Moc、贴图、物理、表情、动作等模型引用在读取前检查路径类型、真实路径、包内边界、普通文件和大小；输出路径检查现有符号链接。

模型包要求一个 `.model3.json`，具有 Moc 和贴图；单个引用文件上限 50 MiB、贴图最多 16 张。先准备引用与转换结果再开始写出，避免已知缺失引用或图像转换失败时先留下部分结果。贴图保持比例，最长边缩至不超过 2048，较小贴图不放大；动作声音文件随其引用拷贝。

回归覆盖输出名中的路径穿越和 shell 字符、包外引用、符号链接、缺失资源、有效贴图转换的比例及动作声音。
