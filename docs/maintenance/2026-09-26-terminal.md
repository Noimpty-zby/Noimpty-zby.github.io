# 2026-09-26 代码小屋的 Git / Linux 改成真正的终端

后端运行记录显示，用户在 Linux 里是一条一条地试命令：`pwd`、`cd test`、`touch test1`，然后连着三次 `nano test1` 和一次 `code .`，都得到 `command not found`。原来的 Git/Linux 是「编辑器 + 执行整段脚本」，没有键盘输入，也没装编辑器，每条命令都要删掉重写再点执行。这次把这两种语言改成交互式终端，脚本模式保留。

## 行为

- Git/Linux 默认显示 xterm.js 终端，工具栏「终端 / 脚本」切换，按语言记在浏览器。提示符 `learner@nanaly:~$`，有 `nano`、`vim`、Tab 补全（含 Git 子命令）、`↑` 历史、`Ctrl+R`；选中后 Ctrl+C 复制，Ctrl+V 粘贴；触屏设备多一排 Tab/Esc/Ctrl+C/Ctrl+D/方向键。
- 目录、导出变量、别名、函数、命令历史和 `/work` 文件在每条命令后记下，会话怎么结束都保存（exit、关页面、断网、切语言/模式、闲置 30 分钟、满 3 小时、后端重启）。页面收到 `saved` 后在终端里写明原因，按任意键重开。
- 同一工作区同时只有一个终端；新窗口接管时旧会话先保存。终端开着时同一工作区的脚本执行返回 409，页面点「执行脚本」、重置环境和 `LEARNING_LAB.runCurrent` 都会先等终端保存关闭。
- 「请教娜娜莉」的上下文在终端模式下带 `terminal.screen`（最后约 60 行）。
- 控制台的「终端」页签改名「输出」，下拉里的 Bash 改名 Linux。

## 实现

- `server/lib/websocket.mjs`：手写的 RFC 6455 服务端（部署不带 node_modules）。`server/lib/terminal.mjs`：票据、会话、保存。`POST /api/terminal/ticket` 发一次性票据，`/api/terminal` 升级为 WebSocket。
- `server/runner/shell-session.py terminal`：容器内开 PTY 跑 `bash -i`，stdin 分帧（类型 + 长度），PROMPT_COMMAND 每次记状态；bash-completion 自带的函数不进存档。
- Dockerfile 在 PyTorch 层之后单独加一层装 `nano vim bash-completion`，并用系统级 excludesFile 忽略工具在 `/work` 留下的点文件；上面的层缓存不受影响。
- `source/js/learning-terminal.js` 是 xterm.js 的包，首次打开终端才加载；`_config.butterfly.yml` 里一个 `type="text/plain"` 的标签只用来带内容指纹 URL。

## 验证

- 本地：`shell-terminal.test.mjs`（真实 PTY 里的 bash：跨会话目录/变量/别名/函数/历史、窗口大小、挂断后仍保存）和 `terminal.test.mjs`（WebSocket 帧、票据单次与 Origin、保存与续接、接管、exit、闲置、关停）；这两者经 `tools/tests/server/local-docker.mjs` 用本机目录代替容器跑真实 API。`learning-lab.test.mjs` 新增 6 项终端连接与工作区交接。
- 浏览器（本地构建 + 本地后端 + 无头 Chromium）：桌面 `/learn/`、Linux 文章分屏、390 宽手机、深浅两色。实际打字执行命令、nano 写中文并保存、↑ 调历史、切脚本模式后脚本在终端留下的目录里读到文件、切回终端自动重开；空闲 22 秒后连接仍在；页面零报错。终端包只在打开终端时下载，URL 带指纹。
- 真实 Docker 部分由 `docker-terminal.integration.test.mjs` 在部署时于服务器上跑：提示符、uid、TERM 与窗口大小、无网络、nano 保存、脚本接着终端的目录和变量、历史跨会话、运行中断开仍保存、Git 仓库与 Tab 补全、exit。本机没有 Docker 权限，这一项只在服务器上执行。
