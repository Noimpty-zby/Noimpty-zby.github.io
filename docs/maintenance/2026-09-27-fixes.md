# 2026-09-27 博客翻新后的修复与验收

本轮复核了终端式代码小屋、内页角色和后端部署脚本，修复以下问题。本记录范围为代码变更、本地回归与浏览器验收。

## 终端语法检查与并发

- Git/Linux 终端开着时，语法检查曾被该终端持有的工作区锁拒绝。现在检查只处理提交的源码，忽略旧页面携带的工作区编号与版本，不恢复、初始化或写回工作区；活动终端、快照和锁保持原状。
- 多个请求同时到达时，原来的“检查空位，再由调用方占位”可能让请求同时通过。现在返回名额前就完成预留，遵守配置的并发上限。
- 名额取得后立刻取消或关闭，以及 Docker 清理抛错时，都会释放本次请求的名额、工作区锁和临时输入，避免后续请求一直等待。

实现与回归：`server/lib/runner.mjs`、`tools/tests/server/runner-boundaries.test.mjs`。边界测试使用模拟 Docker 调用，核对语法检查不改文件、并发峰值和取消/清理后的资源释放。

## 部署失败与验收缓存

- 将重启命令失败纳入回滚：新版本重启或健康检查失败都会恢复旧代码和环境配置，再重启并检查旧版。旧版恢复失败会明确报告，不能宣称已经恢复服务。
- 镜像存在不再等于验收通过。只复用当前线上成功版本的记录，记录关联实际镜像 ID，以及后端、测试、课程参考代码和部署脚本的内容；新版本健康检查通过后才保存记录。
- 首次升级没有记录、同镜像下修改代码、镜像标签指向了新镜像，或集成测试失败后重试，都要重新测试。`--full` 始终重测；同一组输入强制重测失败后，旧成功记录失效，普通重试也不能跳过。

实现与回归：`tools/deploy/backend-remote.sh`、`tools/tests/tooling/deploy-backend.test.mjs`。11 项部署测试通过，使用临时目录与假的 Docker、systemctl、curl；其中 4 项关键新增回归在修复前脚本上均失败。Bash 语法检查通过。完整操作说明见 [后端更新部署](../features/learning-backend.md#更新部署)。

## 手机气泡与键盘操作

课程页手机布局中的单个角色气泡原先位于页头上方，容易被 `overflow: hidden` 裁掉。现在移到角色下方，并调整气泡箭头。

角色使用原生按钮，支持 `Tab` 聚焦以及 `Enter` / 空格切换台词，显示键盘焦点；台词区域设置为状态区域。PJAX 再次初始化时复用按钮，避免嵌套按钮或重复处理一次点击。

实现与回归：`source/css/interior.css`、`source/js/interior-deco.js`、`tools/tests/site/interior-deco.test.mjs`。

## Linux 第七章说明

修正 `tail -f` 的原地重写说明：只有检测到文件变短时才提示 `file truncated` 并从头继续读取。同大小覆盖可能没有新输出；文件名被替换时仍跟着旧文件，不能笼统地说任何保存都会重新输出，或换名后绝不会再有输出。

已用临时文件验证同大小覆盖没有产生新输出，并核对 [GNU tail 文档](https://www.gnu.org/s/coreutils/manual/html_node/tail-invocation.html)。修改位于 `source/_posts/Linux-Command-Line-Chapter7.md`。
