# 2026-09-28 收尾验收

本次在 `96e068b` 安全迁移版本上检查日常发布、前端功能、私密资料、自动任务及后端运行稳定性，只修复确认的问题。文章和页面设计没有大改，后续仅发文章时无需部署后端。

## 修复内容

### Mao 普通联动不再依赖私有后端

迁移时共用的权限判断把普通聊天、语音嘴型、文章标题及课程提示也绑定到后端连接，导致站点已解锁、聊天可用但后端未连接时这些功能静默停止。

现在分别检查页面解锁和私密资料权限：普通联动只要求页面解锁，日程和后台任务仍要求已配置的鉴权后端。新增断开后端场景的回归，确认恢复联动时不会读取私密日程。

### 后端启动与关停完整收尾

- 原来的 15 秒强制退出可能截断较慢的终端原子保存及快照，调整为 90 秒最终期限；服务示例使用 `TimeoutStopSec=105s`。
- 关停时逐阶段处理异常，继续尝试清理执行容器；已接收的 HTTP 请求完成后才释放私有存储锁。启动中途失败也使用同一清理流程。
- 启动时若无法枚举或删除遗留执行容器，拒绝报告就绪并保留任务输入，供下次恢复；删除失败的容器继续受跟踪。
- 回归覆盖较慢保存、未完成 HTTP 请求、重复停止信号、清理异常、启动失败和遗留容器检查失败。90 秒仍是最终上限，不保证在系统故障下无条件保存成功。

已有服务器的 unit 不会被 `deploy:backend` 自动替换。应用本轮后端变更时，需单独核对并更新停止等待时间、执行 `systemctl daemon-reload`；保留其他既有服务配置。部署会断开终端，先保存并结束正在使用的练习。

### 发布时只读检查自动任务后端

新增 `tools/checks/private-backend-check.mjs`：校验 HTTPS 地址、两项后台连接配置、四类资料的迁移版本与数据结构。仅执行固定的四次 GET，限制超时及响应大小，禁止重定向；不生成文件、不调用模型、不发邮件、不写入资料，输出固定的脱敏结果。

Pages 的 `private-backend` job 单独运行检查，不安装 npm 依赖，密钥只传给检查步骤，不传给静态构建或上传产物。失败使整个工作流显示异常，但 `deploy` 仍只依赖 `build`，后端异常不阻止新文章发布。

两条自动任务的手动演练说明已明确：`dry` 不发布、不发信，但仍可能调用模型或搜索服务并计费。

- 本轮浏览器自动化连接超时，未完成真实浏览器逐项点击、播放和手机布局验收；线上 HTTP 检查与脚本行为回归不能替代它们。

- 普通文章 HTML 仍为前端软锁；本机日程草稿没有新增静态加密。迁移前已经公开的数据及第三方副本不能保证收回。
