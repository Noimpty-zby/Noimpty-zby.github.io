## 发现的问题

### 服务器装了新内核，还没有重启

10-15 自动更新装上了 `linux-image-6.8.0-147`，从那天起 `/var/run/reboot-required` 就一直在，可服务器跑的还是 6.8.0-142。自动更新不会自己重启，新内核里的安全修复要重启以后才生效。服务器上跑着执行用户代码的容器，内核漏洞会直接影响容器隔离，所以这件事值得做。命令见文末。

### Dependabot 的两条 markdown-it 提醒

10-21 推送时 GitHub 提示 markdown-it 15.0.2 有两条公告，GHSA-gfr2-rv44-r23c（高危）和 GHSA-vfgh-jcmw-g37q（低危），都是特定输入下渲染时间按平方增长。markdown-it 只在 hexo 构建时渲染仓库自己的文章，不进页面。15.0.3 已经修好，而且在原来声明的范围里，`npm update` 只改 lockfile。升级前后把 source 下 113 个 Markdown 文件按站点的渲染配置各渲染一遍，输出逐字一致。推送以后 #6、#7 自动标成了 fixed。

### npm audit 新报了 seroval 的两条

`npm audit` 从 10-06 的 8 条变成了 16 条，其中 2 条是严重级，来自 seroval 的两份新公告（GHSA-p6vx-979v-rg4c、GHSA-jp82-f5mq-hwhp）。seroval 只经 asciinema-player → solid-js 进依赖树，而站点用的是 `tools/assets/vendor-asciinema.mjs` 从 `dist/bundle` 复制的现成打包文件，不经过 node_modules 里的 solid-js，所以页面不受影响。10-06 时 solid-js 1.9.15 把 seroval 锁在 `~1.5.4`，没有升级路径；1.9.16 起改成了 `~1.6.8`，所以这次 `npm update solid-js` 就能修掉。

`npm audit fix` 还会顺带把 mermaid 从 11.16.1 升到 11.17.2，但新版仍然依赖 katex `^0.16.47`，一条也修不了，所以没有采用。全站没有一篇文章用 mermaid，Butterfly 只在页面里有 mermaid 图时才加载它，它自带的旧版 katex 实际上碰不到。

### 文章页在深色模式下的无障碍问题

线上 9 个页面（首页、课外、复习、学习台、日程、资讯、Linux 第十三章、Git 第十六章、DSA 第五章）跑了 axe，前 6 个没有问题，3 篇文章报了 4 类：

- 代码块行号的对比度只有 3.83:1（要求 4.5:1），三篇一共 68 处。这次检查是在晚上跑的，站点按时间切到了深色模式，主题在深色模式下把行号设成 40% 的白，叠在 `#171717` 上就不够。浅色模式用的是 darker 配色，行号是 5.1:1，所以 10-03 下午那次没有查出来。
- 横向滚动的代码块没法用键盘聚焦（scrollable-region-focusable），每篇一处。宽代码块滚动的是 `figure.highlight` 里面的 `<table>`，它里面没有能聚焦的东西，只用键盘就滚不动。

- DSA 第五章有一张表格的第一个表头是空的（empty-table-header，轻微）。这是文章正文里的表格，改它要动文章，这轮没有改。
