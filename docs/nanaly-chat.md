# 娜娜莉聊天工作区

## 打开聊天小屋

点击左下角猫猫头像。桌面默认使用右侧靠边窗口，宽 520px，上下各留 16px；聊天记录、输入框和工具栏分别占用自己的区域。

- **靠边**：适合一边读文章一边聊天，拖动左边缘调整宽度。
- **浮窗**：默认 620 × 740px，拖动标题区移动窗口；左边缘调宽，下边缘调高。
- **专注**：居中显示更宽的窗口，最大宽度 1160px，适合长回答、代码和资料。

窗口会限制在屏幕范围内，尺寸和布局保存在当前浏览器。双击调整边缘恢复默认尺寸；键盘选中边缘后也可用方向键调整，按住 Shift 加大步长。手机使用接近全屏的窗口，随软键盘和可视视口调整，并把“声音”入口放在话题栏中。

“话题”和“记忆”在窄窗口内以覆盖侧栏打开，在宽窗口内与正文并排。点“收起”或按 Escape 关闭侧栏。浅色、深色主题沿用博客玫瑰粉配色；猫猫表情、细小星点和消息气泡不会遮住正文，减少动态偏好下停用动画。

## 连接模型

打开娜娜莉 → 设置，在“硅基流动 API Key（图片、文件和声音）”填写密钥，并用原保险箱密码保存。已经保存过硅基流动密钥时，解锁后即可使用新增功能。

| 用途 | 当前默认配置 |
| --- | --- |
| 硅基流动接口 | `https://api.siliconflow.cn/v1` |
| 图片、文件及相关追问 | `Pro/moonshotai/Kimi-K2.6` |
| 声音合成 | `FunAudioLLM/CosyVoice2-0.5B` |

文字聊天保留原文字模型配置；只配置硅基流动也可以文字聊天。自动话题标题优先使用已配置的硅基流动模型，没有该密钥时使用文字模型。图片、文件模型可在高级设置中替换；声音当前固定使用 CosyVoice2，以支持声线和自然语言语气控制。

密钥分别保存在同一个本机加密保险箱里，不写入仓库。发送问题、检索规划、自动生成标题及生成语音都可能产生服务商费用。模型供应、额度及价格以账号控制台为准。

图文请求使用官方支持的多模态消息格式；CosyVoice2 的情感和语气控制使用文本指令。接口依据：[硅基流动多模态输入](https://docs.siliconflow.cn/docs/userguide/capabilities/multimodal-vision)、[硅基流动语音合成](https://docs.siliconflow.cn/docs/userguide/capabilities/text-to-speech)。

## 对话、历史与记忆

点击“新话题”即可开始，不需要填写名称。发送第一条问题后先生成本地临时标题；首次成功完成回答后，模型会概括对话标题。标题请求失败时保留已有标题，不影响正常聊天；手动改过的名称不会被自动覆盖。

误触“新话题”但没有消息、草稿或待完成回答时，不会在历史列表堆积空记录，继续点新话题会复用空白话题。旧记录中的默认空话题会在读取时整理；有草稿、手动命名或受撤销记录保护的内容会保留。

在“话题”里搜索、切换对话，点每条右侧的“⋯”可重命名或删除。删除整个话题和清空当前消息都支持 **15 分钟内撤销最近一次操作**；再次清空或删除会替换上一条撤销记录。每个浏览器最多保存 40 个话题，每个话题保留最近 120 条消息；发送给模型的历史另有窗口和字符预算。

收起窗口后，文字回答继续生成；停止按钮会中止请求，切页、锁定也会停止当前请求。发送时立即保存问题，失败或中断可重新回答或接着说；消息支持引用和修改问题。

普通问题可以触发只读的博客检索、文章阅读和联网搜索，无需固定前缀。“全站搜一下：”和“上网搜：”仍可指定范围；联网搜索需要 Tavily 密钥。每次最多三轮规划、五次工具执行。回复下方的来源卡使用实际检索的 URL 与原文片段；引用编号无法对应时明确提示，不把“未检索到”当作“没有写过”。

“记住：”“更正：”“待办：”会打开确认表单。只有确认的内容进入长期记忆，可在“记忆”中编辑或删除；阅读停留和访问次数不会被当作已确认的偏好。对话、草稿、记忆、图片和文件都保存在当前浏览器，不自动同步到仓库或其他设备。清除浏览器站点数据会使这些本地内容不可用。

## 图片与文件

**图片**支持选择、粘贴和拖入 PNG/JPEG/WebP，每轮最多两张、原图每张 10 MB。图片先在本机重新编码、压缩并去掉元数据，点击发送后才交给视觉服务；压缩图保存在 IndexedDB，历史中只存引用。

**文件**可用输入框旁的回形针选择，或拖到聊天窗口。每次最多两份，每份 10 MB；支持 PDF、DOCX、TXT、Markdown、CSV/TSV、JSON/JSONL、YAML、XML，以及常见代码和配置文件。旧版 DOC 请另存为 DOCX；Excel、PowerPoint、音视频和任意 ZIP 包目前不支持。

文件先在浏览器解析，原文件及解析结果保存在本机 IndexedDB。选择文件不会向模型上传内容；点击发送后，将提取文字及本轮可用的扫描页图像交给已配置的硅基流动模型。文件卡会显示实际读取范围。每次模型请求的文件正文共享 48,000 字符预算，优先本轮新文件，历史文件使用剩余额度；单份已解析的 60,000 字符仍保留在本机，但不会每次全部重传。

| 类型 | 读取范围与限制 |
| --- | --- |
| 文本、代码、CSV、JSON | 每份最多前 60,000 字符；UTF-8，或带 BOM 的 UTF-16。其他编码需先另存为 UTF-8。读取文本，不执行代码或公式。 |
| DOCX | 提取正文和表格文字，最多 60,000 字符；不读取嵌入图片、对象及精确排版，不推测页数。过大或异常的压缩结构会拒绝解析。 |
| PDF 文字层 | 最多前 30 页、合计 60,000 字符；显示已提取页码、截断位置和未读取部分。文字层不包含完整图表和精确排版，需要时另附截图。 |
| PDF 扫描页 | 文字稀少的页面尝试转成图片，每份最多两页。扫描图与普通图片共享本轮合计两张的名额；超出的扫描页明确标记为未发送、未读取。 |

有密码的 PDF 需先解锁；损坏文件会报告解析失败。长扫描 PDF 请拆分，或只附需要识别页面的截图。PDF 单次本机解析超过 45 秒会停止并提示拆分。

历史追问可以重新读取近期附件；附件已经丢失时会明确说明，并要求重新附加，不能把历史文字描述当作重新读到了原文件。待发送附件随所属话题保存，切换话题后回来会恢复，避免把另一个话题的附件带进来。浏览器不允许持久存储时，当前页面仍可使用，刷新后需重新附加。锁定或进入设置会隐藏待发送预览；清理附件会保护其他话题、待完成回答和撤销记录所需的文件。

## 声音与提示音

点“声音”打开设置，可试听、调整语速，选择“清甜猫娘”“温柔陪伴”“元气满满”。默认“清甜猫娘”使用 CosyVoice2 的 `diana` 预置女声，加上清甜、轻盈的音色提示；“温柔陪伴”使用 `claire`。这是 AI 合成女声，实际音色由模型决定，不承诺特定角色或声优的声音，也没有上传录音进行声音克隆。

**“随文字表达情绪”默认开启**，可在声音设置中关闭。使用已配置的硅基流动模型（默认 `Pro/moonshotai/Kimi-K2.6`）理解整条回复、动作描写及对应问题的前 1,200 字，区分开心、兴奋、难过、安慰、惊讶、认真、好奇、害羞、打趣、克制不满和平静。一条回复有情绪转折时，按句段切换语气；声线保持一致。判断考虑否定、引用、第三人称和反讽，不直接按情绪词匹配；动作描写不读出来。

模型只标注原文句段的情绪、强度和置信度，不能改写朗读内容或下发任意声音指令。置信度低于 0.75 时平静朗读；判断请求失败、超时或结构不完整时，会提示并退回平静语气。模型判断和实际声音仍可能有偏差，这个阈值不是准确率保证。

回复下方的朗读按钮可播放或停止该条回复。**自动朗读默认关闭**，开启后只在窗口打开、页面可见且新回答成功完成时启动；加载旧历史不会自动朗读。收起窗口、锁定、切换话题或切页会停止正在播放的声音。浏览器如果阻止播放，按提示再点击一次朗读即可。

可安全处理的 WAV 会追加 350 毫秒静音；遇到无法安全改写的 WAV 头时，保留原始音频交给浏览器播放，不让尾音处理阻断朗读。识别流式占位长度时，除 `0xFFFFFFFF` 外也接受写成无符号的小负数（硅基流动的 CosyVoice2 每条响应都用这种写法），否则它返回的音频会被整体判为格式无效。两条播放路径都会在自然结束后等待 500 毫秒再释放资源；主动停止仍会立即生效。浏览器无法播放的音频会移出缓存，重试时重新生成。正在朗读时，新回复的自动朗读不会打断当前声音。

语音模型靠句式而不是分隔符区分指令和正文：祈使句被当作指令执行，陈述句会被当成正文念出来。语气提示因此固定为两句“请”开头的短句，合计不超过 40 字；句数和长度都会影响提示被念出的概率，任何措辞都不能保证不出。生成的音频时长会与朗读文本对照，明显超出时判定为提示被念了出来，丢弃该次结果并改用不带任何提示的纯文本重新生成一次；重新生成仍然超长时会提示，音频照常播放。

朗读会跳过链接地址和格式标记，用简短说明代替代码块；长文字按句分段，单次最多 16,000 字符。语气结果按原文、对应问题和模型短暂缓存，音频按内容、实际语气和声音设置缓存；两者仅在当前页面内存中保存，刷新、锁定或更换账号后清除。理解语气、生成声音及播放阶段均可停止。

开启情绪表达时，首次朗读还会把上述语气分析材料交给硅基流动，额外产生一次模型请求，token 用量计入会话统计；重播命中缓存时不重复请求。试听和朗读会将处理后的文本交给硅基流动生成音频并消耗服务额度。官方说明 TTS 按输入文本的 UTF-8 字节数计费，费用以服务商账单为准；聊天气泡里的 token 数不代表语音费用。[语音计费与能力说明](https://docs.siliconflow.cn/docs/userguide/capabilities/text-to-speech)

轻柔提示音默认开启，可在声音设置中关闭；它由浏览器本机生成，不请求语音 API，不消耗模型额度。后台页面不会触发提示音。

## 链接检查

在文章中点击“检查本文链接”或发送同名请求。检查范围是当前已发布文章的站内链接与图片，最多 24 项；站外链接和超限项明确列为未检查，不宣称全站健康。

配置的 GitHub token 对该仓库具有 Actions 读写、Checks 读取权限时，会派发 `nanaly-article-check.yml`；工作流本身只有 `contents:read` 和 `checks:write`，不发评论、不修改文章。没有凭据或权限时可以在浏览器检查当前页面。任务卡展示真实状态、检查范围、时间和结果，后台结果必须匹配请求编号、运行编号和提交 SHA。刷新页面只恢复记录，点击“刷新任务状态”才联网核验。停止等待不会假装取消已经运行的后台任务。

## 验证

`npm test` 包含窗口尺寸和键盘操作、会话删除与标题竞态、文件解析和读取范围、语音尾音、情绪规划校验、混合语气、停止与缓存、工具循环、Provider 密钥隔离、图片存储、话题恢复、流式停止/失败、任务派发与来源接续的离线回归。`npm run build` 构建站点，`npm run linkcheck` 检查站内链接，`npm run leakcheck` 检查生成内容是否泄露受保护资料。

离线回归不使用真实密钥，不发付费请求。真实服务的账号权限、模型可用性、识别准确度和最终音色，需要解锁自己的配置后体验确认。

`npm run voicecheck` 是对着真实服务的实机检查，**不在 `npm test` 里**：它要花钱、要联网，结果还带随机性，不适合当门禁。它用 `node:vm` 把 `source/js` 下的语音模块原样搬进 Node，配一个不出声的播放器，跑的是线上那条真链路而不是仿制品，报告短回复的语气提示泄漏率、是否触发重传、补尾音是否真的生效。密钥从 `NANALY_TTS_KEY` 或 `~/.nanaly-tts-key` 读，不接受命令行参数。改语音相关代码、换模型，或怀疑服务端改了响应格式时跑一次；`-n` 调次数，`--samples <目录>` 额外落盘音频供试听。

有两类问题只有它能照出来：服务返回的 WAV 头换了写法（离线用例里的占位长度是构造出来的，撞不上真值），以及语音模型把语气提示当正文念出来（离线用例喂的是 mock 音频，听不出在念什么）。

语义验收样例位于 `tools/fixtures/nanaly-emotion-cases.json`。运行 `node tools/tests/nanaly-emotion-eval.mjs` 检查样例与分段契约，不发网络请求；这不代表真实模型通过了准确率测试。需要实际评估时，显式设置专用 `NANALY_EMOTION_EVAL_KEY`、`NANALY_EMOTION_EVAL_BASE_URL`（以及可选 `NANALY_EMOTION_EVAL_MODEL`），运行 `node tools/tests/nanaly-emotion-eval.mjs --live`。它会逐条调用模型并报告结果及用量，不生成付费语音；最终情绪听感仍需试听。
