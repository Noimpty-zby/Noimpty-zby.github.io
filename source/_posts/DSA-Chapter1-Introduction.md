这一篇写在正式学习数据结构之前，目的只有一个，就是先建立一个整体的概念。

具体的数据结构，比如链表怎么插入、树怎么旋转，后面每一章都会讲到。但是那些章节都建立在同一批前提之上，包括数据到底存放在内存的什么地方、为什么物理排列方式只有数组和链表两种，以及说一个操作「快」的时候，到底是在比较什么。如果一开始就把这些问题含糊过去，那么后面每学一种数据结构，都会多一层模糊的地方。

所以这一篇不讲任何具体的数据结构，只把基础打好。

## 一、什么是数据结构

用一句话来说，数据结构研究的是数据在主存储器（main memory）里应该怎样排列，从而让存储空间用得更节省，让 CPU 读取数据更快。

这个定义里有两个词需要先弄清楚：

- **主存储器**。这里指的不是硬盘，也不是数据库文件。数据结构讨论的是程序运行期间，数据在内存里的样子。
- **高效**。高效总是针对某一批操作而言的，并不存在所有操作都快的数据结构。比如数组查找快、插入慢，链表则正好相反。之所以要学这么多种数据结构，就是因为不同的任务需要选择不同的排列方式。

所以以后每学一种数据结构，真正要问的问题并不是「它是什么」，而是它让哪些操作变快了，又让哪些操作变慢了。

## 二、主存储器是怎么划分的

### 2.1 方格是画法，地址是一条直线

内存经常被画成一个二维的平面，由一个一个的小方格组成。每个方格是一个**字节（byte）**，每个方格都有自己的编号，这个编号就是**地址**。

但是需要注意，地址是一维的。把内存画成很多行，只是为了在纸上放得下，内存里并没有「第几行第几列」的概念，它就是从 0 开始一直往后编号的一条直线。

![内存的方格画法与实际的一维地址空间](/img/posts/dsa-intro/memory-address.svg)

*图 1：方格是画给人看的，地址是线性的。一个 `int` 占 4 个连续的字节，它的地址就是第一个字节的地址。*

这条性质看起来像是一句废话，但它其实是整个数组的基础。因为地址是线性的，而且数组的每个元素一样宽，所以

```
A[i] 的地址 = 首地址 + i × 每个元素的字节数
```

只需要一次乘法和一次加法就能得到元素的地址，不需要从头开始一个一个地往后找。数组的随机访问之所以是 O(1)，原因就写在这一行公式里，而不是因为「数组本来就快」。

### 2.2 程序跑起来之后，主存被分成三块

课上把内存画成了三块，从下往上依次是：

1. **代码区**：编译后得到的机器指令存放在这里，程序开始运行后，这部分内容就固定不变了。
2. **栈（stack）**【静态】
3. **堆（heap）**【动态】

![程序运行时主存的三块分区](/img/posts/dsa-intro/memory-sections.svg)

*图 2：这是课上的画法。严格来说，还有一块全局变量和静态变量的存储区；而在真实的系统里，栈和堆的生长方向、地址高低也和这张图不一样。刚开始学的时候，只要记住哪一块是自动管理的、哪一块需要手动管理就可以了。*

### 2.3 栈：一次函数调用开一层，返回就整层收回

下面用一段代码来说明：

```c
void fun2() {
    int c = 30;      // 第三层
}

void fun1() {
    int b = 20;      // 第二层
    fun2();
}

int main() {
    int a = 10;      // 第一层
    fun1();
    return 0;
}
```

*代码 1：三层调用，栈上就压三层。*

`main` 开始执行时，会在栈上开辟一块区域来存放 `a`；`main` 调用了 `fun1`，于是在 `main` 那一层的上面再开辟一层，用来存放 `b`；`fun1` 又调用了 `fun2`，于是再往上开辟一层，用来存放 `c`。每一层叫作一个**栈帧（stack frame）**。

当 `fun2` 执行完并返回时，它那一层会立刻整个消失，占用的空间也被归还；接下来是 `fun1`，最后才轮到 `main`。

![函数调用过程中栈帧的生长与回收](/img/posts/dsa-intro/stack-frames.svg)

*图 3：最后进来的最先出去。*

可以看出，最后开辟的那一层最先被回收，这正是后面要学的栈结构，也就是后进先出（LIFO）。函数调用本身就满足后进先出的规律，所以这块内存直接被称为栈。

### 2.4 那个「静态」到底静态在哪

这里有一点在第一次学习时很容易理解偏，所以需要单独说明。

这里的「静态」并不是指栈在运行时不会变化，因为栈帧明明一直在开辟，也一直在回收。它真正的意思是，每一层需要多大的空间、每个变量放在这一层的第几个字节，这些都在编译阶段就已经计算好了。运行时只需要移动一下栈顶指针，这只要一条指令，程序员也不需要为此写任何代码。

由此可以直接推出两个结论：

- 栈上不能开辟「到运行时才知道大小」的数组，因为栈帧的大小必须在编译期确定。
- 栈的总容量是有限的，常见的大小是 1 MB 或 8 MB。递归太深就会导致栈溢出（stack overflow），后面写递归时会经常遇到这个问题。

另外需要注意，栈帧的回收是自动完成的，并不需要调用 `delete`。真正需要手动管理的，是下面要讲的堆。

### 2.5 堆：运行时申请，手动归还

堆里的内存既可以整整齐齐地排列，也可以东一块、西一块地分散，没有什么限制。堆上的内存需要程序员亲自申请，也需要亲自释放：

```c
int *p = (int *)malloc(5 * sizeof(int));   // 向堆要 5 个 int
p[0] = 1;
free(p);                                   // 用完自己还回去
```

```cpp
int *p = new int[5];                       // C++ 的写法
delete[] p;
```

*代码 2：在堆上申请和释放内存，C 和 C++ 各写一份。*

这里有三个要点：

- **`p` 本身在栈上，而 `p` 指向的那 5 个 `int` 在堆上。** 这是刚开始学习时最容易混淆的一点，指针变量和它所指向的内存存放在不同的地方。
- 堆上的内存不会自动回收。忘记调用 `free` 就会造成内存泄漏；对同一块内存 `free` 两次，或者 `free` 之后继续使用，都属于未定义行为。
- 换来的好处是灵活。申请的大小可以是运行时才知道的变量，内存的生命周期也可以跨越函数，即使函数已经返回，堆上的数据仍然存在。

动态数组、链表的节点、树的节点，后面所有「事先不知道长度」的数据结构，都存放在堆上。

| | 栈 stack | 堆 heap |
| --- | --- | --- |
| 谁分配 | 编译器自动 | 程序员手写 `malloc` / `new` |
| 谁回收 | 函数返回时自动整层收回 | 必须手写 `free` / `delete` |
| 大小何时定 | 编译期 | 运行期 |
| 生命周期 | 跟着函数走 | 到你释放为止 |
| 出事的样子 | stack overflow（递归太深） | 内存泄漏 / 悬空指针 |
| 谁住在这 | 局部变量、参数、返回地址 | 动态数组、链表和树的节点 |

数据结构课一开始就讲这些内容，是因为后面每一种数据结构都要在这两块内存之间做出选择，而选错的后果，就是上面这张表的最后两行。

## 三、逻辑结构与物理结构

这是本篇最重要的一种分类方式。

**物理结构**（physical data structure）只有两种：

- **数组**，是一整块连续的内存。
- **链表**，由分散的节点组成，节点之间用指针连接起来。

数据在内存里真实的排列方式只有这两种，没有第三种。

**逻辑结构**（logical data structure）描述的是数据之间的关系：

- 线性的：**栈**、**队列**
- 非线性的：**树**、**图**
- 表格形式的：**哈希表**

关键在于这两类结构之间的关系。逻辑结构并不是内存里真实存在的东西，它必须借助数组或链表（或者两者的组合）才能实现。

![逻辑结构与物理结构的关系](/img/posts/dsa-intro/logical-vs-physical.svg)

*图 4：上面一层描述数据之间是什么关系，下面一层描述数据实际上怎么存放。*

以栈为例，两种实现方式所需的字段完全不同：

```c
/* 用数组实现：一整块连续空间 + 一个栈顶下标 */
struct ArrayStack {
    int *A;      // 指向堆上的一整块
    int size;    // 容量
    int top;     // 栈顶下标
};

/* 用链表实现：只需要记住头节点 */
struct Node {
    int data;
    struct Node *next;
};

struct LinkedStack {
    struct Node *top;
};
```

*代码 3：同一个栈，两种物理实现。*

对使用者来说，这两种栈的行为完全一样，都支持 `push` 和 `pop`，都是后进先出，没有任何区别。它们的差别全部体现在开销上。数组版的栈满了以后需要扩容，还要把原来的数据全部搬一遍；链表版的栈每个节点都要多占用一个指针的空间，而且节点分散在堆里，对缓存不友好。

可以这样记：逻辑结构决定了数据结构「是什么」，物理结构决定了它的「开销有多大」。

## 四、ADT：抽象数据类型

首先要说清楚什么是**数据类型（data type）**。任何一种数据类型都包含两部分：

1. **数据的表示（representation）**，比如 `int` 占 4 个字节、用补码编码、表示的范围是多少。
2. **能对数据进行的操作（operations）**，比如 `+` `-` `*` `/` `%` 这些运算。

`int` 之所以是一种类型，并不是因为它「是一个数字」，而是因为这两方面的内容都被明确规定了。

**ADT**（Abstract Data Type，抽象数据类型）是同样的概念，只不过用在了自己定义的类型上。一个 ADT 包括两部分，一部分是怎样存储这批数据（用数组还是链表），另一部分是能对这批数据进行哪些操作。

在 C++ 里，它对应的就是 `class`：

```c
/* C 的写法：结构体负责「表示」，一组函数负责「操作」 */
struct Array {
    int *A;      // 数据存在哪
    int size;    // 容量
    int length;  // 当前有几个
};

void Display(struct Array arr);
void Append(struct Array *arr, int x);
void Insert(struct Array *arr, int index, int x);
int  Delete(struct Array *arr, int index);
int  Search(struct Array arr, int key);
```

*代码 4：Array ADT 在 C 语言里的样子，表示和操作是分开的两部分。*

```cpp
/* C++ 的写法：class 把两者合在一起，还能把表示藏起来 */
class Array {
private:
    int *A;                                   // 表示
    int size;
    int length;

public:
    Array(int sz) : A(new int[sz]), size(sz), length(0) {}
    ~Array() { delete[] A; }

    void Insert(int index, int x);            // 操作
    int  Delete(int index);
    int  Search(int key) const;
    int  Get(int index) const;
};
```

*代码 5：同一个 ADT 的 C++ 版本，`private` 部分是表示，`public` 部分是操作。*

那么「抽象」体现在哪里呢？体现在 `private` 那一部分可以整个替换掉。调用方只知道 `Insert`、`Delete` 和 `Search` 这些操作，所以即使有一天把里面的 `int *A` 换成一条链表，调用方的代码也一行都不需要修改。

也就是说，ADT 只对外承诺有哪些操作，并不承诺数据是怎么表示的。这也是后面每一章固定的讲解顺序，先定义这种数据结构应该有哪些操作，再讨论用数组还是链表来实现它。

## 五、时间复杂度与空间复杂度

### 5.1 `n` 是什么

`n` 表示**当前要处理的数据总量**。不用关心它具体是 5 还是 5000，统一用 `n` 来表示。

复杂度要回答的并不是「这段代码要运行多少毫秒」，因为这取决于具体的机器。它要回答的问题是，当 n 变大的时候，开销会按照什么样的趋势增长。

### 5.2 逐行数的方法

刚开始学的时候，不必急着一眼看出答案，可以老老实实地一行一行计数：

| 这一行做了什么 | 记多少 |
| --- | --- |
| 赋值（`x = 0`） | +1 |
| 比较（`i < n`） | +1 |
| 算术运算（`i++`、`a + b`） | +1 |
| `return` | +1 |
| 循环体 | 体内的次数 × 循环跑的遍数 |
| 调用函数 | 加上被调函数自己的复杂度 |

下面用一个例子来数一遍：

```c
int Sum(int A[], int n) {
    int s = 0;                    // 1
    for (int i = 0; i < n; i++)   // i=0 记 1；i<n 判 n+1 次；i++ 走 n 次
        s = s + A[i];             // 每轮 1 次，共 n 次
    return s;                     // 1
}
```

*代码 6：一个求和函数，以及逐行计数的结果。*

全部加起来是 `1 + 1 + (n+1) + n + n + 1 = 3n + 4`。

接下来做两件事，一是只保留最高阶的项，二是去掉系数，于是 `3n + 4` 就变成了 O(n)。

为什么可以这样简化呢？因为当 `n` 很大时，常数 4 的影响早就可以忽略不计了；而系数 3 取决于机器和编译器，换一台电脑就可能改变，保留它反而不是一个稳定的性质。复杂度要描述的是增长的趋势，而不是具体的数值。

### 5.3 四种必须一眼认出的形状

**（1）单层循环：O(n)**

从头到尾遍历一遍，比如在无序数组里做线性查找，就是上面那个例子。

**（2）固定一个元素，让另一个元素往后走一遍：O(n²)**

```c
/* 检查数组里有没有重复元素（最朴素的写法） */
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (A[i] == A[j])
            return 1;
```

*代码 7：双重循环。*

内层循环执行的总次数是 `(n-1) + (n-2) + … + 1 + 0 = n(n-1)/2`。

![双重循环的执行次数是正方形的一半](/img/posts/dsa-intro/nested-loop-triangle.svg)

*图 5：阴影部分的格子数，就是内层循环实际执行的次数。*

把它展开是 $\frac{n^2}{2} - \frac{n}{2}$，最高阶的项是 $n^2$，再去掉 $\frac{1}{2}$ 这个系数，结果就是 O(n²)。

图里的三角形正好是整个正方形的一半，而「一半」是一个常数。所以它和「内层循环每次都完整执行 n 次」的二重循环，复杂度是相同的。在这两种情况下，n 增大一倍，开销都会变成原来的 4 倍。

**（3）每次折半：O(log₂n)**

```c
for (int i = n; i > 0; i /= 2) {
    /* ... */
}
```

*代码 8：每一轮都把 i 减半。*

`i` 的取值依次是 n、n/2、n/4……一直到 1。这里实际要问的是，n 需要除以多少次 2 才能降到 1，答案就是 $\log_2 n$。

反过来，`for (int i = 1; i <= n; i *= 2)` 也是一样的，只不过是从小往大乘。

记住这种形状很有用，二分查找、堆的高度、平衡二叉树的高度，背后都是同一个原因。而且看具体的数字最能体现出 log 有多好，n = 1000 时，它也只有 10。

**（4）两个独立的规模：O(m+n)**

假设有一个链表数组，里面有 m 条链表，所有链表的节点加起来一共有 n 个。现在要把全部数据遍历一遍：

```c
for (int i = 0; i < m; i++)                     // 外层：m 个头指针
    for (Node *p = H[i]; p != NULL; p = p->next)  // 内层：所有链表加起来 n 个节点
        printf("%d ", p->data);
```

*代码 9：遍历链表数组。*

![m 条链表、共 n 个节点的遍历](/img/posts/dsa-intro/linked-list-array.svg)

*图 6：外层循环执行 m 次，内层循环一共执行 n 次。*

所以结果是 O(m+n)。这里有一个容易犯的错误，就是看到双重循环就写成 O(n²)。这样写是错的，因为内层循环的总次数是 n，而不是每一轮都执行 n 次。同样，也不能把 m 和 n 合并成一个量，因为它们是两个相互独立的量，除非题目另外说明了两者之间的关系。

### 5.4 把四种形状放在一起看

![常见复杂度的增长曲线](/img/posts/dsa-intro/complexity-growth.svg)

*图 7：横轴是 n，纵轴是运算次数。曲线的系数只是为了让几条曲线分得开而随意选取的，要看的是曲线的形状，而不是高低。*

具体的数字比曲线更有说服力。当 n 从 10 增长到 1000，也就是增长 100 倍时，O(log n) 只从 3 增长到 10，O(n) 增长了 100 倍，而 O(n²) 增长了 10000 倍。这就是为什么「把 O(n²) 降到 O(n log n)」值得专门用一章来讲。

### 5.5 空间复杂度

空间复杂度描述的是**代码运行时额外占用的内存随着 n 怎样增长**。

- 如果要把 n 个数据存进一个数组，空间复杂度就是 O(n)。
- 如果只用了几个临时变量（比如 `i`、`sum`、`temp`），空间复杂度就是 O(1)，和 n 的大小没有关系。

这里还要补充一点，一般计算的是**辅助空间**，也就是除了输入数据本身以外额外开辟的空间。传进来的那个数组通常不算在内，否则任何处理数组的算法的空间复杂度都至少是 O(n)，这个指标也就失去了区分的意义。

还有一种情况，刚开始学的时候很难意识到，但是后面写递归时一定会遇到：

```c
int Sum(int n) {
    if (n == 0) return 0;
    return n + Sum(n - 1);
}
```

*代码 10：一个数组都没有开，空间复杂度却是 O(n)。*

这个函数没有申请任何内存，但是递归 n 层就意味着栈上同时压着 n 个栈帧，所以它的时间复杂度是 O(n)，空间复杂度也是 O(n)。这正好和第二节的内容联系起来，栈帧是要占用空间的，而栈的总容量是有限的。

## 小结

这一篇没有写任何具体的数据结构，但是下面这几条会一直用到最后：

| 概念 | 一句话 |
| --- | --- |
| 数据结构 | 数据在主存里的排列方式，目的是节省空间、加快读取 |
| 内存三块 | 代码区，栈（编译期确定大小、自动回收），堆（运行期申请、手动释放） |
| 物理结构 | 只有两种，数组（连续存放）和链表（用指针连接） |
| 逻辑结构 | 栈、队列、树、图、哈希表，都要借助数组或链表才能实现 |
| ADT | 由表示和操作组成，对外只承诺操作，表示可以随时更换 |
| 复杂度 | 描述 n 变大时开销的增长趋势；先逐行计数，再只保留最高阶项并去掉系数 |

这一篇真正想养成的是一种提问的习惯。每看到一种数据结构，先问它把数据放在哪里（栈还是堆，连续存放还是用指针连接），再问它让哪些操作变快了，又让哪些操作变慢了。后面的每一章，其实都是在回答这两个问题。
