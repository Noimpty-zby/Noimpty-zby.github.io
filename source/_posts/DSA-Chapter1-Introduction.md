这一篇写在正式步入数据结构之前，目的只有一个：**先有一个宏观的概念**。

具体的结构（链表怎么插、树怎么转）后面每一章都会写，但那些章节全都建立在同一批前提上 —— 数据到底放在内存的哪里、为什么只有数组和链表两种排布、说一个操作「快」的时候到底在比什么。这些东西如果第一天含糊过去，后面每学一个结构都会多一层雾。

所以这篇不写任何具体结构，只把地基铺平。

<!-- more -->

## 一、什么是数据结构

一句话：**数据结构研究的是数据在主存储器（main memory）里该怎么排布，好让存储空间用得省、让 CPU 拿数据拿得快。**

这句定义里有两个词值得先咬住：

- **主存储器**。不是硬盘，不是数据库文件。数据结构讨论的是程序运行期间、数据在内存里的样子。
- **高效**。永远是「对某一批操作而言高效」，不存在什么都快的结构。数组查得快、插得慢，链表反过来 —— 之所以要学这么多结构，就是因为不同的活要挑不同的排布。

所以往后每学一个结构，真正要问的从来不是「它是什么」，而是：**它把哪些操作变快了，代价是哪些操作变慢了。**

## 二、主存储器是怎么划分的

### 2.1 方格是画法，地址是一条直线

内存常被画成一个二维平面：一格一格的小方块，每一格是一个**字节（byte）**，每一格有自己的编号，也就是**地址**。

但要注意：**地址是一维的。** 画成好几行只是为了在纸上放得下，内存里并没有「第几行第几列」这回事，它就是从 0 开始一直往后数的一条直线。

![内存的方格画法与实际的一维地址空间](/img/posts/dsa-intro/memory-address.svg)

*图 1：格子是给人看的，地址是线性的。一个 `int` 占 4 个连续字节，它的地址就是第一个字节的地址。*

这条看起来很像废话的性质，其实是整个数组的地基：因为地址线性、元素等宽，所以

```
A[i] 的地址 = 首地址 + i × 每个元素的字节数
```

一次乘法加一次加法就得到了，不需要从头走过去。**数组的随机访问是 O(1)，原因就写在这一行里**，而不是因为「数组本来就快」。

### 2.2 程序跑起来之后，主存被分成三块

课上把内存画成三块，从下往上：

1. **代码区** —— 你写的代码编译出来的机器指令住在这里，程序一跑起来就固定在那儿。
2. **栈（stack）**【静态】
3. **堆（heap）**【动态】

![程序运行时主存的三块分区](/img/posts/dsa-intro/memory-sections.svg)

*图 2：课上的画法。严格说还有全局/静态变量区，真实系统里栈和堆的生长方向、地址高低也和这张图不同 —— 第一天要记住的是「谁自动、谁手动」。*

### 2.3 栈：一次函数调用开一层，返回就整层收回

怎么理解？看这段代码：

```c
void fun2() {
    int c = 30;      // 第三层
}

void fun1() {
    int b = 20;      // 第二层
    fun2();
}

int main() {
    int a = 10;      // 第一层
    fun1();
    return 0;
}
```

*代码 1：三层调用，栈上就压三层。*

`main` 一开始执行，就在栈上开一块区域放 `a`；`main` 里调用了 `fun1`，就在 `main` 那一层**上面**再开一层放 `b`；`fun1` 里又调用 `fun2`，再往上开一层放 `c`。每一层叫一个**栈帧（stack frame）**。

当 `fun2` 干完活返回，它那一层立刻整个消失，空间还回去；接着是 `fun1`，最后才轮到 `main`。

![函数调用过程中栈帧的生长与回收](/img/posts/dsa-intro/stack-frames.svg)

*图 3：最后进来的最先出去。*

看出来了吗 —— **最后开的那一层最先被收回，这不就是我们要学的栈结构（LIFO）。** 函数调用天然满足后进先出，所以这块内存干脆就叫栈。

### 2.4 那个「静态」到底静态在哪

这里有一点第一遍很容易记歪，值得单独说清楚。

**「静态」不是说它运行时不动**（栈帧明明一直在开、一直在收）。它说的是：**每一层要多大、哪个变量放在这一层的第几个字节，全部在编译阶段就算好了。** 运行时只是把栈顶指针挪一下而已，一条指令的事，不需要你写一个字。

由此可以直接推出两件事：

- 栈上开不了「运行时才知道多大」的数组 —— 因为编译期就得把帧的大小定死。
- 栈的总量是有限的（常见 1 MB / 8 MB）。**递归太深就是 stack overflow**，后面写递归的时候会天天见到。

另外注意：栈帧的回收是**自动**的，不是 `delete`。需要你手动收拾的是下面这块。

### 2.5 堆：运行时申请，手动归还

堆，顾名思义，里面的东西既可以整整齐齐排着，也可以东一块西一块 —— 没什么拘束。它靠程序员亲手创建、亲手释放：

```c
int *p = (int *)malloc(5 * sizeof(int));   // 向堆要 5 个 int
p[0] = 1;
free(p);                                   // 用完自己还回去
```

```cpp
int *p = new int[5];                       // C++ 的写法
delete[] p;
```

*代码 2：堆上的申请与释放，C 与 C++ 各一份。*

三个要点：

- **`p` 本身在栈上，`p` 指向的那 5 个 `int` 在堆上。** 这是第一天最容易混的一点 —— 指针变量和它指向的内存住在不同的地方。
- **不会自动回收。** 忘了 `free` 就是内存泄漏；`free` 两次、或者 `free` 完继续用，都是未定义行为。
- 换来的是自由：大小可以是运行时才知道的变量，生命周期可以跨函数（函数返回了，堆上的东西还在）。

**动态数组、链表节点、树的节点 —— 后面所有「长度事先不知道」的结构，都住在堆上。**

| | 栈 stack | 堆 heap |
| --- | --- | --- |
| 谁分配 | 编译器自动 | 程序员手写 `malloc` / `new` |
| 谁回收 | 函数返回时自动整层收回 | 必须手写 `free` / `delete` |
| 大小何时定 | 编译期 | 运行期 |
| 生命周期 | 跟着函数走 | 到你释放为止 |
| 出事的样子 | stack overflow（递归太深） | 内存泄漏 / 悬空指针 |
| 谁住在这 | 局部变量、参数、返回地址 | 动态数组、链表和树的节点 |

数据结构课一上来就讲这个，是因为后面每一个结构都要在这两块里做选择 —— 而选错的代价，就是上面这张表的最后两行。

## 三、逻辑结构与物理结构

这是本篇最重要的一次分类。

**物理结构（physical data structure）：只有两种。**

- **数组** —— 一整块连续的内存。
- **链表** —— 零散的节点，靠指针串起来。

数据在内存里真实的排布方式，就这两种，没有第三种。

**逻辑结构（logical data structure）：描述数据之间的关系。**

- 线性：**栈**、**队列**
- 非线性：**树**、**图**
- 表格形式：**哈希表**

关键在于两者的关系：**逻辑结构不是内存里真实存在的东西，它必须借助数组或链表（或者两者的组合）来实现。**

![逻辑结构与物理结构的关系](/img/posts/dsa-intro/logical-vs-physical.svg)

*图 4：上面一层说「数据之间是什么关系」，下面一层说「实际怎么放」。*

拿栈举例，两种实现的字段完全不同：

```c
/* 用数组实现：一整块连续空间 + 一个栈顶下标 */
struct ArrayStack {
    int *A;      // 指向堆上的一整块
    int size;    // 容量
    int top;     // 栈顶下标
};

/* 用链表实现：只需要记住头节点 */
struct Node {
    int data;
    struct Node *next;
};

struct LinkedStack {
    struct Node *top;
};
```

*代码 3：同一个栈，两种物理实现。*

对使用者来说，这两个栈的行为一模一样 —— `push`、`pop`、后进先出，一点区别都没有。差别全在代价上：数组版满了要扩容（还要把老数据搬一遍），链表版每个节点要多花一个指针的空间，而且节点散在堆里，缓存不友好。

一句话记住：**逻辑结构定义「是什么」，物理结构决定「多少钱」。**

## 四、ADT：抽象数据类型

先说清楚什么是**数据类型（data type）**。任何一个数据类型都包含两部分：

1. **数据的表示（representation）** —— 比如 `int` 占 4 个字节、用补码编码、范围是多少。
2. **能对它做什么操作（operations）** —— `+` `-` `*` `/` `%` 这些。

`int` 之所以是一个类型，不是因为它「是个数字」，而是因为这两件事都被规定死了。

**ADT（Abstract Data Type，抽象数据类型）是同一套东西，只不过搬到我们自己定义的类型上**：一个 ADT = **怎么存这批数据**（数组还是链表）+ **能对这批数据做哪些操作**。

它就是 C++ 里的 `class`：

```c
/* C 的写法：结构体负责「表示」，一组函数负责「操作」 */
struct Array {
    int *A;      // 数据存在哪
    int size;    // 容量
    int length;  // 当前有几个
};

void Display(struct Array arr);
void Append(struct Array *arr, int x);
void Insert(struct Array *arr, int index, int x);
int  Delete(struct Array *arr, int index);
int  Search(struct Array arr, int key);
```

*代码 4：Array ADT 在 C 里的样子 —— 表示和操作是分开的两坨。*

```cpp
/* C++ 的写法：class 把两者合在一起，还能把表示藏起来 */
class Array {
private:
    int *A;                                   // 表示
    int size;
    int length;

public:
    Array(int sz) : A(new int[sz]), size(sz), length(0) {}
    ~Array() { delete[] A; }

    void Insert(int index, int x);            // 操作
    int  Delete(int index);
    int  Search(int key) const;
    int  Get(int index) const;
};
```

*代码 5：同一个 ADT 的 C++ 版本。`private` 是表示，`public` 是操作。*

「抽象」这两个字落在哪里？落在 **`private` 那一段是可以整个换掉的**。调用方只认识 `Insert` / `Delete` / `Search`，哪天我把里面的 `int *A` 换成一条链表，调用方一行都不用改。

**ADT 只承诺操作，不承诺表示** —— 这就是后面每一章的固定套路：先定义这个结构该有哪些操作，再讨论用数组还是链表来实现它。

## 五、时间复杂度与空间复杂度

### 5.1 `n` 是什么

`n` 就是**当前要处理的数据总数**，不用管它具体是 5 还是 5000，就是 `n`。

复杂度回答的从来不是「这段代码跑多少毫秒」（那取决于机器），而是：**当 n 变大的时候，代价按什么形状变大。**

### 5.2 逐行数的方法

刚开始不用急着一眼看出答案，可以老老实实一行一行数：

| 这一行做了什么 | 记多少 |
| --- | --- |
| 赋值（`x = 0`） | +1 |
| 比较（`i < n`） | +1 |
| 算术运算（`i++`、`a + b`） | +1 |
| `return` | +1 |
| 循环体 | 体内的次数 × 循环跑的遍数 |
| 调用函数 | 加上被调函数自己的复杂度 |

数一遍看看：

```c
int Sum(int A[], int n) {
    int s = 0;                    // 1
    for (int i = 0; i < n; i++)   // i=0 记 1；i<n 判 n+1 次；i++ 走 n 次
        s = s + A[i];             // 每轮 1 次，共 n 次
    return s;                     // 1
}
```

*代码 6：一个求和函数，逐行数出来的结果。*

加起来是 `1 + 1 + (n+1) + n + n + 1 = 3n + 4`。

然后做两件事：**只留最高阶项，扔掉系数** —— `3n + 4` → **O(n)**。

为什么敢扔？因为 `n` 一大，常数 4 早就被淹没了；而系数 3 依赖机器和编译器，换台电脑就变了，留着它反而不是一个稳定的性质。复杂度要刻画的是**形状**，不是绝对值。

### 5.3 四种必须一眼认出的形状

**（1）单层循环 → O(n)**

从头到尾走一遍，比如在无序数组里线性查找。就是上面那个例子。

**（2）固定一个、另一个往后走一遍 → O(n²)**

```c
/* 检查数组里有没有重复元素（最朴素的写法） */
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (A[i] == A[j])
            return 1;
```

*代码 7：双重循环。*

内层跑的次数是 `(n-1) + (n-2) + … + 1 + 0 = n(n-1)/2`。

![双重循环的执行次数是正方形的一半](/img/posts/dsa-intro/nested-loop-triangle.svg)

*图 5：阴影格子就是内层实际跑的次数。*

展开是 $\frac{n^2}{2} - \frac{n}{2}$，最高阶是 $n^2$，扔掉 $\frac{1}{2}$ 这个系数 —— **O(n²)**。

图里那个三角形正好是整块正方形的一半，而「一半」是个常数。所以它和「内层老老实实跑满 n 次」的完整二重循环是**同一个复杂度**：n 翻一倍，代价都变成 4 倍。

**（3）每次折半 → O(log₂n)**

```c
for (int i = n; i > 0; i /= 2) {
    /* ... */
}
```

*代码 8：每轮把 i 砍一半。*

`i` 的取值是 n → n/2 → n/4 → … → 1。这里问的其实是：**n 被除以几次 2 才降到 1？** 答案就是 $\log_2 n$。

反过来 `for (int i = 1; i <= n; i *= 2)` 也一样，只是从下往上乘。

记住这个形状很划算 —— 二分查找、堆的高度、平衡二叉树的高度，全都是同一个理由。而且 log 有多好，看数字最直观：n = 1000 时它才 10。

**（4）两个独立的规模 → O(m+n)**

一个链表数组：有 m 条链表，所有链表的节点加起来是 n 个。把全部数据遍历一遍：

```c
for (int i = 0; i < m; i++)                     // 外层：m 个头指针
    for (Node *p = H[i]; p != NULL; p = p->next)  // 内层：所有链表加起来 n 个节点
        printf("%d ", p->data);
```

*代码 9：遍历链表数组。*

![m 条链表、共 n 个节点的遍历](/img/posts/dsa-intro/linked-list-array.svg)

*图 6：外层 m 次，内层总共 n 次。*

结果是 **O(m+n)**。这里有个坑要避开：看到双重循环就写 O(n²) 是错的 —— 内层的总次数是 n，不是每次都 n。同样也**不能把 m 和 n 合并**，它们是两个互相独立的量，除非题目额外说明了两者的关系。

### 5.4 把四种形状放在一起看

![常见复杂度的增长曲线](/img/posts/dsa-intro/complexity-growth.svg)

*图 7：横轴是 n，纵轴是运算次数。曲线的系数是为了画得开而随便取的，要看的是形状，不是高低。*

数字比曲线更有说服力：n 从 10 涨到 1000（100 倍），O(log n) 从 3 涨到 10，O(n) 涨 100 倍，O(n²) 涨 **10000 倍**。这就是为什么「能把 O(n²) 降到 O(n log n)」值得单独花一章去讲。

### 5.5 空间复杂度

空间复杂度是**代码运行时额外占用的内存随 n 怎么涨**。

- 要把 n 个数据存进一个数组 → **O(n)**。
- 只用了几个临时变量（`i`、`sum`、`temp`）→ **O(1)**，和 n 多大没关系。

有一点要补一句：一般算的是**辅助空间**，也就是「除了输入本身之外额外开的」。传进来的那个数组通常不计入，否则任何处理数组的算法都至少是 O(n)，这个指标就没有区分度了。

还有一个第一天完全没意识到、后面写递归一定会撞上的：

```c
int Sum(int n) {
    if (n == 0) return 0;
    return n + Sum(n - 1);
}
```

*代码 10：一个数组都没开，空间复杂度却是 O(n)。*

它没申请任何内存，但递归 n 层就意味着栈上同时压着 n 个栈帧 —— **时间 O(n)，空间也是 O(n)**。这正好接回第二节：栈帧是要占地方的，而栈的总量有限。

## 小结

第一天没写一行结构，但下面这几条会一路用到最后：

| 概念 | 一句话 |
| --- | --- |
| 数据结构 | 数据在主存里的排布方式，为的是省空间、拿得快 |
| 内存三块 | 代码区 / 栈（编译期定好、自动收回）/ 堆（运行期申请、手动释放） |
| 物理结构 | 只有两种：数组（连续）、链表（指针相连） |
| 逻辑结构 | 栈、队列、树、图、哈希表 —— 都得靠上面那两种落地 |
| ADT | 表示 + 操作，且只对外承诺操作，表示随时可以换 |
| 复杂度 | n 变大时代价的形状；先逐行数，再只留最高阶、扔掉系数 |

真正想留下的是一种提问的习惯：**看到一个结构，先问它把数据放在哪（栈还是堆、连续还是链），再问它让哪个操作变快、又让哪个操作变慢。** 后面每一章其实都是在回答这两个问题。
