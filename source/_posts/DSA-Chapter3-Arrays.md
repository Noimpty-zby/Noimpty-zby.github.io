上一章讲的是**调用**怎么在内存里排 —— 一次调用一层栈帧，帧叠着帧。这一章换成**数据**怎么在内存里排，而数组是所有排法里最简单的那一种：**挨着放，每个一样宽**。

就这两条。后面所有的性质 —— 为什么查得快、为什么插得慢、为什么下标从 0 开始、为什么越界了没人拦你 —— 全都是从这两条推出来的，没有一条需要额外记。

这一篇不写数组上的算法（插入、删除、查找、合并那些留到下一篇），只写数组本身：它怎么声明、住在哪、怎么变长、以及**编译器到底凭什么一步就能找到 `A[i]`**。最后那一节是这一章的重点，也是唯一需要动笔算的地方。

## 一、数组只有两条性质

**第一，元素在地址上是连续的。** 一个 `int A[5]`，五个元素紧挨着躺在内存里，中间一个字节都不空。

**第二，每个元素一样宽。** 都是 `int`，都是 4 个字节。

有了这两条，**知道首地址和下标就能算出任何一个元素在哪**，不需要从头一个个走过去。这就是第一章那句「数组的随机访问是 O(1)」的全部内容 —— 它不是数组的天赋，是这两条性质的直接结果。

### 1.1 五种声明写法

![五种声明写法在内存里分别是什么样子](/img/posts/dsa-arrays/declare-five.svg)

*图 1：容量和初值是两件事。*

```c
int A[5];                       // ① 容量 5，值是什么不知道
int B[5] = {2, 4, 6, 8, 10};    // ② 容量 5，五个值都给了
int C[5] = {2, 4};              // ③ 容量 5，给了两个，后三个是 0
int D[5] = {0};                 // ④ 容量 5，整块清零
int E[]  = {2, 4, 6, 8, 10};    // ⑤ 不写容量，由初始化列表定 —— 这里是 5
```

*代码 1：五种写法。*

跑出来是这样：

```
A (未初始化): 0 0 0 0 0
B = {2,4,6,8,10}: 2 4 6 8 10
C = {2,4}: 2 4 0 0 0
D = {0}: 0 0 0 0 0
E = {2,4,6,8,10} 无长度: 2 4 6 8 10
sizeof(E) = 20, 元素个数 = 5
```

③ 和 ④ 值得单独记一句：**只要写了初始化列表，没写到的位置一律补 0**，这是 C 标准规定的，不是运气。所以 `= {0}` 才成了「整块清零」的惯用写法 —— 它靠的不是那个 0，是那条补零规则。

⑤ 的容量是编译期数出来的。`sizeof(E) / sizeof(E[0])` 得到 5，这也是 C 里唯一能从数组本身问出长度的办法 —— 而且只在能看见声明的地方管用，1.4 节会说到它什么时候失效。

### 1.2 「垃圾值」是谁留下的

上面那次 `A` 打出来全是 0，很容易让人以为「未初始化也没关系」。**它只是碰巧。** `main` 用的是一块刚拿到的、被内核清过零的栈页，所以读出来是 0。

换个位置就露馅了：让一个函数先在某块栈空间上写点东西，再让另一个同样深度的函数在同一块地方声明一个未初始化的数组。

```c
void dirty(void) {              /* 先在这块栈空间上留下点东西 */
    int tmp[5] = {111, 222, 333, 444, 555};
    printf("dirty() 写入: ");
    for (int i = 0; i < 5; i++) printf("%d ", tmp[i]);
    puts("");
}

void fresh(void) {              /* 同样深度的另一个函数，用的是同一块栈空间 */
    int A[5];                   /* 没有初始化 */
    printf("fresh() 读到: ");
    for (int i = 0; i < 5; i++) printf("%d ", A[i]);
    puts("");
}

int main(void) {
    int A[5];                   /* main 自己那块，还没人动过 */
    printf("main 里直接读未初始化数组: ");
    for (int i = 0; i < 5; i++) printf("%d ", A[i]);
    puts("");
    dirty();
    fresh();
}
```

*代码 2：让「垃圾值」现原形。*

```
main 里直接读未初始化数组: 0 0 0 0 0
dirty() 写入: 111 222 333 444 555
fresh() 读到: 111 222 333 444 555
```

**「垃圾值」不是随机数，是上一个人留在这块地上的东西。** 声明一个数组只是划出一段地址，没有任何人负责把它擦干净 —— 擦是要花时间的，C 不替你付这个钱。

这件事的实际后果是：**未初始化的读，测的时候可能一直是对的。** 那块内存碰巧是 0，程序就碰巧正常；等哪天调用路径变了、栈上换了邻居，它才开始出错。

### 1.3 下标就是地址算术

访问一个元素，课上讲了两种写法。顺手多试了一种：

```c
int A[5] = {2, 4, 6, 8, 10};
printf("%d\n", A[2]);       // 6
printf("%d\n", *(A + 2));   // 6
printf("%d\n", 2[A]);       // 6 —— 也是合法的
```

*代码 3：三种写法，同一个元素。*

`2[A]` 居然能编过，而且结果一样。

原因是 C 标准里 `a[b]` 的定义**就是** `*(a + b)`。加法可以交换，所以 `A[2]` 和 `2[A]` 是同一个表达式。这个写法没有任何实用价值，但它把一件事挑明了：**下标不是一种「访问数组」的语法，它就是地址算术的缩写。**

地址也能直接验：

```
A         = 0x7ffc68a05a40
&A[0]     = 0x7ffc68a05a40      ← 数组名就是首地址
&A[2]     = 0x7ffc68a05a48
A+2       = 0x7ffc68a05a48      ← 和 &A[2] 完全相同
&A[2]-&A[0] 字节差 = 8, sizeof(int) = 4
```

差 8 个字节，正好是 2 × 4。指针加法是**按元素**走的，不是按字节 —— `A + 2` 在地址上跳的是 `2 × sizeof(int)`。这条到第四节会变成一条正式的公式。

### 1.4 传进函数就不是数组了

```c
void f(int A[5]) { printf("函数里 sizeof(A) = %zu\n", sizeof(A)); }

int main(void) {
    int A[5];
    printf("main 里 sizeof(A) = %zu\n", sizeof(A));
    f(A);
}
```

*代码 4：同一个 `A`，两个 `sizeof`。*

```
main 里 sizeof(A) = 20
函数里 sizeof(A) = 8        ← 这是 sizeof(int*)
```

参数表里那个 `[5]` 是**给人看的**，编译器根本不收：数组传参时退化成了指向首元素的指针，长度那一半信息在传参的一刻就丢了。gcc 甚至会直接提醒 ——

```
warning: ‘sizeof’ on array function parameter ‘A’
         will return size of ‘int *’
```

**所以 C 里的数组参数永远要额外带一个长度。** 这不是习惯问题，是这门语言里没有别的办法。

## 二、静态数组与动态数组

### 2.1 差的是「容量还能不能换」

「静态 / 动态」这两个词容易被误解成「值能不能改」。不是 —— 值当然都能改。差的是**容量定下来之后还能不能换一块**。

![数组住在哪，谁负责收尸](/img/posts/dsa-arrays/stack-vs-heap.svg)

*图 2：左边这块出了作用域自动消失，右边这块必须自己还。*

- **栈上的数组**（`int A[5]`）：进作用域时整块划出来，出作用域整块收回。谁都不用写 `free`，代价是**中途换不了一块更大的** —— 它的长度是类型的一部分。
- **堆上的数组**（`int *p = new int[5]`）：栈上只有一个指针，数据在堆里。长度可以是运行期才知道的值，能换一块更大的，代价是**必须自己 `delete[]`**。

`sizeof` 把这个区别说得很直白：`sizeof(A)` 是 20（整块），`sizeof(p)` 是 8（一个指针）。**指针身上没有长度这个信息**，这也是为什么堆上的数组同样得自己记着长度。

### 2.2 长度能不能写成变量

`int n; cin >> n; int A[n];` 到底合不合法？这一点常见的说法是「C 里数组长度必须是常量，C++ 里可以用变量」。让编译器自己回答一遍：

| 编译方式 | 结果 |
| --- | --- |
| `gcc -std=c99 -pedantic-errors` | 通过 |
| `gcc -std=c89 -pedantic-errors` | `error: ISO C90 forbids variable length array ‘A’` |
| `g++ -std=c++17 -pedantic-errors` | `error: ISO C++ forbids variable length array ‘A’` |
| `g++ -std=c++17`（不加 `-pedantic`） | 通过 |

**方向正好是反的。** 变长数组（VLA）是 **C99 加进 C 标准**的东西，C++ 标准里从来没有；`g++` 肯收只是因为它默认开着 GNU 扩展，`-pedantic-errors` 一加就报错。

还有两条跟着这件事走：

- **C11 把 VLA 改成了可选项**。实现可以定义 `__STDC_NO_VLA__` 表示不支持 —— 这台机器上的 gcc 没定义它，所以 VLA 可用。
- **VLA 开在栈上**。长度来自运行期输入意味着**长度也可能来自用户**，`int A[n]` 里 n 一大就是爆栈。真需要运行期定长度，答案是堆，不是 VLA。

### 2.3 堆上的数组：申请与归还

```cpp
int *p = new int[5];            // C++
delete[] p;                     // 必须带 []，否则只析构第一个元素

int *q = (int*)malloc(5 * sizeof(int));     // C
free(q);
```

*代码 5：两套写法，各自配对，不能混用。*

两件事别错：`new[]` 配 `delete[]`、`malloc` 配 `free`，交叉着用是未定义行为；`delete[]` 的方括号也不能省。

### 2.4 扩容：三步，一步都不能少

栈上那块换不了，堆上这块也不是「就地变长」—— 堆里你这块后面很可能已经住了别人。所谓扩容，实际上是**另找一块大的，把东西搬过去**。

![扩容：容量换不了，就换一块新的](/img/posts/dsa-arrays/grow-array.svg)

*图 3：三步是一个整体，缺一步就是一个 bug。*

```cpp
int *p = new int[5];
for (int i = 0; i < 5; i++) p[i] = (i + 1) * 2;     // 2 4 6 8 10

int *q = new int[10];                   // ① 另开一块大的
for (int i = 0; i < 5; i++) q[i] = p[i];//    把旧值搬过去
delete[] p;                             // ② 老的那块还给堆
p = q;                                  // ③ 名字接过来
q = nullptr;                            //    再把 q 清掉
```

*代码 6：扩容的三步。*

```
p (cap 5)  = 0x5872081f9ee0, 内容: 2 4 6 8 10
p (cap 10) = 0x5872081f9f30, 内容: 2 4 6 8 10 0 0 0 0 0
```

地址变了 —— 这是整件事里最要紧的一点：**扩容之后，所有指向旧块的指针全部失效。** 这就是 `std::vector` 一 `push_back` 就可能让迭代器失效的根子。

三步各自对应一个 bug：

| 少了哪一步 | 后果 |
| --- | --- |
| ① 不拷贝 | 新块里全是垃圾值 |
| ② 不 `delete[]` | 旧块再也没人能还了 —— 内存泄漏 |
| ③ 不让 `p = q` | 名字还指着已经还掉的那块 —— 野指针 |

第三步末尾的 `q = nullptr` 不是形式主义：留着 `q`，堆上同一块内存就有两个名字，将来谁都可能再 `delete` 一次。

### 2.5 一次该扩多少

搬一次是 O(n)，所以**一次扩多少**直接决定了总代价。两种策略，实测一下：

| 插入 n 个元素 | 每次 +1 的拷贝次数 | 每次翻倍的拷贝次数 |
| --- | --- | --- |
| 10 | 45 | 15 |
| 100 | 4 950 | 127 |
| 1 000 | 499 500 | 1 023 |
| 10 000 | 49 995 000 | 16 383 |
| 100 000 | **4 999 950 000** | **131 071** |

每次多要一格，就是每插一个元素都要把前面所有的搬一遍：$1 + 2 + \cdots + (n-1) = \frac{n(n-1)}{2}$ —— **O(n²)**，插 10 万个要搬 50 亿次。

每次翻倍，搬的总量是

$$
1 + 2 + 4 + \cdots + \frac{n}{2} < n
$$

—— 加起来不到 2n，**均摊到每次插入是 O(1)**。这就是 `std::vector` 的做法，也是「均摊复杂度」这个概念最标准的例子：单看某一次 `push_back` 可能很慢（正好赶上搬家），但把它摊到前面那些不搬家的插入上，每次仍然是常数。

## 三、二维数组的三种声明

### 3.1 二维是画法，不是排法

`int A[3][4]` 画在纸上是 3 行 4 列，但**内存里没有「行」和「列」这回事**。第一章说过地址是一维的，这里再确认一次：

```
=== int A[3][4] 的地址（相对首地址的字节偏移）===
  行 0:    0   4   8  12
  行 1:   16  20  24  28
  行 2:   32  36  40  44
  sizeof(A) = 48 字节，等于 3*4*4 = 48
  当成一维扫: 0 1 2 3 10 11 12 13 20 21 22 23
```

12 个元素从 0 排到 44，一个字节都不空。**「二维」只活在下标的写法里，内存里它就是一条 48 字节的直线。**

### 3.2 三种写法

```cpp
int A[3][4];                    // ① 真正的二维数组：一整块

int *B[3];                      // ② 指针数组：3 个指针，每个指向一段
for (int i = 0; i < 3; i++) B[i] = new int[4];

int **C = new int*[3];          // ③ 二级指针：连指针数组本身也在堆上
for (int i = 0; i < 3; i++) C[i] = new int[4];
```

*代码 7：三种写法，下标写起来都是 `X[i][j]`。*

三种的下标写法完全一样，这也正是它们容易被当成一回事的原因。

![三种「二维数组」，在内存里是三样东西](/img/posts/dsa-arrays/two-d-layouts.svg)

*图 4：只有第一种是真的一整块。*

### 3.3 它们不是一回事

**第一，`sizeof` 不一样：**

```
sizeof(A) = 48     ← 真的一整块
sizeof(B) = 24     ← 三个指针
sizeof(C) = 8      ← 一个指针
```

**第二，行与行之间不连续：**

```
B[0] -> 0x637242489ec0
B[1] -> 0x637242489ee0
B[2] -> 0x637242489f00
行 0 与行 1 的字节距离 = 32
```

一行 4 个 `int` 是 16 字节，可两行的首地址差了 **32** —— 多出来的 16 字节是堆自己的开销：每块前面要放块头，尾巴还要对齐。所以后两种写法**不能当成一维扫**：

```
把方法二当成一维扫: 0 1 2 3 0 0 33 0
```

前 4 个是第 0 行，没问题；后 4 个就不是第 1 行了 —— 那是块头和对齐，以及碰巧落在那儿的东西。同样的扫法在方法一上得到的是完整的 12 个值。

**第三，取一个元素的代价不一样。** 方法一是一次乘加就落到元素上；方法二、三要先读出行指针，再用它去读元素 —— **两次内存访问，而且两次落在完全无关的地址上**，缓存基本帮不上忙。

那为什么还要有后两种？因为它们能做方法一做不到的事：**行长可以不一样**（锯齿数组），**行数可以运行期才定**，**整块太大时堆上凑得出零碎的几段、凑不出连续的一大片**。是取舍，不是优劣。

### 3.4 传参时列数不能省

```c
void ok (int A[][4], int rows) { /* ... */ }    // 可以
void bad(int A[][],  int rows) { /* ... */ }    // 编不过
```

*代码 8：第二个维度是必须写的。*

gcc 的原话：

```
error: array type has incomplete element type ‘int[]’
note: declaration of ‘A’ as multidimensional array must have bounds
      for all dimensions except the first
```

这条规则不是语法洁癖 —— **下一节那条地址公式里就有列数**。不知道一行有几个元素，编译器算不出 `A[i][j]` 在哪。第一个维度可以省，是因为公式里压根没用到行数。

## 四、（重点）编译器怎么找到元素的位置

前面三节都在说数组长什么样。这一节说的是**编译器拿到 `A[i]` 之后做了什么** —— 一共就一次乘法、一次加法，但从它出发能一口气解释掉四件事：数组为什么从 0 开始、越界为什么没人拦、行主序和列主序哪个更好、以及 n 维数组的地址该怎么算。

### 4.1 一维：一次乘法，一次加法

![编译器怎么找到 A[i]](/img/posts/dsa-arrays/address-1d.svg)

*图 5：这一行公式就是「随机访问 O(1)」的全部内容。*

设 $L_0$ 是数组的首地址（base address），$w$ 是一个元素占的字节数，那么

$$
\mathrm{Addr}(A[i]) = L_0 + i \times w
$$

`int A[5]` 里 $w = 4$，所以 `A[2]` 在 $L_0 + 8$ —— 和 1.3 节量出来的 8 字节对上了。

要紧的是这个式子里**没有 n**。不管数组有 5 个元素还是 5 亿个，不管要的是第 2 个还是第 5 亿个，都是乘一次、加一次。**O(1) 说的就是这件事**，不是「数组本来就快」。

反过来，链表没有这条公式 —— 它的节点散在各处，下一个在哪只有上一个知道，所以只能顺着指针一个个走。**两种物理结构的全部差别，最后都落到「有没有这条公式」上。**

### 4.2 为什么下标从 0 开始

如果下标从 1 开始，公式要改成：

$$
\mathrm{Addr}(A[i]) = L_0 + (i - 1) \times w
$$

常见的说法是「这样每次访问都要多算一次减法，所以从 0 开始更快」。方向是对的，但**量级要说准**：是**每次访问多一次减法**，一次，不是很多次。

而且在真实的编译结果里，这一次减法常常连一条指令都不用多。把两种写法分别编出来：

```c
int zero_based(int *A, int i) { return A[i]; }        /* 下标从 0 开始 */
int one_based (int *A, int i) { return A[i - 1]; }    /* 下标从 1 开始 */
```

*代码 9：只差一个 `- 1`。*

`gcc -O2` 的结果：

```asm
zero_based:
        movsx   rsi, esi
        mov     eax, DWORD PTR [rdi+rsi*4]

one_based:
        movsx   rsi, esi
        mov     eax, DWORD PTR -4[rdi+rsi*4]
```

**同一条指令，只是多带了一个 `-4` 的位移。** x86 的寻址方式本来就有这么个字段，用不用都一样快 —— 换句话说，下界是**编译期常数**的时候，「减一」是白送的。

真会多花钱的是下界要到运行期才知道的情况（Pascal 那种 `array[lo..hi]`）：

```c
int var_based(int *A, int i, int lo) { return A[i - lo]; }
```

```asm
var_based:
        sub     esi, edx            ← 这一条是真多出来的
        movsx   rsi, esi
        mov     eax, DWORD PTR [rdi+rsi*4]
```

所以这件事的准确说法是：**从 0 开始，是为了让「下标」和「偏移」变成同一个数。** 公式里没有修正项，指针算术、数组名、`*(A+i)` 这几套东西才能严丝合缝地对上。省下的那点指令是顺带的，不是理由本身。

### 4.3 公式只会算，不会拦

既然取元素就是套一遍公式，那把 `i` 写成 5 会怎么样？公式照算 —— $L_0 + 5 \times 4$ 是个合法地址，它就去读了。

把两个数组紧挨着放，看得最清楚：

```c
struct Pair { int A[5]; int B[5]; };     /* 结构体成员按声明顺序排，B 紧跟在 A 后面 */

struct Pair s;
for (int i = 0; i < 5; i++) { s.A[i] = (i + 1) * 2; s.B[i] = 100 + i; }
printf("B 的首地址比 A 的大 %ld 字节 = 5 * 4\n",
       (char*)&s.B[0] - (char*)&s.A[0]);

int i = 5;                           /* 用变量绕开编译期常量折叠 */
printf("A[5] 读出来 = %d\n", s.A[i]);         /* 越界读 */
printf("A[7] 读出来 = %d\n", s.A[7]);
s.A[i] = -1;                                  /* 越界写 */
printf("给 A[5] 写了 -1 之后，B[0] = %d\n", s.B[0]);
```

*代码 10：越界读写。*

```
A = 2 4 6 8 10
B = 100 101 102 103 104
B 的首地址比 A 的大 20 字节 = 5 * 4
A[5] 读出来 = 100
A[7] 读出来 = 102
给 A[5] 写了 -1 之后，B[0] = -1
```

`A[5]` 读到的正是 `B[0]`，`A[7]` 读到 `B[2]`，往 `A[5]` 里写 `-1` 直接把 `B[0]` 改掉了。整个过程 **gcc 开 `-Wall -Wextra` 一句警告都没有**，运行时也没有任何人吭声。

原因就是那条公式：**编译器只负责算地址，不负责判断这个地址还属不属于你。** C 里没有边界检查 —— 加上它意味着每次访问都要多一次比较、还要额外存着长度，这笔钱这门语言不肯出。

这也是数组最危险的地方：越界不会当场崩，它只是**悄悄改掉了旁边那个变量**。等到你发现 `B[0]` 不对，现场早就没了。

### 4.4 二维：行主序与列主序

二维数组要把 `(i, j)` 这一对下标压成一个偏移。压法有两种。

![同一张表，两种铺法](/img/posts/dsa-arrays/row-col-major.svg)

*图 6：一行一个颜色，看颜色在直线上排成什么样子。*

**行主序（row major）**：一行铺完再铺下一行。第 i 行前面压着 i 整行，每行 n 个元素，本行内再走 j 个：

$$
\mathrm{Addr}(A[i][j]) = L_0 + (i \times n + j) \times w \qquad (n = \text{列数})
$$

**列主序（column major）**：一列铺完再铺下一列。对称地：

$$
\mathrm{Addr}(A[i][j]) = L_0 + (j \times m + i) \times w \qquad (m = \text{行数})
$$

C / C++ 用的是行主序，Fortran 和 MATLAB 用的是列主序。拿 `int A[3][4]` 验一遍行主序：`A[2][1]` 应该在 $(2 \times 4 + 1) \times 4 = 36$，实测偏移正是 **36**。

**这两种映射一样快。** 不是「差不多」，是真的一样 —— 把两条公式分别编出来：

```asm
row_major:  imul esi, ecx        col_major:  imul edx, ecx
            add  esi, edx                    add  edx, esi
            mov  eax, [rdi+rsi*4]            mov  eax, [rdi+rdx*4]
```

一次乘、一次加、一次取数，指令形状完全相同。**所以选哪一种纯粹是语言设计者的自由**，两边都不吃亏。

### 4.5 算得一样快，走得不一样快

上一段说的是「算一个元素的地址」一样快。但**整个数组扫一遍**就完全是另一回事了。

![算地址一样快，走的顺序不一样快](/img/posts/dsa-arrays/cache-line.svg)

*图 7：一次内存访问搬回来的是一整条缓存行，用不用得上全看遍历顺序。*

同一个数组、同一个和，只把两层循环的顺序对调：

```cpp
for (int i = 0; i < N; i++)                     // 按行走
    for (int j = 0; j < N; j++) a += M[i][j];

for (int j = 0; j < N; j++)                     // 按列走
    for (int i = 0; i < N; i++) b += M[i][j];
```

*代码 11：区别只有 `i` 和 `j` 谁在外层。*

| 矩阵 | 占用 | 按行走 | 按列走 | 慢几倍 |
| --- | --- | --- | --- | --- |
| 512×512 | 1 MB | 0.05 ms | 0.22 ms | 4.1 × |
| 1024×1024 | 4 MB | 0.21 ms | 2.40 ms | 11.3 × |
| 2048×2048 | 16 MB | 0.83 ms | 17.77 ms | **21.5 ×** |
| 4096×4096 | 64 MB | 3.38 ms | 64.80 ms | 19.2 × |
| 8192×8192 | 256 MB | 14.18 ms | 300.68 ms | 21.2 × |

（每一档都重复多次取最快的一轮，整组跑三遍，大矩阵那几档稳定在 20 倍上下。）

两个和完全相等，访问次数一模一样，地址公式也一样便宜 —— 慢二十倍的原因不在公式里。

**在于 CPU 一次不只搬 4 个字节。** 它一次搬一整条**缓存行**（这台机器是 64 字节 = 16 个 `int`）。按行走，搬回来的 16 个接下来全用得上，平均 16 次访问才真的等一次内存；按列走，每走一步就跨过一整行，搬回来的 16 个只用 1 个，剩下 15 个在被用到之前就被挤出去了。

表里最小的那一档只差 4 倍，因为 1 MB 的矩阵整个待在这颗核自己的 L2（每核 1 MB）里，跳着走也跳不出去；再往上，差距就稳定在二十倍上下了。

**所以「行主序还是列主序」这个选择，真正的影响不在算地址，在于它决定了「哪种遍历顺序是顺着内存走的」。** C 是行主序，所以 C 里的双重循环，`j` 放内层。这是那种写法上零成本、收益却有二十倍的事。

### 4.6 推广到 n 维：把公式提一提

三维 `int A[2][3][4]` 就是「2 个 3×4 的表」，仍然一口气排在一条直线上。一层层往里嵌：

$$
\mathrm{Addr}(A[i][j][k]) = L_0 + \bigl((i \times 3 + j) \times 4 + k\bigr) \times w
$$

`A[1][2][3]` 算出来是 $((1 \times 3 + 2) \times 4 + 3) \times 4 = 92$，实测偏移正是 92（24 个元素逐个核对过，全部一致）。

推到 n 维，维度是 $d_1 \times d_2 \times \cdots \times d_n$，下标是 $i_1, i_2, \ldots, i_n$。**直接把每一项摊开写**是这样：

$$
\mathrm{Addr} = L_0 + \bigl(i_1 d_2 d_3 \cdots d_n + i_2 d_3 \cdots d_n + \cdots + i_{n-1} d_n + i_n\bigr) \times w
$$

数一下乘法：第一项要乘 $n-1$ 次，第二项 $n-2$ 次……最后再乘一个 $w$，一共

$$
\frac{n(n-1)}{2} + 1 \;=\; O(n^2)
$$

![推广到 n 维：把公式提一提](/img/posts/dsa-arrays/ndim-horner.svg)

*图 8：和上一章泰勒展开那道题是同一个招式。*

但这些项里有大量重复的公共因子。**从里往外提一层**：

$$
\mathrm{Addr} = L_0 + \Bigl( \bigl( \cdots ((i_1 d_2 + i_2) d_3 + i_3) d_4 \cdots \bigr) d_n + i_n \Bigr) \times w
$$

现在每多一维只多一次乘法，一共 **n 次，O(n)**。实测两种写法算出来的地址完全一致，乘法次数则是：

| 维数 n | 朴素展开 | 提取公因式后 |
| --- | --- | --- |
| 3 | 4 | 3 |
| 5 | 11 | 5 |
| 10 | 46 | 10 |

这就是上一章 6.4 节里泰勒展开的第二种写法 —— 秦九韶 / Horner。**同一个招式在两个完全不相干的地方出现，说明它不是那道题的技巧，是一条通用的路子**：一串项里如果反复出现同样的公共因子，就从里往外提，把重复的乘法省掉。

实话说，真实代码里很少写超过三维的数组，这个 O(n²) → O(n) 省下的是常数级的功夫。它值得记的原因在别处：**这是「地址公式」这条线能推到的最远的地方** —— 从一维的 $L_0 + iw$ 一路推到 n 维，中间没有任何新东西，全是同一条规则套下去。

## 小结

| 要点 | 一句话 |
| --- | --- |
| 数组的全部性质 | 地址连续 + 每个等宽，剩下的都是推论 |
| 初始化 | 只要写了初始化列表，没写到的位置一律补 0 |
| 垃圾值 | 不是随机数，是上一个人留在这块栈上的东西 |
| 下标 | `a[b]` 就是 `*(a+b)`，所以 `2[A]` 也能编过 |
| 传参 | 数组一传进函数就退化成指针，长度必须另外带 |
| 静态 / 动态 | 差的不是值能不能改，是**容量还能不能换一块** |
| 变长数组 | 是 **C99** 的东西，C++ 标准里没有；g++ 收是扩展 |
| 扩容 | 拷贝 → `delete[]` → 接名字，三步缺一个就是一个 bug；扩完旧指针全失效 |
| 扩多少 | 每次 +1 是 O(n²)，翻倍是均摊 O(1) |
| 二维的三种写法 | 只有 `int A[3][4]` 是一整块，另两种是「指针数组 + 几段」 |
| 地址公式 | $L_0 + i \times w$ —— 式子里没有 n，所以随机访问是 O(1) |
| 从 0 开始 | 为了让下标就是偏移；省下的那次减法在常数下界时根本不花钱 |
| 越界 | 公式只会算不会拦，改掉的是邻居的值，还不报错 |
| 行 / 列主序 | 算地址一样快，**遍历顺序**差二十倍 |
| n 维 | 提公因式，乘法从 O(n²) 降到 O(n) —— 和泰勒展开那题同一个招式 |

如果只留一条，那就是这条：**数组的一切，都是「地址连续 + 每个等宽」这两件事的推论。** 查得快是因为能算地址，越界不报错是因为算完了就直接用，按列走慢是因为算出来的地址跳着走 —— 连一次都没有例外。
