上一章把数组当成一个 ADT，实现了插入、删除、查找、反转等一系列操作。这一章讲字符串。C 语言里并没有专门的字符串类型，所谓字符串，其实就是一个以 `'\0'` 结尾的字符数组。所以上一章的很多做法在这里还能接着用，比如用两个指针反转、用一张表统计每个值出现的次数。

字符串和普通的整数数组相比有两点不同，这一章的大部分内容都是围绕这两点展开的。

- 第一点是字符本身就是数字。字符在内存里存的是它的 ASCII 编号，比如 `'A'` 存的是 65，所以字符之间可以直接做减法、比较大小。大小写转换、比较两个字符串、用字母当下标查表，依靠的都是这一点。
- 第二点是字符串不记录自己的长度。上一章的 Array ADT 用 `length` 记录元素个数，而字符串只在末尾放一个 `'\0'`，所以求长度要从头数到 `'\0'`，几乎每个函数的循环条件也都是「还没有碰到 `'\0'`」。如果末尾漏了 `'\0'`，这些循环就不知道应该在哪里停下来。

第一、二节讲字符和字符串在内存里是怎么存的。第三节是求长度、大小写转换、数单词、反转、比较和判断回文这几个基本操作。第四、五节分别用两层循环、计数表和位运算来查找重复字符、判断变位词。最后一节用递归写出一个字符串的全部排列。

## 一、字符就是一个小整数

### 1.1 ASCII

计算机只能存数字，所以要存字符，就得先给每个字符规定一个编号。ASCII 就是美国制定的一张字符编号表，一共 128 个字符，编号从 0 到 127。常用的几个编号如下：

| 字符 | 编号 | 字符 | 编号 |
| --- | --- | --- | --- |
| `'A'` | 65 | `'a'` | 97 |
| `'B'` | 66 | `'b'` | 98 |
| `'Z'` | 90 | `'z'` | 122 |
| `'0'` | 48 | `' '`（空格） | 32 |

![ASCII 一共 128 个字符](/img/posts/dsa-strings/ascii-map.svg)

*图 1：上半部分是 0 到 127 的分段，下半部分是 `'A'` 和 `'a'` 的二进制。*

因为 128 正好是 2⁷，所以 7 位二进制就能表示全部的 ASCII 字符。C 语言的 `char` 占 1 个字节，也就是 8 位，用它存 ASCII 字符时，最高的那一位始终是 0。

这张表里同一类字符的编号是连续的，这一点在后面会反复用到。大写字母从 65 排到 90，小写字母从 97 排到 122，数字字符从 48 排到 57。因此字符之间的减法是有意义的，比如 `'a' - 'A'` 等于 32，这就是同一个字母的大写和小写之间的距离；`'7' - '0'` 等于 7，也就是数字字符 `'7'` 所代表的数值。

从图 1 的下半部分还可以看出，`'A'`（0100 0001）和 `'a'`（0110 0001）只差从右往左数的第 5 位，而这一位的值正好是 32。所以大小写转换除了加减 32 以外，也可以用位运算来做，3.2 节会讲到。

### 1.2 Unicode 和 UTF-8

ASCII 只能表示英文字母、数字和常用的符号，中文、日文以及各种表情符号都不在里面。Unicode 的做法是给世界上的每一个字符都分配一个编号，这个编号叫作**码点**（code point），写成 U+ 加十六进制数的形式，比如「中」的码点是 U+4E2D。

Unicode 的码点范围是 U+0000 到 U+10FFFF，最大的那个码点需要 21 位才能表示。所以 16 位装不下全部的 Unicode 字符，说 Unicode 占 2 个字节并不准确。另外，码点只是一个编号，要真正存进内存，还需要选一种编码方式。常见的编码方式有两种。

- UTF-8 用 1 到 4 个字节存一个字符。ASCII 字符只占 1 个字节，而且编码和 ASCII 完全相同，所以纯英文的文本在 UTF-8 下和 ASCII 没有任何区别。Linux 和网页基本上都使用 UTF-8。
- UTF-16 以 2 个字节为一个单位，U+FFFF 以内的字符占 2 个字节，超过 U+FFFF 的字符（比如表情符号）占 4 个字节。Java 的 `char` 和 Windows 的宽字符用的就是 UTF-16，常说的「一个字符占 2 个字节」，指的其实是 UTF-16 的一个单位。

用 `iconv` 实际转换几个字符，得到的字节数如下：

| 字符 | 码点 | UTF-8 | UTF-16 |
| --- | --- | --- | --- |
| A | U+0041 | 1 字节 | 2 字节 |
| é | U+00E9 | 2 字节 | 2 字节 |
| 中 | U+4E2D | 3 字节 | 2 字节 |
| 😀 | U+1F600 | 4 字节 | 4 字节 |

在 Linux 上，C 源文件一般是按 UTF-8 保存的，所以 `strlen("中")` 的结果是 3，因为 `strlen` 数的是字节数，而不是字符数。这一章的代码都假定字符串里只有 ASCII 字符，也就是一个字符正好占一个字节。

## 二、字符变量和字符串

### 2.1 char 和单引号

`char` 是 C 语言里的一种数据类型，大小是 1 个字节，用来存一个字符：

```c
char temp = 'A';
printf("%c %d\n", temp, temp);     // 输出 A 65
```

字符常量要用单引号括起来。`temp` 里存的其实就是 65 这个数，用 `%c` 打印时显示成字符，用 `%d` 打印时显示成整数。反过来，写成 `char temp = 65;` 效果也完全一样。

这里的单引号既不能换成双引号，也不能省略。`"A"` 是一个字符串字面量，它占 2 个字节，分别是 `'A'` 和 `'\0'`。字符串字面量出现在表达式里时，代表的是它第一个字符的地址，所以 `char temp = "A";` 实际上是把一个地址塞进了只有 1 个字节的变量里。gcc 11 对这一行只给出一条警告，程序照样能编译运行，而 `temp` 得到的是这个地址的最低一个字节，这台机器上运行两次都是 4：

```
warning: initialization of 'char' from 'char *' makes integer from pointer without a cast [-Wint-conversion]
temp = 4
```

如果完全不加引号，`A` 就会被当成一个变量名，编译器会报 `error: 'A' undeclared`。

### 2.2 字符数组的几种初始化

一个 `char` 只能存一个字符，要存多个字符就要用字符数组。字符数组有下面几种初始化的写法：

```c
char x[5];                                   // 只声明，不初始化
char x[5] = {'A', 'B', 'C', 'D', 'E'};
char x[5] = {65, 66, 67, 68, 69};            // 和上一行完全相同
char x[]  = {'A', 'B', 'C', 'D', 'E'};       // 大小由初值的个数决定，是 5
char x[5] = {'A', 'B'};                      // 只给前两个
```

*代码 1：字符数组的五种初始化。*

把后四种写法的每个字节打印出来，结果如下：

```
char a[5]={'A','B','C','D','E'}    sizeof=5  65 66 67 68 69
char b[5]={65,66,67,68,69}         sizeof=5  65 66 67 68 69
char c[]={'A',...,'E'}             sizeof=5  65 66 67 68 69
char d[5]={'A','B'}                sizeof=5  65 66 0 0 0
```

前三种写法得到的内容完全相同，因为 `'A'` 本来就是 65。第一种写法 `char x[5];` 没有给初值。如果它是函数里的局部变量，那么里面的内容就是栈上原来留下的值，不能直接拿来用；如果它是全局变量或者 `static` 变量，那么内容全是 0。

最后一种写法只给了两个初值。C 语言规定，数组里没有给出初值的元素一律补 0，所以 `x[2]` 到 `x[4]` 都是 0。下一节会看到，因为这个数组的末尾正好有 0，所以它已经是一个合法的字符串 `"AB"` 了。

### 2.3 '\0'：字符数组和字符串的区别

字符串就是一个以 `'\0'` 结尾的字符数组。`'\0'` 叫作**空字符**，它的编号是 0。需要注意的是，它和字符 `'0'`（编号 48）是两个不同的字符。

为什么需要这样一个结尾标记呢？这是因为 C 语言把字符串传给函数时，传过去的只是第一个字符的地址，至于数组有多大、里面存了几个字符，这些信息都没有传过去。所以 `printf("%s")`、`strlen` 这类函数只能从第一个字符开始往后读，读到 `'\0'` 就认为字符串结束了。

要让字符数组的末尾带上 `'\0'`，有两种写法：

```c
char x[] = {'A', 'B', 'C', 'D', 'E', '\0'};  // 手动加上
char x[] = "ABCDE";                          // 双引号会自动在末尾加上 '\0'
```

*代码 2：两种写法得到的都是 6 个字节，`sizeof(x)` 是 6，`strlen(x)` 是 5。*

![字符数组和字符串](/img/posts/dsa-strings/char-arrays.svg)

*图 2：绿色的格子是 `'\0'`，第三行的虚线格子是紧挨着的另一个数组。*

如果末尾没有 `'\0'`，`printf` 就会一直往后读，直到在内存里碰到一个值为 0 的字节为止。下面这个程序在 `c` 的前面还声明了另一个数组 `s`：

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char s[8] = "abcdefg";
    char c[]  = {'A', 'B', 'C', 'D', 'E'};     // 没有 '\0'
    printf("[%s] strlen=%zu\n", c, strlen(c));
    return 0;
}
```

*代码 3：字符数组的末尾没有 '\0'。*

用 `gcc -O0` 编译运行时，`s` 在栈上正好紧挨在 `c` 的后面，于是 `s` 的内容也被当成了 `c` 的一部分：

```
[ABCDEabcdefg] strlen=12
```

如果改用 `-O2` 编译，变量的排列方式就变了，`c` 后面碰巧是一个 0，于是输出又变成了完全正确的 `[ABCDE] strlen=5`。只有打开 AddressSanitizer，才能看到这里确实发生了越界读：

```
ERROR: AddressSanitizer: stack-buffer-overflow
READ of size 6 ...
    [32, 37) 'c' (line 6) <== Memory access at offset 37 overflows this variable
```

这和上一章 2.4 节、5.3 节遇到的情况一样，-O2 下的输出虽然完全正确，但是程序照样读到了数组外面。

还有一种写法也会漏掉 `'\0'`：

```c
char z[5] = "Hello";
```

`"Hello"` 有 5 个字符，加上 `'\0'` 一共需要 6 个字节，但是数组只开了 5 个字节。C 语言允许这种写法，这时编译器会把 5 个字符放进去，然后直接丢掉 `'\0'`，即使加上 `-Wall -Wextra`，gcc 也没有给出任何警告。同样的代码如果用 g++ 编译，就会直接报错 `initializer-string for 'char [5]' is too long`。所以用双引号初始化时，要么不写数组的大小，让编译器自己去算；要么让数组的大小比字符个数多 1。

### 2.4 数组和指针：字面量不能改

字符串还有一种常见的写法是用指针。下面这个程序把两种写法放在一起：

```c
#include <stdio.h>

int main(void) {
    char a[] = "hello";       // 数组：字面量的内容被复制到栈上
    char *p  = "hello";       // 指针：指向只读区里的字面量
    a[0] = 'H';
    printf("%s\n", a);
    p[0] = 'H';
    printf("%s\n", p);
    return 0;
}
```

*代码 4：数组可以修改，指针指向的字面量不能修改。*

```
Hello
Segmentation fault (core dumped)
```

这两行声明看起来很像，但是含义完全不同。`char a[] = "hello"` 会在栈上开一个 6 字节的数组，再把字面量的内容复制进去，所以 `a` 的内容可以随便修改。而 `char *p = "hello"` 只在栈上开了一个 8 字节的指针，它指向的是程序里的字面量本身。字面量存放在只读的 `.rodata` 段里（用 `objdump -s -j .rodata` 可以看到 `hello` 就在那里），所以通过 `p` 去修改它时，程序会因为段错误被系统终止。

为了让编译器提前发现这种错误，指向字面量的指针最好写成 `const char *p`。后面的大小写转换和反转都会直接修改字符串，所以传给它们的必须是数组，而不能是指向字面量的指针。

## 三、扫到 '\0' 为止

### 3.1 求长度

```c
int Length(const char *s) {
    int i;
    for (i = 0; s[i] != '\0'; i++)
        ;
    return i;
}
```

*代码 5：求长度。循环体是空的，所有的工作都在循环条件里完成。*

i 从 0 开始，每遇到一个不是 `'\0'` 的字符就加一，最后停在 `'\0'` 的下标上。因为下标是从 0 开始的，所以 `'\0'` 的下标正好等于字符的个数。对 `"Welcome"` 运行，结果是 7，和标准库的 `strlen` 相同；空字符串 `""` 的结果是 0。

求长度的时间复杂度是 O(n)，而上一章的 Array ADT 只要读一下 `length` 就知道长度，是 O(1)。之所以有这个差别，是因为字符串不记录自己的长度。这会带来一个很常见的性能问题，如果在循环条件里写 `i < strlen(s)`，那么每一轮循环都要重新数一遍长度，整个循环就从 O(n) 变成了 O(n²)：

```c
for (int i = 0; i < strlen(s); i++)     // 每一轮都重新数一遍
    ...
int len = strlen(s);                     // 先算好，循环里只比较整数
for (int i = 0; i < len; i++)
    ...
```

用代码 5 代替 `strlen` 并统计读取字符的次数，`-O0` 下的实测结果如下：

| 字符串长度 n | 循环条件里求长度 | 先算好长度 |
| --- | --- | --- |
| 10 | 121 | 11 |
| 1 000 | 1 002 001 | 1 001 |
| 10 000 | 100 020 001 | 10 001 |

循环一共要判断 n + 1 次条件，每次求长度都要读 n + 1 个字符（包括 `'\0'`），所以总次数正好是 (n + 1)²。

另外，求长度和 `sizeof` 是两回事。对 `char a[] = "Welcome";` 来说，`sizeof a` 是 8，因为它算的是整个数组占多少字节，其中包括 `'\0'`；而 `Length(a)` 是 7。如果 `a` 是一个指针，那么 `sizeof` 得到的就是指针本身的大小 8，和字符串的内容没有关系。

### 3.2 大小写转换

1.1 节说过，同一个字母的大写和小写编号相差 32，大写在前，小写在后。所以大写字母加上 32 就变成了小写，小写字母减去 32 就变成了大写。

但是在转换之前，一定要先判断这个字符是不是字母。如果把每个字符都减去 32，那么空格（32）就会变成 0，也就是 `'\0'`，字符串会从空格的位置被截断：

```
"hello world" 的每个字符都减去 32
输出: [HELLO] strlen=5
字节: 72 69 76 76 79 0 87 79 82 76 68 0
```

从字节可以看出，后面的 `WORLD` 其实也已经转换好了，但是因为它前面多出了一个 `'\0'`，`printf` 读到那里就停了。正确的写法是先判断范围，只转换字母，其他字符保持不变：

```c
void ToggleCase(char *s) {
    for (int i = 0; s[i] != '\0'; i++) {
        if (s[i] >= 'A' && s[i] <= 'Z')      s[i] += 32;    // 大写变小写
        else if (s[i] >= 'a' && s[i] <= 'z') s[i] -= 32;    // 小写变大写
    }
}
```

*代码 6：大小写互换。如果只想全部转成大写或者全部转成小写，保留其中一个分支就可以了。*

```
前  WeLcOmE to C 2026!
后  wElCoMe TO c 2026!
```

可以看到，数字、空格和感叹号都没有变化。代码里用 `'A'`、`'Z'` 这样的字符常量来表示范围，而没有直接写 65、90，因为字符常量本身就是编号，这样写更容易看懂。

从二进制的角度看，加减 32 其实就是修改第 5 位（图 1）。所以 `s[i] ^= 32` 可以翻转大小写，`s[i] | 32` 一定得到小写，`s[i] & ~32` 一定得到大写。但是位运算同样只能用在字母上，如果对整个字符串都做 `^= 32`，那么空格同样会变成 `'\0'`，数字 `'2'`（50）也会变成编号为 18 的控制字符。标准库 `<ctype.h>` 里的 `toupper` 和 `tolower` 每次只转换一个字符，遇到不是字母的字符会原样返回，所以不需要自己判断范围。

### 3.3 数单词

最简单的想法是数空格。因为单词之间用空格隔开，所以单词数就等于空格数加一。

```c
int words = 1;
for (int i = 0; s[i] != '\0'; i++)
    if (s[i] == ' ') words++;
```

不过，这只在每两个单词之间正好隔一个空格时才成立。如果两个单词之间有连续多个空格，那么多出来的空格都会被当成新的单词。一种改进的办法是只数「前一格不是空格」的空格，这样连续的一串空格只会算一次：

```c
int words = 1;
for (int i = 0; s[i] != '\0'; i++)
    if (s[i] == ' ' && s[i - 1] != ' ') words++;
```

*代码 7：数空格的两种写法。*

第二种写法能处理中间的连续空格，但是开头和结尾的空格它仍然处理不好。而且如果字符串的第一个字符就是空格，那么 i = 0 时就会去读 `s[-1]`，这就越界了。下面以 `How are you` 为基础，在不同的位置多加几个空格，把这几种情况都实测一遍：

| 字符串 | 空格数 + 1 | 只数前一格不是空格的 | 数词首 |
| --- | --- | --- | --- |
| `How are you` | 3 | 3 | 3 |
| 单词之间分别隔 2 个、3 个空格 | 6 | 3 | 3 |
| 结尾多 2 个空格 | 5 | 4 | 3 |
| 开头多 2 个空格 | 5 | 4（读了 `s[-1]`） | 3 |
| 空串 `""` | 1 | 1 | 0 |
| 只有 3 个空格 | 4 | 2（读了 `s[-1]`） | 0 |

标着「读了 `s[-1]`」的两行，把字符串复制到堆上再用 AddressSanitizer 运行，都会报 `heap-buffer-overflow`，位置是字符串左边 1 个字节（`1 bytes to the left of`）。不开 ASan 时得到的 4 和 2，取决于 `s[-1]` 里碰巧是什么值。如果它碰巧不是空格，那么 i = 0 的那个空格也会被多算成一个单词。

表格的最后一列换了一个角度，不再去数空格，而是数单词的开头。如果一个字符不是空格，并且它是第一个字符，或者它前面的字符是空格，那么它就是一个单词的第一个字母。因为每个单词都正好有一个开头，所以这样数出来的就是单词数，不需要再加一，而且开头、中间、结尾有多少个空格都不会影响结果。

```c
int Words(const char *s) {
    int words = 0;
    for (int i = 0; s[i] != '\0'; i++)
        if (s[i] != ' ' && (i == 0 || s[i - 1] == ' ')) words++;
    return words;
}
```

*代码 8：数词首。*

![数单词](/img/posts/dsa-strings/word-count.svg)

*图 3：同一个字符串用三种方法来数，只有数词首得到了正确的 3。*

括号里把 `i == 0 ||` 写在前面，是为了借助短路求值。当 i 等于 0 时，整个括号已经为真，程序就不会再去读 `s[-1]` 了。如果单词之间还可能出现制表符或者换行符，可以把 `== ' '` 换成 `<ctype.h>` 里的 `isspace`。

### 3.4 反转

反转字符串的做法和上一章 5.1 节反转数组一样，既可以借助另一个数组，也可以用两个指针原地交换。唯一需要注意的是末尾的 `'\0'`，它必须留在原来的位置，不能参与反转。

```c
void Reverse(char *s) {
    int j = 0;
    while (s[j] != '\0') j++;      // j 停在 '\0' 上
    j--;                           // 退回到最后一个字符
    for (int i = 0; i < j; i++, j--) {
        char t = s[i];
        s[i] = s[j];
        s[j] = t;
    }
}
```

*代码 9：原地反转。*

第一个 while 循环结束时，j 停在 `'\0'` 上，所以要先减一，让 j 指向最后一个字符，然后才能开始交换。如果漏掉了这一句 `j--`，第一次交换就会把 `'\0'` 换到最前面：

```
Reverse("python")      输出 nohtyp
漏掉 j-- 的版本        输出空串，strlen=0
字节: 0 110 111 104 116 121 112
```

![反转时的 '\0'](/img/posts/dsa-strings/reverse-null.svg)

*图 4：上半部分的 j 从最后一个字符开始，下半部分的 j 从 `'\0'` 开始。*

从字节可以看出，后面 6 个字节其实已经是 `nohtyp` 了，但是因为第一个字节是 0，所以 `printf` 一个字符都不会打印。

如果借助另一个数组 B 来反转，同样要记得在 B 的末尾补上 `'\0'`：

```c
void ReverseCopy(const char *a, char *b) {
    int i = 0, j;
    while (a[i] != '\0') i++;
    for (i = i - 1, j = 0; i >= 0; i--, j++)
        b[j] = a[i];
    b[j] = '\0';                   // 不补的话，b 就不是字符串
}
```

*代码 10：借助另一个数组反转。*

两种方法的时间复杂度都是 O(n)。借助另一个数组的方法需要 O(n) 的额外空间，而原地交换只需要 O(1)。另外，原地反转会修改字符串，所以按照 2.4 节的说法，不能直接对 `char *p = "python"` 这样的字面量调用 `Reverse`。

### 3.5 比较

比较两个字符串的大小时，要从头开始逐个比较字符，找到第一个不相同的字符，再比较这两个字符的编号。两个字符串谁长谁短，并不直接决定谁大谁小。

```c
int Compare(const char *a, const char *b) {
    int i = 0;
    while (a[i] != '\0' && a[i] == b[i]) i++;
    return a[i] - b[i];            // 小于 0、等于 0、大于 0
}
```

*代码 11：比较两个字符串。*

循环条件只检查了 `a[i]` 是不是 `'\0'`，并没有检查 `b[i]`。这是因为当 `a[i] == b[i]` 并且 `a[i]` 不是 `'\0'` 时，`b[i]` 也一定不是 `'\0'`。循环停下来有两种可能，一种是找到了不相同的字符，另一种是两个字符串同时结束了。无论是哪一种情况，返回 `a[i] - b[i]` 都能得到正确的结果，如果两个字符串同时结束，返回的就是 0，表示两个字符串相等。

```
Painter   Painting   -4      'e'(101) 比 'i'(105) 小
Paint     Painter    -101    '\0'(0) 比 'e'(101) 小
Zebra     apple      -7      'Z'(90) 比 'a'(97) 小
hello     hello      0
```

这几行结果说明了两件事。第一，如果一个字符串是另一个字符串的前缀，那么短的那个更小，因为 `'\0'` 的编号是 0，比任何字符都小。第二，所有的大写字母都排在小写字母前面，所以 `"Zebra"` 比 `"apple"` 小，这和查字典时不分大小写的顺序是不一样的。

标准库的 `strcmp` 做的也是同一件事。C 标准只规定了 `strcmp` 返回值的正负号，这台机器上的 glibc 返回的正好是这两个字符的差，和上面的结果完全一样。但是其他实现不一定会这样返回，所以判断时应该写 `strcmp(a, b) < 0`，而不是 `strcmp(a, b) == -1`。

如果字符串里有 UTF-8 编码的中文或者其他非 ASCII 字符，代码 11 还会出问题。这些字符的每个字节都大于等于 128，而 x86 上的 `char` 是有符号的，所以 128 以上的字节会被当成负数。比如 `"é"` 的第一个字节是 0xC3，按 `char` 读出来是 -61，于是 `Compare("é", "z")` 返回 -183，认为 `"é"` 更小；而 `strcmp` 是按 `unsigned char` 来比较的，返回 73。所以只要在相减之前把两个字符都转换成 `unsigned char`，结果就和 `strcmp` 一致了。

### 3.6 回文

回文指的是正着读和倒着读都一样的字符串，比如 `"madam"` 和 `"racecar"`。判断回文有两种方法。

第一种方法是把字符串反转一遍，然后和原来的字符串比较。需要注意的是，反转的必须是一份副本。如果直接在原字符串上反转，那么原来的内容就没有了，拿反转后的结果和它自己比较，结果永远是相等的，这样连 `"python"` 也会被判断成回文。

第二种方法不需要副本。i 从第一个字符开始，j 从最后一个字符开始，两个指针往中间走，每一步比较 `s[i]` 和 `s[j]`，只要有一对不相等，就说明不是回文。

```c
int IsPalindrome(const char *s) {
    int j = 0;
    while (s[j] != '\0') j++;
    j--;
    for (int i = 0; i < j; i++, j--)
        if (s[i] != s[j]) return 0;
    return 1;
}
```

*代码 12：用两个指针判断回文。*

| 字符串 | 是不是回文 | 比较次数 |
| --- | --- | --- |
| `"madam"` | 是 | 2 |
| `"racecar"` | 是 | 3 |
| `"abba"` | 是 | 2 |
| `"python"` | 不是 | 1 |
| `"Madam"` | 不是 | 1 |

长度为 n 的回文要比较 ⌊n/2⌋ 次，如果长度是奇数，正中间的那个字符不需要和任何字符比较。不是回文的字符串，在第一对不相等的地方就返回了。所以这种方法的时间复杂度是 O(n)，额外空间是 O(1)，而第一种方法还需要 O(n) 的额外空间来存放副本。`"Madam"` 之所以不是回文，是因为 `'M'` 和 `'m'` 的编号不同。如果要忽略大小写，可以先用 3.2 节的方法把字符串统一转换成小写，然后再判断。

## 四、找重复的字符

这一节要找出字符串里出现了不止一次的字符，比如 `"finding"` 里的 i 和 n 都出现了 2 次。下面三种方法分别用两层循环、一张表和一个整数来记录「哪些字符已经出现过」。

### 4.1 两层循环

和上一章 7.2 节查找无序数组里的重复元素一样，可以先固定一个字符，再拿它和后面的每个字符逐一比较，统计相同字符的个数。

```c
for (int i = 0; s[i] != '\0'; i++) {
    int seen = 0;
    for (int k = 0; k < i; k++)              // 前面出现过，说明已经数过了
        if (s[k] == s[i]) { seen = 1; break; }
    if (seen) continue;
    int count = 1;
    for (int j = i + 1; s[j] != '\0'; j++)
        if (s[j] == s[i]) count++;
    if (count > 1) printf("%c 出现 %d 次\n", s[i], count);
}
```

*代码 13：用两层循环找重复，O(n²)。*

中间那个往前看的循环是为了避免重复打印。以 `"banana"` 为例，a 在下标 1、3、5 各出现了一次，如果没有这个检查，那么 i = 1 时会打印「a 出现 3 次」，i = 3 时又会打印一遍「a 出现 2 次」。上一章的做法是把数过的元素改成 -1 作为标记。但是字符串一般不应该被这样修改，而且如果把数过的字符改成了 0，字符串还会从那里被截断，所以这里改成了往前看一眼。

```
finding:  i 出现 2 次, n 出现 2 次
banana:   a 出现 3 次, n 出现 2 次
```

### 4.2 哈希表：用字母当下标

也可以像上一章 7.1 节的查表法那样，开一张表 H，用字符当下标，`H[c]` 记录字符 c 出现了几次。这里假设字符串里只有小写字母。`'a'` 到 `'z'` 的编号是 97 到 122，如果直接用编号当下标，表就要开 123 格，而且前面的 97 格永远都用不到。所以先减去 `'a'`，让下标变成 0 到 25，这样表只需要 26 格。

```c
int H[26] = {0};
for (int i = 0; s[i] != '\0'; i++)
    H[s[i] - 'a']++;
for (int v = 0; v < 26; v++)
    if (H[v] > 1) printf("%c 出现 %d 次\n", v + 'a', H[v]);
```

*代码 14：用一张 26 格的表计数，O(n)。*

这里写的是 `s[i] - 'a'` 而不是 `s[i] - 97`。两者的值完全相同，但是前者一看就知道是在算「这个字母在字母表里排第几」。打印的时候反过来再加上 `'a'`，就把下标还原成了字母。

扫描一遍字符串是 O(n)，扫描一遍表是 O(26)，所以总的时间复杂度是 O(n)。这种方法的前提是字符串里只有小写字母，比如大写的 `'F'` 减去 `'a'` 得到的是 -27，这时访问 `H[-27]` 就越界了。如果字符串里可能出现任意的 ASCII 字符，那么可以直接开 128 格的表，用字符本身的编号当下标。

### 4.3 位运算：一个 int 当 26 个开关

如果只需要知道有没有重复，而不需要知道重复了几次，那么表里的每一格只需要存 0 或 1。一个 int 有 32 位，每一位都可以当作一格来用，所以 26 个字母正好装得下。

要操作单独的某一位，需要用到下面三个位运算：

| 运算 | 例子 | 用途 |
| --- | --- | --- |
| 左移 `<<` | `1 << 3` 得到 `1000` | 造出一个只有第 3 位是 1 的数 |
| 按位与 `&` | `1010 & 1000` 得到 `1000` | 检查某一位是不是 1，也叫掩码 |
| 按位或 `\|` | `1010 \| 0100` 得到 `1110` | 把某一位设成 1，也叫合并 |

具体的做法是，对每个字符先算出它对应的那一位 `x = 1u << (s[i] - 'a')`，再用 `H & x` 检查 H 里的这一位是不是已经是 1。如果是 1，说明这个字母之前出现过；如果是 0，就用 `H |= x` 把这一位设成 1，表示这个字母已经出现过了。

```c
unsigned int H = 0;
for (int i = 0; s[i] != '\0'; i++) {
    unsigned int x = 1u << (s[i] - 'a');
    if (H & x) printf("%c 重复\n", s[i]);   // 这一位已经是 1
    else       H |= x;                      // 把这一位设成 1
}
```

*代码 15：用一个 32 位整数记录出现过的字母。*

对 `"finding"` 逐步跟踪 H 的变化，结果如下（只列出低 26 位）：

```
字符  位   H & x   之后的 H
f     5    0       00000000000000000000100000
i     8    0       00000000000000000100100000
n     13   0       00000000000010000100100000
d     3    0       00000000000010000100101000
i     8    非 0    00000000000010000100101000   i 重复
n     13   非 0    00000000000010000100101000   n 重复
g     6    0       00000000000010000101101000
```

![一个 int 当 26 个开关](/img/posts/dsa-strings/bitset.svg)

*图 5：读到第二个 i 时，x 只有第 8 位是 1，而 H 的第 8 位已经被第一个 i 设成了 1。*

这种方法只用了一个 4 字节的整数，而 4.2 节的表需要 26 个 int，也就是 104 个字节。但是一位只能表示「出现过」和「没出现过」两种状态，没有办法计数。比如对 `"banana"` 运行，结果是：

```
a 重复
n 重复
a 重复
```

a 一共出现了 3 次，所以第二次和第三次出现时各报了一次重复，而且从输出里也看不出它到底出现了几次。如果需要知道次数，还是要用 4.2 节的计数表。另外，代码里把 H 和 x 都声明成了 `unsigned int`，这是因为把 1 左移到有符号 int 的第 31 位属于未定义行为。26 个字母用不到这一位，但是写成无符号数以后，就不用再考虑这个问题了。

## 五、变位词

如果两个字符串由完全相同的字符组成，只是排列的顺序不同，那么就称它们互为**变位词**（anagram），比如 `"decimal"` 和 `"medical"`、`"listen"` 和 `"silent"`。这里的「相同」不只是用到了同样几个字母，每个字母出现的次数也必须相同。

### 5.1 两层循环

最直接的想法是拿第一个字符串的每个字符，到第二个字符串里去查找，如果每个字符都能找到，就认为它们是变位词。但是这个方法在有重复字母时会出错，比如 `"aab"` 和 `"abb"`。`"aab"` 里的 a 能在 `"abb"` 里找到，b 也能找到，于是这个方法认为它们是变位词，可实际上 `"aab"` 有两个 a，`"abb"` 只有一个。

问题在于，第二个字符串里的同一个 a 被找到了两次。解决的办法是，每找到一个字符，就在第二个字符串的副本里把它划掉（换成一个不会出现的字符），这样同一个字符就不能被使用第二次了。改成划掉以后，`"aab"` 和 `"abb"` 的结果就变成了「不是」。

两层循环的时间复杂度是 O(n²)。另外，在逐个查找之前还应该先比较两个字符串的长度，因为长度不同的两个字符串一定不是变位词。

### 5.2 计数表

更快的方法是用 4.2 节的计数表。扫描第一个字符串时，每个字母对应的格子加一；扫描第二个字符串时，每个字母对应的格子减一。如果两个字符串互为变位词，那么加减之后，所有格子都应该回到 0。

```c
int IsAnagram(const char *a, const char *b) {
    if (strlen(a) != strlen(b)) return 0;
    int H[26] = {0};
    for (int i = 0; a[i] != '\0'; i++) H[a[i] - 'a']++;
    for (int i = 0; b[i] != '\0'; i++)
        if (--H[b[i] - 'a'] < 0) return 0;   // b 里这个字母比 a 里多
    return 1;
}
```

*代码 16：用计数表判断变位词，O(n)。*

在第二个循环里，只要某一格减到了负数，就说明 b 里的这个字母比 a 里的多，于是可以直接返回。如果第二个循环顺利走完了，就说明没有任何一格是负数。又因为两个字符串的长度相同，表里所有格子加起来等于 0，而每一格都不是负数，所以每一格都只能是 0，也就是说两个字符串互为变位词。

开头的长度检查不能省略。如果去掉它，`IsAnagram("abc", "ab")` 会返回 1，因为 b 比 a 短，扫描 b 时没有任何一格减到负数，而 c 那一格剩下的 1 根本没有被检查到。几组实测结果如下：

| 两个字符串 | 逐个查找 | 划掉、计数表 | 计数表不查长度 |
| --- | --- | --- | --- |
| `decimal`、`medical` | 是 | 是 | 是 |
| `aab`、`abb` | 是（错误） | 不是 | 不是 |
| `abc`、`ab` | 不是 | 不是 | 是（错误） |

4.3 节的位运算在这里用不上。`"aab"` 和 `"abb"` 用到的字母都是 a 和 b，所以两个整数的各个位完全相同，但是它们并不是变位词。判断变位词需要知道每个字母出现的次数，而一位只能表示一个字母有没有出现过。

## 六、全排列

最后一个问题是打印一个字符串的全部排列。比如 `"ABC"` 一共有 3! = 6 种排列，分别是 ABC、ACB、BAC、BCA、CAB、CBA。

### 6.1 状态空间树

手工列举排列时，一般会先决定第一个位置放哪个字符，这时有 3 种选择。第一个位置确定以后，第二个位置还剩 2 种选择，最后一个位置就只剩 1 种选择了。把这个过程画出来，就得到了一棵树，这棵树叫作**状态空间树**（state space tree）。

![ABC 的状态空间树](/img/posts/dsa-strings/perm-tree.svg)

*图 6：每往下走一层就确定一个位置，从根走到叶子的路线就是一个排列。粉色的路线是 BCA。*

这棵树一共有 1 + 3 + 6 + 6 = 16 个节点，最底层的 6 个叶子对应 6 种排列。程序要做的，就是把这棵树完整地走一遍。从根出发往下走，每到一个叶子就打印一次；走到底以后退回上一层，撤销刚才的选择，再去试下一个分支。这种「试一个分支，退回来，再试下一个分支」的做法叫作**回溯**（backtracking），用递归来写是最自然的。

### 6.2 写法一：标记数组加结果数组

```c
void Perm(const char S[], int k) {
    static int  T[10] = {0};     // T[i] == 1 表示 S[i] 已经用过了
    static char R[10];           // 正在拼的排列
    if (S[k] == '\0') {          // R 已经放满了
        R[k] = '\0';
        printf("%s\n", R);
        return;
    }
    for (int i = 0; S[i] != '\0'; i++) {
        if (T[i] == 0) {         // S[i] 还没用过
            R[k] = S[i];
            T[i] = 1;
            Perm(S, k + 1);
            T[i] = 0;            // 回来以后，把 S[i] 还回去
        }
    }
}
```

*代码 17：全排列的第一种写法，调用方式是 `Perm("ABC", 0)`。*

参数 k 表示现在要填 R 的第几个位置，也就是正处在树的第几层。T 是标记数组，`T[i]` 为 0 表示 `S[i]` 还没有被用过，为 1 表示它已经被放进 R 里了。每一层都从头到尾扫描一遍 S，遇到 `T[i]` 为 1 的字符就跳过，遇到 `T[i]` 为 0 的字符就把它放进 `R[k]`，同时把 `T[i]` 设成 1，然后递归去填下一个位置。当 `S[k]` 是 `'\0'` 时，k 已经等于字符串的长度，这说明 R 已经放满了，于是在末尾补上 `'\0'`，然后打印出来。

对 `"ABC"` 运行，输出的 6 个排列依次是：

```
ABC ACB BAC BCA CAB CBA
```

如果输入的字符本来就是按顺序排列的，那么输出正好也是字典序，因为每一层都是从前往后挑选字符的。实测 `Perm` 一共被调用了 16 次，正好等于图 6 中的节点个数；对 `"ABCD"` 运行，一共调用了 65 次（1 + 4 + 12 + 24 + 24），打印了 24 个排列。

这段代码里有两个地方最容易出错。

第一个是递归调用后面的 `T[i] = 0`，它就是回溯里撤销选择的那一步。递归返回以后，`S[i]` 要被还回去，这样下一轮循环换另一个字符放在当前位置时，`S[i]` 还可以放在后面的位置上。如果漏掉了这一句，用过的字符就永远不会被还回去：

```
漏掉 T[i] = 0，第一次调用: ABC        （只调用了 4 次）
              第二次调用: 什么也没打印
```

第一次调用走到第一个叶子以后，三个字符全都被标记成了用过，后面的分支一个都走不进去。而且因为 T 是静态的，这些 1 会一直保留到下一次调用，所以第二次调用连一个排列都打印不出来。

第二个是 `static`。T 和 R 必须是所有递归层共用的同一份，这样下一层才能看到上一层标记了哪些字符、往 R 里放了哪些字符。普通的局部数组在每次调用时都会重新创建一份，如果把 T 改成普通的局部数组 `int T[10] = {0};`，那么每一层看到的 T 都是全 0，任何字符都可以被重复使用，结果就从 6 个排列变成了 3³ = 27 个字符串：

```
AAA AAB AAC ABA ABB ABC ACA ACB ACC BAA ... CCC
```

加上 `static` 以后，T 和 R 在整个程序运行期间只有一份，所有递归层读写的都是同一个数组。把它们改成全局变量，或者作为参数一层一层传下去，效果也是一样的。另外，因为数组的大小是 10，所以这个函数最多只能处理 9 个字符的字符串。

### 6.3 写法二：原地交换

第二种写法不需要额外的数组，它直接在 S 上交换字符：

```c
void swap(char *x, char *y) { char t = *x; *x = *y; *y = t; }

void Perm2(char S[], int l, int h) {
    if (l == h) {                    // 只剩最后一个位置，只有一种放法
        printf("%s\n", S);
        return;
    }
    for (int i = l; i <= h; i++) {
        swap(&S[l], &S[i]);          // 让 S[i] 来当第 l 个字符
        Perm2(S, l + 1, h);
        swap(&S[l], &S[i]);          // 换回来
    }
}
```

*代码 18：全排列的第二种写法，调用方式是 `char s[] = "ABC"; Perm2(s, 0, 2);`。*

l 和 h 分别指向还没有确定的那一段的头和尾。下标 0 到 l − 1 的字符已经确定了，现在要决定第 l 个位置放哪个字符，候选的字符就是 `S[l]` 到 `S[h]`。循环让它们依次和 `S[l]` 交换，每交换一次，就递归去排列剩下的 `S[l + 1]` 到 `S[h]`。当 l 等于 h 时，只剩下最后一个位置，也只剩下一个字符，这时整个字符串就是一种排列。因为这个函数会修改 S，所以按照 2.4 节的说法，传进去的必须是数组，不能是字面量。

![交换法的递归树](/img/posts/dsa-strings/perm-swap.svg)

*图 7：方框里是进入每一层时 S 的内容，线上写的是往下走之前做了哪一次交换。*

```
ABC ACB BAC BCA CBA CAB
```

这个顺序并不是字典序，最后两个是 CBA、CAB。这是因为 l = 0 时的第三个分支把 A 和 C 做了交换，S 变成了 `"CBA"`，所以在这个分支里先得到的是 CBA。实测 `"ABC"` 一共调用了 10 次，`"ABCD"` 一共调用了 41 次（1 + 4 + 12 + 24），比写法一的 16 次和 65 次都少，因为写法二在只剩一个位置时就直接打印了，少走了最后一层。

和写法一一样，递归调用后面的那次交换也不能省略。循环的每一轮都假设 `S[l]` 到 `S[h]` 还是刚进入这一层时的样子，如果上一轮的交换没有换回来，下一轮就是在一个已经被打乱的字符串上继续交换。实测去掉第二次 `swap` 以后，`"ABC"` 的输出是：

```
ABC ACB CAB CBA ABC ACB
```

虽然一共打印了 6 个，但是 ABC 和 ACB 各出现了两次，BAC 和 BCA 却一次都没有出现，而且程序结束后 S 也没有恢复成 `"ABC"`，而是变成了 `"ACB"`。由此可见，写法一里的 `T[i] = 0` 和写法二里的第二次交换做的是同一件事，也就是在回溯时撤销刚才的选择。

两种写法的对比如下：

| | 写法一（标记数组） | 写法二（原地交换） |
| --- | --- | --- |
| 额外空间 | T、R 两个数组 | 不需要 |
| 调用次数（ABC） | 16 | 10 |
| 输出顺序 | 输入有序时是字典序 | 不是字典序 |
| 撤销选择 | `T[i] = 0` | 再交换一次 |

两种写法都要打印 n! 个排列，每个排列的长度都是 n，所以时间复杂度都是 O(n · n!)。n! 增长得非常快，10 个字符就已经有 3 628 800 种排列了，所以全排列只适合用在很短的字符串上。两种写法的递归深度都是 n 左右，所以栈空间都是 O(n)。

## 小结

| 内容 | 要点 |
| --- | --- |
| 字符 | `char` 占 1 个字节，存的是编号；`'A'` 是 65，`'a'` 是 97，两者相差 32 |
| Unicode | 码点最大是 U+10FFFF，需要 21 位；UTF-8 每个字符占 1 到 4 个字节，`strlen` 数的是字节数 |
| 字符串 | 以 `'\0'` 结尾的字符数组；用双引号初始化会自动补 `'\0'`，数组的大小要比字符数多 1 |
| 漏掉 '\0' | `printf` 和 `strlen` 会一直读到内存里的某个 0 为止，-O0 下读出了相邻数组的内容 |
| 字面量 | `char *p = "..."` 指向只读区，修改会段错误；需要修改时用 `char a[] = "..."` |
| 求长度 | O(n)，从头数到 `'\0'`；不要在循环条件里反复求长度 |
| 大小写 | 先判断是不是字母，再加减 32，否则空格会变成 `'\0'` |
| 数单词 | 数词首，也就是不是空格、并且是第一个字符或前一个字符是空格的位置 |
| 反转 | j 要从最后一个字符开始，`'\0'` 留在原地 |
| 比较 | 比第一个不同字符的编号；前缀更小，大写排在小写前面；非 ASCII 字符要按 `unsigned char` 比较 |
| 回文 | 两个指针往中间比较，最多 ⌊n/2⌋ 次，额外空间 O(1) |
| 找重复 | 两层循环 O(n²)；26 格的计数表 O(n)；一个 int 的 26 位只能判断有没有，不能计数 |
| 变位词 | 先比较长度，再用计数表一加一减，减到负数就不是 |
| 全排列 | 状态空间树加回溯；标记数组的写法要用 `static` 并且写 `T[i] = 0`，交换的写法要换回来 |

回头看这一章，字符串的大部分操作其实都是把上一章的数组操作放到字符数组上再做一遍，比如用两个指针反转、用计数表找重复。真正不同的地方只有两处。一处是字符本身就是数字，所以字符之间可以相减、可以比较大小，也可以直接拿来当表的下标。另一处是字符串靠末尾的 `'\0'` 来标记结束，而不像 Array ADT 那样记录长度，所以求长度要扫描一遍，每个循环都以碰到 `'\0'` 作为结束条件。这一章遇到的几个错误，比如漏掉 `'\0'`、空格被减成 `'\0'`、反转时把 `'\0'` 换到最前面，也都和这个结束标记有关。
