换方向之后的第一门课，从最基础的地方开始。第一章的内容不多——六条命令加上选项的写法——但有一个概念如果第一天没搞清楚，后面会一直别扭：**你敲下去的那串字符，到底是谁在处理？**

这一篇按课程顺序记，但每条命令后面会多问一句「这件事是谁干的」。第一章的知识点看起来零散，其实全都能挂回这条线上。

## 一、终端、Shell 与内核的关系

严格来说是三者协作，而不是简单的两级关系：

```
终端(Terminal) -> Shell(命令解释器) -> 内核(Kernel) -> 硬件/操作系统资源
```

- **终端（Terminal）**：只是一个显示窗口，负责接收键盘输入、显示输出，本身不理解命令的含义。
- **Shell（如 bash、zsh）**：真正「听懂」命令的程序。它解析输入的命令，并把对应的请求通过**系统调用（system call）**交给内核。
- **内核（Kernel）**：操作系统的核心，负责管理 CPU、内存、文件系统、设备等资源，执行 Shell 转达的请求，并把结果返回。

一句话总结：**我们在终端里打字，Shell 负责翻译和调度，内核负责真正干活。**

这个分层不是为了考试才背的。它能直接解释第一章里好几个「看起来是巧合」的现象——下面每一节都会用到它，所以这里先把三者的分工记牢。

## 二、指令的基础形式

```
command -option(s) argument
```

- `command`：要执行的命令名
- `-option(s)`：可选参数，用来改变命令的行为（选项）
- `argument`：命令作用的对象，例如文件名、目录名

这三段是**由 Shell 切开的**，不是由命令自己切开的。Shell 按空格把这行字拆成一个个词，然后把它们作为参数列表交给命令。这就是为什么文件名里有空格会出事——Shell 会老老实实把它拆成两个参数，而命令根本不知道你本来想说的是一个文件。

## 三、今日常用命令

| 命令 | 作用 |
| --- | --- |
| `clear` | 清空当前终端界面显示的记录（不影响历史命令，仍可用 ↑ 键翻出） |
| `date` | 获取并显示当前系统时间 |
| `ncal` | 以日历形式展示当前月份 |
| `echo 内容` | 将输入的内容原样输出到终端（常用于打印文本或变量值） |
| `sort 文件` | 对文件中的内容按行排序后输出（默认按字典序，不会修改原文件） |
| `rm 文件` | 删除指定文件，**默认不可恢复**，使用时需谨慎（可加 `-i` 选项在删除前逐个确认） |

下面几条是记完表格之后，回头对着第一节那张分工图想明白的。

### clear 清掉的是显示，不是历史

`clear` 之后按 ↑ 仍然能翻出刚才的命令——这不是「清得不干净」，而是两件事本来就归不同的东西管：**屏幕上显示什么是终端的事，历史记录是 Shell 的事。** `clear` 只是让终端重画一遍窗口，Shell 那份命令历史它碰都碰不到。

反过来也成立：清历史要用 Shell 自己的机制（`history -c`），`clear` 帮不上忙。

### echo 打印变量时，展开是 Shell 做的

`echo $HOME` 打印出家目录，很容易以为是 `echo` 认识 `$HOME` 这个变量。其实不是：Shell 在把参数交给 `echo` 之前，就已经把 `$HOME` 替换成了具体的路径。`echo` 收到的是一个普通字符串，它自始至终不知道有变量这回事。

这解释了另一个现象：单引号里的 `$HOME` 不会被展开，因为**引号也是 Shell 的语法**，它决定的是「这一段要不要替换」。命令那边看到的永远是替换之后的结果。

### sort 不改原文件，但重定向会

`sort 文件` 只是把排好序的结果打印到屏幕上，原文件一个字节都没动。想保存结果自然会想到重定向：

```bash
sort names.txt > names.txt   # ⚠️ 别这么写，文件会被清空
```

*代码 1：一个会把数据弄丢的写法。*

结果是 `names.txt` 变成空文件，内容全没了。原因还是第一节那张分工图：**重定向是 Shell 干的，不是 `sort` 干的**，而且顺序是 Shell 先动手——它会先以「清空并写入」的方式打开 `names.txt`，然后才启动 `sort`。等 `sort` 开始读的时候，文件已经是空的了。

正确的做法是写去别的文件，或者用 `sort` 自己的 `-o` 选项（它内部处理了这种情况）：

```bash
sort names.txt -o names.txt
```

*代码 2：就地排序的安全写法。*

### rm 没有回收站

`rm` 不是「移到回收站」，是直接把目录项删掉，**默认没有任何确认，也没有撤销**。加 `-i` 会在删除每个文件前问一次：

```bash
rm -i notes.txt
```

*代码 3：删除前逐个确认。*

刚上手的阶段建议养成先 `ls` 看一眼、再 `rm` 的习惯——尤其是在参数里写了通配符的时候。通配符同样是 Shell 展开的：你写 `rm *.txt`，`rm` 收到的其实是 Shell 替你列好的一串具体文件名。所以「到底会删掉哪些」这件事，在 `rm` 启动之前就已经定死了。

## 四、选项的两种写法

### 短选项可以合并

如果一个命令后面要接多个单字符选项，可以不用每个都写 `-` 加空格，直接拼在一起：

```bash
ncal -hA1
```

*代码 4：合并写法。*

等价于 `ncal -h -A 1`，作用是：`-h` 取消高亮显示今天的日期，`-A 1` 额外显示下一个月份（after）。

这里有个容易踩的限制：**能带参数的选项必须放在合并串的最后一个**。`-hA1` 之所以成立，是因为 `A` 排在最后，后面的 `1` 才能被认成它的参数。顺序换成 `-A1h` 意思就完全变了——`1h` 会被整个当成 `-A` 的参数。

### 长选项要用两个短横线

如果想使用某个选项的完整英文名称（而不是单字母缩写），前面要加两个短横线 `--`：

```bash
date -u && date --universal
```

*代码 5：短选项与长选项等价。*

`-u` 和 `--universal` 是同一个选项的短、长两种写法，作用都是以 UTC（协调世界时）显示当前时间。

`&&` 表示前一条命令成功后再执行后一条。「成功」在这里有确切含义：命令退出时会返回一个**退出状态码**，`0` 代表成功，非 `0` 代表出错，`&&` 看的就是这个数字。这个符号同样属于 Shell——它是在两条命令之间做调度，两个 `date` 本身完全不知道对方存在。

顺带记一个以后会用上的：**单独一个 `--` 表示「选项到此为止」**，后面的东西一律当普通参数。这就是删掉一个名叫 `-rf` 的文件的办法（`rm -- -rf`），否则 `rm` 会把它当成选项来解析。

## 小结

第一章真正的收获不是那六条命令，而是**「这件事归谁管」这个问题本身**：

| 现象 | 谁干的 |
| --- | --- |
| 清屏之后历史还在 | 显示归终端，历史归 Shell |
| `$HOME` 变成了路径 | Shell 在调用命令之前就展开好了 |
| `> file` 把文件清空了 | Shell 先清空再启动命令 |
| `*.txt` 变成一串文件名 | Shell 展开，命令收到的是结果 |
| `&&` 决定要不要跑第二条 | Shell 看上一条的退出状态码 |

一整列都是 Shell。所以后面学到某个「命令的行为很奇怪」的时候，第一个该怀疑的往往不是那条命令——而是它在拿到参数之前，Shell 已经替它做过什么。
