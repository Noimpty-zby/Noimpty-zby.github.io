这是换方向之后的第一门课，所以从最基础的地方开始。第一章的内容不多，只有六条命令和选项的写法，但是其中有一个概念，如果一开始没有弄清楚，后面就会一直觉得别扭，那就是：**在终端里敲下去的那一串字符，到底是由谁来处理的？**

## 一、终端、Shell 与内核的关系

严格来说，这是三者之间的协作，而不是简单的两级关系：

```
终端(Terminal) -> Shell(命令解释器) -> 内核(Kernel) -> 硬件/操作系统资源
```

- **终端**（Terminal）只是一个显示窗口，负责接收键盘输入和显示输出，它本身并不理解命令的含义。
- **Shell**（如 bash、zsh）是真正能「听懂」命令的程序。它负责解析输入的命令，再通过**系统调用**（system call）把对应的请求交给内核。
- **内核**（Kernel）是操作系统的核心，负责管理 CPU、内存、文件系统和设备等资源。它执行 Shell 转交过来的请求，再把结果返回。

用一句话总结，就是在终端里打字，由 Shell 负责翻译和调度，由内核负责真正执行。

这种分层并不是为了应付考试才需要记住的。第一章里有好几个看起来像是巧合的现象，都可以直接用它来解释，下面每一节都会用到这一点，所以这里先把三者的分工记牢。

## 二、指令的基础形式

```
command -option(s) argument
```

- `command`：要执行的命令名
- `-option(s)`：可选参数，用来改变命令的行为（选项）
- `argument`：命令作用的对象，例如文件名、目录名

这三部分是**由 Shell 切分开的**，而不是由命令自己切分的。Shell 会按照空格把这一行文字拆成一个个词，然后把它们作为参数列表交给命令。这也就是为什么文件名里带空格时会出问题，因为 Shell 会照常把它拆成两个参数，而命令根本不知道这两个词原本是一个文件名。

## 三、今日常用命令

| 命令 | 作用 |
| --- | --- |
| `clear` | 清空当前终端界面显示的记录（不影响历史命令，仍可用 ↑ 键翻出） |
| `date` | 获取并显示当前系统时间 |
| `ncal` | 以日历形式展示当前月份 |
| `echo 内容` | 将输入的内容原样输出到终端（常用于打印文本或变量值） |
| `sort 文件` | 对文件中的内容按行排序后输出（默认按字典序，不会修改原文件） |
| `rm 文件` | 删除指定文件，**默认不可恢复**，使用时需谨慎（可加 `-i` 选项在删除前逐个确认） |

下面几点，是记完这张表之后，再对照第一节那张分工图想明白的。

### clear 清掉的是显示，不是历史

执行 `clear` 之后，按 ↑ 键仍然能翻出刚才输入的命令。这并不是因为清得不干净，而是因为这两件事本来就由不同的部分负责。屏幕上显示什么，由终端负责；命令的历史记录，则由 Shell 负责。`clear` 只是让终端重新绘制一遍窗口，并不会影响 Shell 保存的那份命令历史。

反过来也是一样。如果要清除历史记录，就要使用 Shell 自己提供的机制（`history -c`），用 `clear` 是做不到的。

### echo 打印变量时，展开是 Shell 做的

执行 `echo $HOME` 会打印出家目录的路径，这很容易让人以为是 `echo` 认识 `$HOME` 这个变量。但实际上并不是这样。Shell 在把参数交给 `echo` 之前，就已经把 `$HOME` 替换成了具体的路径，所以 `echo` 收到的只是一个普通的字符串，它从头到尾都不知道有变量这回事。

这也解释了另一个现象，那就是写在单引号里的 `$HOME` 不会被展开。因为引号同样属于 Shell 的语法，它决定的是某一段内容要不要被替换，而命令看到的永远是替换之后的结果。

### sort 不改原文件，但重定向会

`sort 文件` 只会把排好序的结果打印到屏幕上，原文件一个字节都不会改变。如果想保存排序的结果，自然会想到使用重定向：

```bash
sort names.txt > names.txt   # ⚠️ 别这么写，文件会被清空
```

*代码 1：一个会把数据弄丢的写法。*

结果是 `names.txt` 变成了一个空文件，原来的内容全部丢失了。原因还是要回到第一节那张分工图，**重定向是由 Shell 完成的，而不是由 `sort` 完成的**，而且是 Shell 先动手。Shell 会先以「清空后写入」的方式打开 `names.txt`，然后才启动 `sort`。所以等到 `sort` 开始读取文件时，这个文件已经是空的了。

正确的做法是把结果写到另一个文件里，或者使用 `sort` 自己提供的 `-o` 选项，因为这个选项在内部处理了这种情况：

```bash
sort names.txt -o names.txt
```

*代码 2：就地排序的安全写法。*

### rm 没有回收站

`rm` 并不会把文件移到回收站，而是直接删除对应的目录项。它**默认不会做任何确认，也无法撤销**。如果加上 `-i` 选项，它会在删除每个文件之前询问一次：

```bash
rm -i notes.txt
```

*代码 3：删除前逐个确认。*

在刚开始上手的阶段，最好养成先用 `ls` 看一眼、再执行 `rm` 的习惯，尤其是当参数里用到通配符的时候。通配符同样是由 Shell 展开的。比如写下 `rm *.txt` 时，`rm` 实际收到的是 Shell 已经替它列好的一串具体文件名。所以到底会删掉哪些文件，在 `rm` 启动之前就已经确定了。

## 四、选项的两种写法

### 短选项可以合并

如果一个命令后面要跟多个单字母选项，可以不必每个都写成 `-` 加空格的形式，而是直接把它们拼在一起：

```bash
ncal -hA1
```

*代码 4：合并写法。*

这条命令等价于 `ncal -h -A 1`。其中 `-h` 表示取消对今天日期的高亮显示，`-A 1` 表示额外显示下一个月份（after）。

这里有一个容易出错的限制，那就是**需要带参数的选项必须放在合并串的最后**。`-hA1` 之所以能正常工作，是因为 `A` 排在最后，后面的 `1` 才能被识别成它的参数。如果把顺序改成 `-A1h`，意思就完全变了，因为 `1h` 会整个被当成 `-A` 的参数。

### 长选项要用两个短横线

如果想使用选项的完整英文名称，而不是单字母的缩写，就要在前面加上两个短横线 `--`：

```bash
date -u && date --universal
```

*代码 5：短选项与长选项等价。*

`-u` 和 `--universal` 是同一个选项的短写法和长写法，它们的作用都是以 UTC（协调世界时）显示当前时间。

`&&` 表示前一条命令执行成功之后，再执行后一条命令。这里的「成功」有明确的含义。每条命令退出时都会返回一个**退出状态码**，`0` 表示成功，非 `0` 表示出错，而 `&&` 判断的就是这个数字。这个符号同样属于 Shell，它负责在两条命令之间进行调度，而这两个 `date` 本身完全不知道对方的存在。

另外，顺便记住一个以后会用到的写法：**单独的一个 `--` 表示选项到此结束**，后面的内容都会被当作普通参数。如果要删除一个名叫 `-rf` 的文件，就可以用这种办法（`rm -- -rf`），否则 `rm` 会把它当成选项来解析。

## 小结

第一章真正的收获并不是这六条命令，而是「**这件事由谁负责**」这个问题本身：

| 现象 | 谁干的 |
| --- | --- |
| 清屏之后历史还在 | 显示归终端，历史归 Shell |
| `$HOME` 变成了路径 | Shell 在调用命令之前就展开好了 |
| `> file` 把文件清空了 | Shell 先清空再启动命令 |
| `*.txt` 变成一串文件名 | Shell 展开，命令收到的是结果 |
| `&&` 决定要不要跑第二条 | Shell 看上一条的退出状态码 |

可以看到，右边一整列都是 Shell。所以以后遇到某条命令的行为很奇怪时，首先应该怀疑的往往不是那条命令本身，而是 Shell 在把参数交给它之前，已经替它做了哪些处理。
