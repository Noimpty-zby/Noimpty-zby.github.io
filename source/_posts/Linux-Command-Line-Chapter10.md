[第一章](/2026/08/25/Linux-Command-Line-Chapter1/)提到过，`echo $HOME` 能打印出家目录的路径，`rm *.txt` 能删掉一批文件，但是在这两件事里，真正把 `$HOME` 和 `*.txt` 换成具体内容的都是 Shell，而不是 `echo` 和 `rm`。[第三章](/2026/09/05/Linux-Command-Line-Chapter3/)里的 `~` 也是这样。Shell 在运行命令之前改写命令行的这一步叫作展开（expansion），这一章就把 Bash 的几种展开放在一起，按顺序整理一遍。

为了看清楚展开以后的结果，这一章会大量使用 `echo`。因为 `echo` 会把收到的参数原样打印出来，所以屏幕上显示的内容，就是 Shell 改写之后交给命令的那一行。下面的例子都在同一个练习目录里运行，目录里有这些文件：

```bash
$ ls -A
.secret.txt  contact.html  day10.log  day3.log    notes.txt
about.html   day1.log      day2.log   index.html  style.css
```

*代码 1：练习目录里一共 10 个文件，`-A` 让 `ls` 把以点开头的 .secret.txt 也列了出来。*

## 一、路径名展开：* ? [ ]

先看一个对比。`echo hello` 会原样打印出 hello，但是 `echo *.html` 打印出来的并不是 `*.html`：

```bash
$ echo hello
hello
$ echo *.html
about.html contact.html index.html
```

*代码 2：`echo` 收到的不是 `*.html`，而是三个文件名。*

这是因为 `*` 在 Shell 里是一个通配符。如果 Shell 发现一个单词里有没加引号的 `*`、`?` 或者 `[`，就会把这个单词当成一个模式，到目录里找出名字符合这个模式的文件，再把这个单词换成按字母顺序排好的文件名。所以 `echo` 实际收到了三个参数，它从头到尾都不知道用户输入的是 `*.html`。这种展开叫作路径名展开（pathname expansion），也常被叫作通配（globbing）。它比较的是整个文件名，并不只是扩展名，所以 `*` 可以出现在名字的任何位置。

### 1.1 * 匹配任意长度的字符串

`*` 可以匹配任意长度的字符串，也包括空字符串。所以 `*.html` 的意思是以 .html 结尾的名字，而单独一个 `*` 可以匹配当前目录里的所有名字，目录的名字也包括在内。但是以点开头的隐藏文件是一个例外，`*` 不会匹配到它们：

```bash
$ echo *
about.html contact.html day1.log day10.log day2.log day3.log index.html notes.txt style.css
$ echo *.txt
notes.txt
$ echo .s*
.secret.txt
```

*代码 3：`*` 和 `*.txt` 都没有匹配到 .secret.txt，只有当模式本身以点开头时，隐藏文件才会被匹配到。*

### 1.2 ? 恰好匹配一个字符

`?` 只匹配一个字符，而且必须恰好是一个，不能多也不能少。比如 `day?.log` 只能匹配 day 和 .log 之间有一个字符的名字：

```bash
$ echo day?.log
day1.log day2.log day3.log
$ echo day??.log
day10.log
```

*代码 4：day10.log 在 day 和 .log 之间有两个字符，所以只有 `??` 才能匹配到它。*

### 1.3 [ ] 匹配列出来的某一个字符

方括号同样只匹配一个字符，但是这个字符必须是方括号里列出来的某一个，比如 `[13]` 匹配 1 或者 3。如果要表示一段连续的字符，就在两端之间写一个 `-`，比如 `[1-2]`、`[0-9]`、`[a-z]`。如果方括号里的第一个字符是 `^`，意思就反过来了，变成匹配方括号里没有列出的任意一个字符。在 Bash 里 `[^1]` 和 `[!1]` 的作用相同，其中 `[!1]` 是 POSIX 标准规定的写法，在别的 Shell 里也能用。

```bash
$ echo day[13].log
day1.log day3.log
$ echo day[1-2].log
day1.log day2.log
$ echo day[^1].log
day2.log day3.log
$ echo day[!1].log
day2.log day3.log
```

*代码 5：方括号可以逐个列出字符，可以写一段范围，也可以取反。*

方括号里的每一个字符都算数，逗号也不例外。所以列举字符时不要写成 `[1,2]`，否则名字里带逗号的文件也会被匹配到。[第九章](/2026/10/02/Linux-Command-Line-Chapter9/)介绍过的 `[:digit:]` 这类字符类，在通配符里同样可以使用，但是外面要再套一层方括号，比如 `day[[:digit:]].log` 的效果就和 `day[0-9].log` 相同。

![10 个文件和 5 个模式的匹配表，隐藏文件 .secret.txt 一个模式都没有匹配上](/img/posts/linux-expansion/glob-match.svg)

*图 1：通配符只会和目录里已经存在的名字比较。*

### 1.4 匹配不到时，模式原样保留

如果目录里没有任何文件能和模式匹配，那么 Bash 既不会报错，也不会把这个单词删掉，而是把它原样交给命令：

```bash
$ echo *.png
*.png
$ ls *.png
ls: cannot access '*.png': No such file or directory
```

*代码 6：`ls` 收到的是字面上的 `*.png`，于是去找一个名字就叫 *.png 的文件。*

`echo` 打印出了 `*.png`，看上去好像通配符没有起作用。实际上 Shell 已经找过一遍了，只是一个文件都没有找到，于是就把 `*.png` 留了下来。`ls` 的报错也说明了这一点，因为报错的是 `ls` 而不是 Shell，`ls` 收到的参数就是 `*.png` 这五个字符，所以它会去找一个名字就叫 `*.png` 的文件。

### 1.5 执行之前，先用 echo 看一眼

因为通配符在命令启动之前就已经替换好了，所以在执行 `rm` 这类不能撤销的命令之前，可以先在整条命令的前面加一个 `echo`，看看 Shell 会把它改写成什么样子：

```bash
$ echo rm day?.log
rm day1.log day2.log day3.log
```

*代码 7：加上 `echo` 以后，`rm` 并没有运行，屏幕上显示的是它将会收到的参数。*

## 二、波浪号展开：~

第三章已经介绍过，`~` 会被 Shell 替换成家目录的路径，所以 `cd ~` 能回到家目录，而 `echo ~` 打印出来的是家目录的路径。这里再补充两点。如果 `~` 后面紧跟着一个用户名，那么它会被替换成那个用户的家目录。另外，`~` 只有出现在一个单词的开头时才会被替换，如果写在单词的中间，它就只是一个普通的字符：

```bash
$ echo ~
/home/zby
$ echo ~/notes.txt
/home/zby/notes.txt
$ echo ~root
/root
$ echo a~
a~
```

*代码 8：`~root` 是 root 用户的家目录，`a~` 里的波浪号不在开头，所以没有被替换。*

波浪号展开只是替换文字，并不会检查替换以后的路径是否存在。比如家目录里其实并没有 notes.txt，但是 `echo ~/notes.txt` 照样打印出了完整的路径。这一点和通配符不同，通配符匹配不到文件时是不会凭空写出文件名的。

## 三、花括号展开：{ }

如果在花括号里写几个用逗号隔开的部分，那么 Shell 会把花括号外面的前缀和后缀分别接到每一个部分上，展开成几个单独的单词。这有点像乘法分配律，比如 `x{a,b}y` 会展开成 xay 和 xby。如果一个单词里有两组花括号，那么两组里的部分会两两组合：

```bash
$ echo {a,b,c}.txt
a.txt b.txt c.txt
$ echo x{a,b}y
xay xby
$ echo {a,b}{1,2}
a1 a2 b1 b2
```

*代码 9：展开的结果按照书写的顺序排列，每个部分对应一个单词。*

花括号里也可以写一个序列，格式是 `{起点..终点}` 或者 `{起点..终点..步长}`。起点和终点可以是整数，也可以是单个字母。如果在数字前面补了零，那么展开的结果也会补成同样的宽度：

```bash
$ echo {1..9}
1 2 3 4 5 6 7 8 9
$ echo {1..10..2}
1 3 5 7 9
$ echo {10..1..3}
10 7 4 1
$ echo {a..e}
a b c d e
$ echo {01..10}
01 02 03 04 05 06 07 08 09 10
```

*代码 10：`{1..10..2}` 从 1 开始每次加 2，加到 11 时已经超过了终点，所以结果里没有 10。*

花括号还可以嵌套，这时里面那一组先展开，展开的结果再作为外面那一组的一部分。这在新建一整套目录时很方便，比如下面第一条命令一次就能建好四个目录。和上一节一样，这里先在前面加上 `echo`，看一看展开以后的样子：

```bash
$ echo mkdir -p site/{css,js,img/{icons,photos}}
mkdir -p site/css site/js site/img/icons site/img/photos
$ echo cp notes.txt{,.bak}
cp notes.txt notes.txt.bak
```

*代码 11：第二条命令的花括号里，逗号前面是空的，所以展开成了原来的文件名和加上 .bak 的文件名，正好是备份一个文件时要写的两个参数。*

花括号的写法要求比较严格。花括号里至少要有一个逗号，或者是一个完整的序列，否则 Bash 不会展开它。逗号后面也不能加空格，因为空格会把这个单词拆成两个，于是每一半里的花括号都不完整了。另外，写在引号里的花括号同样不会展开：

```bash
$ echo {a}
{a}
$ echo {a, b}
{a, b}
$ echo "{a,b}"
{a,b}
```

*代码 12：这三种写法都没有展开，花括号被原样打印了出来。*

### 3.1 花括号负责生成，方括号负责匹配

`day{1..5}.log` 和 `day[1-5].log` 看起来很像，但是两者的工作方式完全不同。花括号展开只是按照写法生成文字，并不关心目录里有什么文件；而方括号属于路径名展开，它只会从已经存在的文件里挑出符合模式的名字：

```bash
$ echo day{1..5}.log
day1.log day2.log day3.log day4.log day5.log
$ echo day[1-5].log
day1.log day2.log day3.log
```

*代码 13：目录里并没有 day4.log 和 day5.log，但是花括号照样把它们写了出来。*

这个区别在新建文件时最明显。`touch day{4..6}.log` 会新建 day4.log、day5.log 和 day6.log 三个文件。但是如果写成 `touch day[4-6].log`，因为目录里一个文件都匹配不到，模式会被原样交给 `touch`，于是目录里多出了一个名字就叫 day[4-6].log 的文件：

```bash
$ touch day[4-6].log
$ ls
 about.html     day1.log    day2.log  'day[4-6].log'   notes.txt
 contact.html   day10.log   day3.log   index.html      style.css
```

*代码 14：`ls` 给这个名字加上了引号，提醒它里面含有 Shell 的特殊字符。*

![上面一行 day{1..5}.log 生成了 5 个名字，下面一行 day[1-5].log 只匹配到存在的 3 个](/img/posts/linux-expansion/brace-vs-bracket.svg)

*图 2：花括号展开不看目录，路径名展开只看目录。*

所以如果要批量新建文件或者目录，应该用花括号；如果要处理一批已经存在的文件，才用通配符。

## 四、算术展开：$(( ))

如果把一个算式写在 `$((` 和 `))` 之间，那么 Shell 会先算出结果，再用结果替换掉整个算式。前面的 `$` 和两层括号都不能少，如果直接写 `echo 10+7`，那么 `10+7` 只是一段普通的文字：

```bash
$ echo $((10+7))
17
$ echo 10+7
10+7
$ echo $((10-7)) $((10*7)) $((10/7)) $((10%7)) $((10**7))
3 70 1 3 10000000
```

*代码 15：`%` 是取余数，`**` 是乘方，所以最后一个结果是 10 的 7 次方。*

运算的优先级和数学里一样，先算乘除，再算加减，也可以用括号改变顺序，比如 `$((2+3*4))` 的结果是 14，而 `$(((2+3)*4))` 的结果是 20。

这里最容易出错的是除法。Bash 的算术展开只支持整数，所以 `/` 做的是整数除法，小数部分会被直接舍去。如果算式里出现了小数，Bash 会报语法错误，除数是 0 的时候也会报错：

```bash
$ echo $((10/3))
3
$ echo $((10/3.0))
bash: 10/3.0: syntax error: invalid arithmetic operator (error token is ".0")
$ echo $((10/0))
bash: 10/0: division by 0 (error token is "0")
```

*代码 16：10 除以 3 得到的是 3，而不是 3.33。*

另外，`$(( ))` 里的 `*` 是乘号，不会被当成通配符，所以 `*` 的两边加不加空格都可以。但是如果把乘法直接写在 `echo` 的后面，那么 `*` 就会被展开成文件名：

```bash
$ echo $(( 10 * 7 ))
70
$ echo 10 * 7
10 about.html contact.html day1.log day10.log day2.log day3.log index.html notes.txt style.css 7
```

*代码 17：第二条命令里的 `*` 被换成了当前目录里的所有文件名。*

还要注意不能少写一层括号。`$(10+7)` 只有一层括号，它是下一节要讲的命令替换，这时 Shell 会把 `10+7` 当成一条命令去运行，结果自然是找不到这条命令：

```bash
$ echo $(10+7)
10+7: command not found

```

*代码 18：报错来自命令替换，`echo` 收到的内容是空的，所以只打印了一个空行。*

## 五、命令替换：$( ) 和反引号

如果把一条命令写在 `$(` 和 `)` 之间，那么 Shell 会先运行这条命令，再用它输出的内容替换掉这一整段。比如 `date +%F` 会输出今天的日期，把它放进命令替换里，就可以用日期给目录命名：

```bash
$ echo $(date +%F)
2026-10-04
$ mkdir backup-$(date +%F)
$ ls -d backup*
backup-2026-10-04
```

*代码 19：`mkdir` 收到的参数是 backup-2026-10-04，它并不知道这个名字里有一部分来自 `date`。*

反引号是命令替换更早的写法，`` `date` `` 和 `$(date)` 的作用相同。但是反引号不方便嵌套，如果要在里面再套一层命令替换，里面那层反引号就要用反斜杠转义，而 `$( )` 直接套起来就可以了。所以现在一般推荐使用 `$( )`：

```bash
$ echo $(basename $(pwd))
lab
$ echo `basename \`pwd\``
lab
```

*代码 20：`pwd` 输出当前目录的完整路径，`basename` 只取路径的最后一段，两种写法的结果相同。*

命令替换和第九章的管道都能把一条命令的输出交给另一条命令，但是交过去的位置不一样。管道把输出接到后一条命令的标准输入上，而命令替换把输出写进了命令行，让它成为后一条命令的参数。第九章说过，`ls` 只看参数，从来不读标准输入，所以用管道是没办法把一个路径交给 `ls` 的。这时就可以用命令替换，比如想查看 `ls` 这个程序文件本身的详细信息，就可以把 `which ls` 的输出作为 `ls -l` 的参数：

```bash
$ ls -l $(which ls)
-rwxr-xr-x 1 root root 138216 Aug 25 23:12 /usr/bin/ls
```

*代码 21：`which ls` 输出了 /usr/bin/ls，这个路径成为了 `ls -l` 的参数。*

## 六、引号：决定哪些展开会发生

### 6.1 不加引号时，Shell 会按空格拆分单词

```bash
$ echo hello     world
hello world
$ echo "hello     world"
hello     world
```

*代码 22：不加引号时，hello 和 world 之间的五个空格只剩下了一个。*

Shell 会按照空格把一行命令拆成一个个单词（word），每个单词就是一个参数。所以在第一条命令里，`echo` 收到的是 hello 和 world 两个参数，至于它们之间原来有几个空格，`echo` 并不知道，它只是在两个参数之间补上一个空格再打印出来。加上双引号以后，引号里的内容是一个完整的单词，空格也是这个单词的一部分，所以会被原样保留下来。

### 6.2 双引号和单引号的区别

双引号除了能保留空格，还会让通配符、波浪号和花括号都失去特殊的含义。但是 `$` 和反引号在双引号里仍然有效，所以算术展开和命令替换照样会发生。单引号则更彻底，单引号里的所有字符都按字面意思处理，任何展开都不会发生：

```bash
$ echo "*.html ~ {1..3} $((10+7)) $(date +%F)"
*.html ~ {1..3} 17 2026-10-04
$ echo '*.html ~ {1..3} $((10+7)) $(date +%F)'
*.html ~ {1..3} $((10+7)) $(date +%F)
```

*代码 23：双引号里只有以 `$` 开头的两段被展开了，单引号里一段都没有展开。*

把这一章的几种展开和两种引号放在一起，就是下面这张表：

| 会不会展开 | 不加引号 | 双引号 | 单引号 |
| --- | --- | --- | --- |
| `*`、`?`、`[…]` | 会 | 不会 | 不会 |
| `~` | 会 | 不会 | 不会 |
| `{a,b}`、`{1..3}` | 会 | 不会 | 不会 |
| `$(( ))` | 会 | 会 | 不会 |
| `$( )` 和反引号 | 会 | 会 | 不会 |
| 按空格拆分单词 | 会 | 不会 | 不会 |

如果只是想让某一个字符不被展开，也可以在它的前面加一个反斜杠，比如 `echo \*.html` 打印出来的就是 `*.html`。

### 6.3 双引号里的 $

因为 `$` 在双引号里仍然有特殊的含义，所以如果双引号里的文字碰巧带有 `$`，就可能被替换掉。比如下面这个价格：

```bash
$ echo "price: $100"
price: 00
$ echo 'price: $100'
price: $100
$ echo "price: \$100"
price: $100
```

*代码 24：双引号里的 `$1` 被当成了一个变量，它的值是空的，于是只剩下了后面的 00。*

`$1` 在 Shell 里表示第一个位置参数，写脚本的时候会用到。在终端里直接输入命令时，它的值是空的，所以 `$100` 只剩下了 `00`。遇到这种情况，就要改用单引号，或者在 `$` 的前面加一个反斜杠。

### 6.4 命令替换的结果也会被拆分

6.1 节的拆分不只发生在用户输入的空格上。如果命令替换的外面没有加双引号，那么它输出的内容也会再按空格和换行拆一遍，多个空格因此会变成一个，多行的输出也会被拼成一行。比如今天是 10 月 4 日，所以 `date` 的输出里 Oct 和 4 之间有两个空格：

```bash
$ echo "$(date)"
Sun Oct  4 19:17:21 CST 2026
$ echo $(date)
Sun Oct 4 19:17:22 CST 2026
```

*代码 25：没有加双引号时，Oct 和 4 之间的两个空格变成了一个。*

所以使用命令替换时，外面最好加上双引号，这样它的结果才会作为一个完整的参数，原样交给命令。

## 七、展开的顺序

一行命令里可以同时出现好几种展开，这时 Bash 会按照固定的顺序处理它们。`man bash` 的 EXPANSION 一节规定的顺序是这样的：

1. 花括号展开；
2. 波浪号展开、变量展开、算术展开和命令替换，这四种在同一步里按从左往右的顺序进行；
3. 按空格拆分单词；
4. 路径名展开；
5. 去掉引号。

下面这条命令把这五步都走了一遍，图 3 画出了每一步处理完以后的样子：

```bash
$ echo '*' day{1..2}.log $(echo a b) ~ *.html
* day1.log day2.log a b /home/zby about.html contact.html index.html
```

*代码 26：加了引号的 `*` 原样输出，而没加引号的 `*.html` 被换成了文件名。*

![一条命令依次经过花括号展开、波浪号和命令替换、拆分单词、路径名展开、去掉引号，参数从 6 个变成 10 个](/img/posts/linux-expansion/expansion-order.svg)

*图 3：只有花括号展开、拆分单词和路径名展开会让参数变多，其他几种展开都是把一个单词换成一个单词。*

这个顺序可以解释几个看起来奇怪的现象。因为花括号展开排在第一步，这时候算术展开还没有做，所以 `{1..$((1+2))}` 里的终点还不是一个数字，花括号也就不会展开。而路径名展开排在命令替换的后面，所以命令替换输出的 `*.html` 如果外面没有双引号，就会被再展开一次，变成文件名：

```bash
$ echo {1..$((1+2))}
{1..3}
$ echo $(echo '*.html')
about.html contact.html index.html
$ echo "$(echo '*.html')"
*.html
```

*代码 27：第一条命令里的花括号没有展开；第二条命令里的通配符来自命令替换的输出，也照样被展开了。*

最后一步是去掉引号，这说明引号只是写给 Shell 看的。Shell 根据引号决定哪些展开不做，做完以后就把引号删掉，所以命令收到的参数里并没有引号。这也是 `echo "a" 'b' c` 打印出来的是 `a b c` 的原因。

如果想直接看到 Shell 改写以后的整行命令，除了在前面加 `echo`，还可以先执行 `set -x`。这样之后的每条命令在运行之前，Bash 都会先打印一行以 `+` 开头的、展开以后的命令，用 `set +x` 就可以关掉它。

## 小结

| 名称 | 写法 | 要点 |
| --- | --- | --- |
| 路径名展开 | `*` `?` `[…]` | 只匹配已经存在的文件，不匹配隐藏文件；匹配不到时原样保留 |
| 波浪号展开 | `~` | 只在单词的开头替换，不检查路径是否存在 |
| 花括号展开 | `{a,b}` `{1..9}` | 按写法生成，不看目录；里面要有逗号或者完整的序列 |
| 算术展开 | `$(( ))` | 只算整数，除法会舍去小数部分 |
| 命令替换 | `$( )` | 用命令的输出替换这一段，不加双引号时结果会被拆分 |
| 双引号 | `"…"` | 保留空格，只有 `$` 和反引号的展开还会发生 |
| 单引号 | `'…'` | 所有字符都按字面意思处理 |

这一章的几种展开都发生在命令启动之前。Shell 先按照固定的顺序把整行命令改写好，然后才去运行命令，所以命令收到的永远是改写以后的参数。因此，如果一条命令的结果和预想的不一样，那么可以先在前面加上 `echo`，或者打开 `set -x`，看清楚 Shell 到底把它改写成了什么。至于哪些内容交给 Shell 展开、哪些内容原样保留，则由引号来决定。不需要任何展开的文字可以放进单引号，需要用到 `$` 的文字则放进双引号。
