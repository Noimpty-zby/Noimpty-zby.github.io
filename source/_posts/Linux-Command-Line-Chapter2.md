第二章讲的是怎么自己查文档。课程里介绍了 `man`、`type`、`which`、`help` 这四条命令，它们看起来是四个查文档的小工具，好像随便挑一个能用的就行。

但是试过几次之后就会发现，它们并不能相互替代。`man cd` 查不到内容，`which cd` 也什么都不返回，`help ls` 同样会报错。**这四条命令各自有自己能查到和查不到的范围，而这个范围取决于所查的那个名字到底是什么东西。**

所以这一篇的顺序和课程正好相反，先讲 `man` 怎么读，再讲 `man` 查不到的时候应该怎么办。后面这一部分，正好可以接着 [第一章](/2026/08/25/Linux-Command-Line-Chapter1/) 的那张分工图往下讲。

## 一、man：内容归 man 管，翻页归另一个程序管

`man` 是 manual pages（使用手册）的缩写，用法是在后面跟上一个命令名：

```bash
man ls
```

*代码 1：打开 `ls` 的手册。*

按下回车之后，整个终端都会被手册占满。这时键盘输入的不再是命令，而是在操作一个**翻页器**。常用的按键有下面这些：

| 键 | 作用 |
| --- | --- |
| `q` | quit，退出手册回到命令行 |
| `f` / `空格` | forward，向后翻一屏 |
| `b` | back，向前翻一屏 |
| `↑` / `↓` | 一次滚一行 |
| `g` / `G` | 跳到手册开头 / 结尾 |
| `/内容` | 向后搜索，回车确认 |
| `n` / `N` | 跳到下一个 / 上一个搜索结果 |
| `h` | help，列出翻页器自己的按键说明 |

最后那个 `h` 最容易被误解。它显示的并不是这条命令有哪些选项，而是翻页器自己有哪些按键。里面讲的搜索、跳转、标记，全都是关于翻页这件事的说明，和 `ls` 没有任何关系。

这个区别并不只是容易记混而已，它其实是第一章那张分工图的又一个例子。`man` 本身只负责**找到并格式化**那份文档，而把内容一屏一屏地显示出来、响应按键的，是另一个叫作 **`less`** 的程序。这一点在 `man --help` 里可以直接看到，它有一个 `-P, --pager=PAGER` 选项，下一行 `-r, --prompt` 的说明里也写着 the `less` pager，这说明翻页器是一个可以替换的外部程序。因为是两个程序串联在一起工作，所以按键的说明和手册的内容也是两份不同的东西。

这还带来了一个附带的好处，那就是 `less` 的这套按键在别的地方也能使用。以后遇到 `git log`、`less 大文件` 这类会占满整个屏幕的情况，翻页的按键是完全一样的，因为背后用的是同一个程序。

## 二、SYNOPSIS 那一串方括号怎么读

打开手册之后，最先看到的是 SYNOPSIS（概述）部分，它的样子是这样的：

```
NAME
       ls - list directory contents

SYNOPSIS
       ls [OPTION]... [FILE]...
```

*代码 2：`ls` 手册的开头两段。*

这一段是整份手册里信息最集中的地方，它只用一行就写出了这条命令的所有合法写法。读懂它只需要下面几条规则：

| 写法 | 含义 |
| --- | --- |
| `[ ]` | 方括号里的东西**可省略** |
| `...` | 前面那个东西可以**重复出现多次** |
| `\|` | 竖线两边**二选一** |
| 加粗的字 | **原样照抄**，一个字符都不能改 |
| 斜体 / 下划线的字 | **占位符**，要换成你自己的东西 |

所以 `ls [OPTION]... [FILE]...` 的意思是，`ls` 这两个字母必须照写；后面可以跟任意多个选项，也可以一个都不跟；再后面可以跟任意多个文件名，同样也可以一个都不跟。这也正好解释了为什么 `ls`、`ls -l`、`ls -l a.txt b.txt` 这三种写法都是合法的。

手册后面的几个部分，也有必要知道它们分别写了什么，否则很容易从头读到尾：

- **DESCRIPTION**：详细的说明，选项清单通常也在这里。
- **EXAMPLES**：使用示例。如果有这一部分，最好优先看它，这比读 DESCRIPTION 快得多。
- **EXIT STATUS**：退出状态码的含义，写脚本需要判断命令是否成功时会查到这里。
- **SEE ALSO**：相关的命令，可以从这里继续往下查。

实际使用时，最高效的方法是打开手册后直接输入 `/-l` 搜索那个选项，看完就按 `q` 退出。手册是用来查的，并不是用来从头读到尾的。

## 三、8 个章节：同一个名字可能是好几样东西

手册一共分成 8 个部分（section），平时查命令时用到的用户命令（user commands）只是其中的第一部分：

| 章节 | 内容 |
| --- | --- |
| 1 | 用户命令（平时敲的那些） |
| 2 | 系统调用（内核提供的接口） |
| 3 | 库函数（C 标准库这类） |
| 4 | 特殊文件与设备（`/dev` 下面的东西） |
| 5 | 文件格式与约定（配置文件长什么样） |
| 6 | 游戏 |
| 7 | 杂项与综述 |
| 8 | 系统管理命令（一般要 root） |

之所以要分章节，并不是为了整理得好看，而是因为**同一个名字在不同的层次上，确实可能是不同的东西**。最典型的例子是 `passwd`，它既是一条修改密码的命令（第 1 章），又是 `/etc/passwd` 这个文件的格式说明（第 5 章）。如果直接执行 `man passwd`，只会显示最先找到的那一份，也就是第 1 章的那条命令。

要指定章节，就把章节编号写在名字前面：

```bash
man 5 passwd      # 只看第 5 章：/etc/passwd 的文件格式
man -a passwd     # 所有章节挨个看，q 一次跳到下一个
man -k passwd     # 按关键词搜：所有简介里提到 passwd 的手册页
```

*代码 3：三条容易记混的写法。*

这三条命令很容易混在一起，但它们的区别其实很清楚：

- **`man 5 名字`**：已经知道要看哪一章，就直接去那一章。
- **`man -a 名字`**：不知道有几章，就把所有章节都看一遍。`-a` 是 all 的意思。
- **`man -k 关键词`**：连命令叫什么都不知道，就让它去搜索。

第三条最值得单独说明，因为它和前两条完全不是一回事。`-k` 并不是用来查看某个命令的全部信息，而是拿关键词去搜索所有手册页的名字和一句话简介（它等价于另一条叫作 `apropos` 的命令）。所以它的用途正好反过来，适用的情况不是「知道命令名，想看它怎么用」，而是「**知道自己想做什么，但不知道该用哪条命令**」：

```bash
man -k "list directory"
# ls (1)  - list directory contents
# dir (1) - list directory contents
```

*代码 4：`-k` 是根据想做的事情，反过来查找应该用的命令。*

这里有一个容易遇到的问题。`man -k` 搜索的并不是手册本身，而是一个事先建好的索引数据库。所以在新安装的系统上，或者刚安装完某个软件之后，可能会得到 `nothing appropriate` 的提示。这并不是真的没有相关的手册，而是索引还没有建立，执行一次 `sudo mandb` 重建索引就可以了。

## 四、man 查不到的时候：先搞清这个名字是什么

到这里为止，一切都很顺利，直到执行了下面这条命令：

```bash
man cd
# No manual entry for cd
```

*代码 5：查不到。*

第一反应可能是文档没有装全，但真正的原因要有意思得多：**`cd` 根本就不是一个程序，所以它没有自己的手册页。**

回到第一章那张图，命令其实分为两种。一种是磁盘上真实存在的可执行文件，比如 `ls` 对应的就是 `/usr/bin/ls` 这个文件，Shell 找到它之后，会启动一个新的进程来运行它。另一种叫作 **Shell 内建命令（builtin）**，它是 Shell 这个程序自身带有的功能，不需要启动任何新的进程。

`cd` 必须属于后一种，而且也只能属于后一种。原因在于，`cd` 要改变的是当前工作目录，而这个状态保存在 Shell 自己身上。假如 `cd` 是一个独立的程序，那么 Shell 启动它之后，它改变的只是自己这个新进程的工作目录；等它一退出，一切又恢复了原样，结果就是一条执行之后没有任何效果的命令。所以 `cd` 不可能做成一个独立的程序，它必须由 Shell 亲自执行。

这一节要讲的三条命令，回答的就是「这个名字属于哪一种」。

### type：最该先敲的那条

`type` 会直接告诉你，这个名字会被当作什么东西来处理：

```bash
type cd
# cd is a shell builtin

type man
# man is /usr/bin/man

type ls
# ls is aliased to `ls --color=auto'
```

*代码 6：三种不同的答案。*

它给出的结果有四类，分别是**别名（alias）、Shell 内建命令（builtin）、函数（function）和外部程序（会给出完整路径）**。这四类正好对应四种不同的查文档方式，下面小结里的那张表就是按照这个分类排列的。

第三行的结果还顺便解开了一个疑问。很多系统上 `ls` 的输出是彩色的，可是手册里根本没有提到默认会显示颜色，这是为什么呢？原因是敲下的 `ls` 早就被替换成了 `ls --color=auto`。别名替换是 Shell 在调用命令之前完成的，这和第一章里 `$HOME` 的展开属于同一类事情。

`type` 还有一个 `-a` 选项，它会把所有同名的东西全部列出来：

```bash
type -a echo
# echo is a shell builtin
# echo is /usr/bin/echo
```

*代码 7：同一个名字，两个不同的东西。*

（有的系统上还会多出一行 `/bin/echo`。这并不是第三个 echo，只是因为 `/bin` 本身是指向 `/usr/bin` 的软链接，所以同一个文件被列出了两次。）

`echo` 同时以内建命令和外部程序两种形式存在，而且内建命令的优先级更高。这就带来了一件很违反直觉的事情：`man echo` 打开的是 `/usr/bin/echo` 的手册，但是敲下 `echo` 时，实际运行的却是 Shell 内建的那个。这两者在绝大多数情况下行为一致，但是支持的选项确实有些差别。所以当手册上写的和实际运行的结果对不上时，应该先用 `type -a` 看一下，是不是查错了对象。

### which：只认磁盘上的文件

`which` 的作用是**告诉你某个程序的可执行文件在哪里**：

```bash
which man
# /usr/bin/man

which cd
#（什么都没有）
```

*代码 8：`which` 对内建命令无能为力。*

`which` 查不到 `cd` 并不是一个 bug。`which` 的做法是拿着这个名字，到 `PATH` 里列出的那几个目录中逐个查找同名的文件，而 `cd` 在磁盘上根本没有对应的文件，自然也就找不到。

更根本的原因在于，`which` 自己就是一个外部程序。它是由 Shell 启动的另一个进程，处在 Shell 的外部，所以看不到 Shell 内部的别名、函数和内建命令。而 `type` 是 Shell 的内建命令，它是从 Shell 内部去查看的，所以 `type` 知道的信息总是比 `which` 多。因此只要能用 `type`，就不要用 `which`。

### help：内建命令的说明书

内建命令虽然没有 man 手册，但这并不代表它们没有文档。要查看它们的文档，需要使用 Shell 自己提供的 `help` 命令：

```bash
help cd
# cd: cd [-L|[-P [-e]] [-@]] [dir]
#     Change the shell working directory.
#     ...
```

*代码 9：内建命令的文档由 Shell 提供。*

需要注意，`help` 和 `--help` 只是长得像，实际上是两样完全不同的东西：

- **`help 名字`**：这是一条独立的命令（它本身也是内建命令），只负责显示 Shell 内建命令的文档。所以 `help ls` 会报错，因为 `ls` 不是内建命令。
- **`命令 --help`**：这是传给那个程序的一个**选项**，由程序自己打印一段简介。至于能不能用，要看程序的作者有没有实现它。

所以要查看外部程序的简要文档，就用 `ls --help`；要查看内建命令的文档，就用 `help cd`，两种方式不能混用。

## 小结

把这一章的四条命令按照「名字是什么东西」重新排列一遍，就得到了下面这张查询表：

| `type` 说它是 | 例子 | 该用什么查 |
| --- | --- | --- |
| 别名 alias | `ls` | `type` 就能看到它被换成了什么 |
| Shell 内建 builtin | `cd` / `echo` / `pwd` | `help 名字` |
| 函数 function | 自己或配置文件里定义的 | `type 名字` 会直接打出定义 |
| 外部程序（一个路径） | `man` / `sort` | `man 名字`，或者 `名字 --help` |

所以正确的顺序应该是，**先用 `type` 弄清楚这个名字是什么，再决定用哪种方式查文档。** 一上来就用 `man` 之所以大多数时候都能成功，只是因为大部分命令恰好都是外部程序，一旦遇到那几个内建命令，就会莫名其妙地查不到。

回头来看，第一章的结论是「一件事由谁负责」，而这一章其实是把同样的问题换了一种问法，变成了「一个名字由谁负责」。`cd` 由 Shell 负责，`ls` 对应磁盘上的那个文件，而 `echo` 在两边各有一份。如果弄不清名字的归属，就查不到对应的文档，这和文档写得全不全并没有关系。
