这一章进文件系统，讲的是怎么在目录之间走动（navigation），以及怎么创建文件和文件夹。

命令本身不多，`pwd` / `ls` / `cd` / `touch` / `mkdir` 加一个 `file`。但这一章有一个第一次接触时很难自己想到的前提：**整个 Linux 系统只有一棵目录树，没有 C 盘 D 盘。** 想不通这件事，`/` 和 `~` 这两个符号就会一直是「要背下来的写法」，而不是「指路的起点」。

另外这几条命令在 [Git 第零章](/2026/09/05/Git-Chapter0-Command-Line/) 那篇里按 Git 课的取舍已经过了一遍——「当前工作目录是每条命令的隐含参数」那条线那边写过了，这里不重复。这一篇往下挖两层：**路径到底是怎么表达位置的**，以及 **`ls -l` 那一行密密麻麻的东西各自是什么。**

## 一、只有一棵树，树根是 `/`

先纠正一个我自己在笔记里写错的地方：根目录是 `/`，这是**正斜杠**，不是反斜杠。这个区分在别处不重要，在 Shell 里很重要——**反斜杠 `\` 在 Shell 里是转义符**，是完全另一件东西（它的作用是「后面这个字符别按特殊含义解释」，比如 `cd my\ folder` 里那个空格）。两个符号一个是路径分隔符，一个是转义符，写混了错得很彻底。

Windows 的思路是每块盘一棵树：`C:\`、`D:\` 各自独立，互相之间没有上下级关系。Linux 不是这样——**整个系统只有一棵树，树根就是 `/`**。插进来的 U 盘、第二块硬盘、网络存储，都不会长出新的树根，而是被「挂载」到这棵树的某个目录上（通常在 `/media` 或 `/mnt` 底下），从此就是这棵树的一根枝。

所以任何一个文件，都能从 `/` 出发用一条唯一的路径写到。看看根下面有什么：

```bash
ls /
# bin  boot  dev  etc  home  lib  media  mnt  opt  proc  root  run  sbin  srv  sys  tmp  usr  var
```

*代码 1：树根下面这一层。*

这些目录名是有约定的，不是各家发行版随便起的。常打交道的几个：

| 目录 | 装的是什么 |
| --- | --- |
| `/home` | 所有普通用户的家目录，我的在 `/home/zby` |
| `/etc` | 系统和软件的配置文件，几乎全是纯文本 |
| `/usr` | 绝大多数软件本体，`/usr/bin` 里就是那些命令的可执行文件 |
| `/bin` | 基础命令。现代发行版上它已经是指向 `/usr/bin` 的符号链接了 |
| `/var` | 会不断变大的东西：日志（`/var/log`）、缓存、队列 |
| `/tmp` | 临时文件，重启后一般会被清空 |
| `/dev` | 设备，硬盘、终端这些在这里都表现成「文件」 |
| `/proc` | 内核和进程的实时状态，不是真实存在于磁盘上的文件 |
| `/root` | **root 用户的家目录** |

最后一行要单独拎出来说：**`/root` 不是根目录。** 根目录是 `/`，`/root` 只是超级用户 root 那个人的家目录，地位跟 `/home/zby` 完全一样，只是它没放在 `/home` 底下。名字撞车而已，两者没有任何关系。

如果想用图形界面看一眼根目录里都有什么：

```bash
xdg-open /
```

*代码 2：把「这个位置」交给图形界面打开。*

这条命令各平台不一样（macOS 是 `open`，WSL 是 `explorer.exe`），[Git 第零章](/2026/09/05/Git-Chapter0-Command-Line/) 里有一张对照表。它没什么魔法，只是把一个路径递给文件管理器——刚上手的时候拿它对照着 `ls` 看，比光看命令输出更容易在脑子里把树建起来。

## 二、家目录与 `~`：第二个起点

家目录是这棵树上属于你自己的那一块，一般在 `/home/用户名` 下面。它的特殊之处不只是「东西都放这儿」，而是**它基本上是普通用户唯一能随便写的地方**——树上大部分位置（`/etc`、`/usr`、`/var`）都需要 root 权限才能改。所以「文档、配置、项目全在家目录里」不是习惯问题，是权限决定的。

因为太常用，它有一个专门的简写符号 `~`：

```bash
cd ~/projects        # 等于 cd /home/zby/projects
echo ~               # /home/zby
cd                   # 不带参数也是回家
```

*代码 3：`~` 的三种用法。*

这里有个当时想当然了的地方：**`~` 不是「一个特殊的目录名」，它是 Shell 在启动命令之前替换掉的。** 跟第一章里 `$HOME` 那一节是同一回事——命令收到的参数从来都是 `/home/zby/projects` 这条完整路径，它压根不知道你打的是波浪号。

验证也很简单，用第一章那个办法：套上单引号，替换就不发生了。

```bash
echo ~        # /home/zby   —— Shell 替换了
echo '~'      # ~           —— 引号里的东西原样交给命令
```

*代码 4：引号是 Shell 的语法，所以它能拦住替换。*

这也解释了一个偶尔会撞上的现象：某些配置文件里写 `~/xxx` 是不生效的。因为那份配置不是 Shell 读的，没有人替它做这个替换，`~` 就真的会被当成一个叫「~」的目录名去找。**要保险就写完整路径。**

## 三、pwd / ls / cd：在树上问路和走路

这三条 [Git 第零章](/2026/09/05/Git-Chapter0-Command-Line/) 里写过了，这里只补一句最该记住的：**它们的差别是「问」「看」「走」**——`pwd` 问我在哪，`ls` 看那边有什么（人不动），`cd` 才真的换位置。

在这一章的框架下，只需要再加一层理解：**路径有两种写法，区别只在于从哪个节点起步。**

```bash
cd /home/zby/projects/linux-study    # 绝对路径：从树根 / 起步
cd projects/linux-study              # 相对路径：从我现在站的地方起步
cd ..                                # 相对路径：向上一层
```

*代码 5：前两行是同一个目的地的两种写法，第三行是相对路径的另一种用法。*

**以 `/` 开头的就是绝对路径**，它从树根出发，在哪儿敲结果都一样；不以 `/` 开头的就是相对路径，含义取决于 `pwd` 的当前值，换个地方敲会到完全不同的地方。`..` 能回退不是因为 `cd` 认识这个咒语，而是因为每个目录里真的有一个叫 `..` 的条目指向上一层——这一点下一节还会再用到一次。

## 四、`ls -l`：那一行到底在说什么

`ls` 默认只给名字。`-l`（long）会把每一项摊开成一行，`-a`（all）会连以点开头的隐藏文件一起列出来，两个常一起用：

```bash
ls -la
```

*代码 6：出现频率最高的组合。*

`-l` 那一行信息量很大，拆开看是八段：

```
-rw-r--r-- 1 zby zby 1380 Sep  5 19:24 daily-learning2.md
```

*代码 7：一个普通文件的一行。*

| 段 | 这一行里的值 | 含义 |
| --- | --- | --- |
| 类型位 | `-` | `-` 普通文件，`d` 目录，`l` 符号链接 |
| 权限九位 | `rw-r--r--` | 属主 / 属组 / 其他人各三位，读写执行 |
| 硬链接数 | `1` | 有几个名字指向这份数据 |
| 属主 | `zby` | 这个文件属于谁 |
| 属组 | `zby` | 属于哪个用户组 |
| 大小 | `1380` | **字节数**，不是 KB |
| 时间 | `Sep  5 19:24` | 最后一次**修改内容**的时间 |
| 名字 | `daily-learning2.md` | 文件名 |

有三个地方我笔记里记错或者记漏了，值得单独写下来。

**第一，那一列不是「创建人」，是属主（owner）。** Linux 根本不记录文件是谁创建的——这个信息从来没被保存过。它记的是「现在归谁」，而这是可以被改的（`chown`），改完之后原来那个人的痕迹一点都不剩。所以看到一个文件属于 `zby`，只能说明它现在归 `zby`，不能推出是他建的。

**第二，时间是「最后修改内容」的时间，而且文件其实有三个时间。**

| 时间 | 什么时候变 | 怎么看 |
| --- | --- | --- |
| mtime（modify） | 内容被改的时候 | `ls -l`（默认） |
| atime（access） | 内容被读的时候 | `ls -lu` |
| ctime（change） | 元数据被改的时候（改名、改权限、换属主） | `ls -lc` |

`ls -l` 默认给的是 mtime。所以「改了个文件名」这种操作不会让 `ls -l` 的时间变——变的是看不见的那个 ctime。

**第三，目录那一行的两个数字都不是字面意思。** 拿一个目录的行来看：

```
drwxr-xr-x 3 zby zby 4096 Sep  5 21:45 a
```

*代码 8：一个目录的一行。*

- **`4096` 不是里面所有东西加起来的大小**，而是这个目录本身那张「名字 → 数据」的表占的空间。想看里面到底占了多少得用 `du -sh 目录名`。
- **`3` 这个硬链接数也有讲法。** 一个刚建的空目录这个数字是 2：一个来自它在上一层里的名字，一个来自它自己里面那个 `.`。之后每多一个子目录就加一——因为那个子目录里的 `..` 又指回了它。所以这里的 `3` 意味着 `a` 里面有 1 个子目录。上一节说的「`.` 和 `..` 是真实存在的条目」，这就是它留下的痕迹。

顺便两个常用的：`-h`（human-readable）把字节数换成 `1.4K`、`12M` 这种；`-A` 跟 `-a`几乎一样，但不列 `.` 和 `..`，看隐藏文件时清爽一些。

## 五、touch 与 file：名字不决定内容

`touch` 在当前位置建一个空文件：

```bash
touch notes.md
```

*代码 9：建一个空文件。*

但它的本职工作**不是建文件，而是把文件的时间戳更新到现在**（touch 就是「碰一下」）——只有目标不存在时才顺手建一个空的。这一点和「对已有文件 `touch` 不会清空它」在 [Git 第零章](/2026/09/05/Git-Chapter0-Command-Line/) 里写过了，这里补一条跟上一节接得上的：**`touch` 能改的只有 atime 和 mtime，ctime 改不了。** 因为 ctime 是内核在元数据发生变化时自己写的，而你改时间戳这个动作本身就是一次元数据变化——它只会被刷成「现在」。想伪造一个文件的年龄，前两个能骗过去，第三个骗不过去。

然后是这一章里我觉得最值得记的一条：`file`。

```bash
file notes.md
# notes.md: ASCII text

file a
# a: directory
```

*代码 10：`file` 报告的是「这是什么」。*

它的作用是看一个文件到底是什么类型。关键在于**它是靠读文件开头的内容来判断的，不是靠扩展名**——很多文件格式在开头几个字节有固定的标志（叫 magic number），`file` 认的是那个。

这一点直接可以做实验。把一个 SVG 图片改名成 `.txt`：

```bash
cp pic.svg pic.txt
file pic.txt
# pic.txt: SVG Scalable Vector Graphics image
```

*代码 11：改了名字，`file` 照样认出来。*

它没有被骗到。**这就是「Unix 里扩展名对系统没有意义」那句话的实证**——`.txt` 只是名字的一部分，系统从来没有拿它做过任何判断。真正在乎扩展名的是编辑器、浏览器和你自己。反过来也成立：一个叫 `README` 没有任何扩展名的文件，该怎么用还是怎么用。

所以 `file` 的实际用途是：**下载了一个来路不明的文件、或者一个明显打不开的文件时，先 `file` 一下**，看看它到底是什么。名字撒谎，开头那几个字节不会。

## 六、mkdir -p：把中间缺的层一次补齐

```bash
mkdir notes                # 建一个目录
mkdir -p 2026/09/linux     # 中间缺的层一并建出来
```

*代码 12：`mkdir` 与 `-p`。*

`mkdir` 是 make directory 的缩写。默认情况下 `mkdir 2026/09/linux` 在 `2026` 不存在时会直接报错——它只肯建最后那一层，不会替你补前面的。加上 `-p`（parents）之后，缺几层就补几层。

`-p` 还有一个不太显眼、但在脚本里更常用的作用：**目标已经存在时它不报错。** 没有 `-p` 的 `mkdir` 撞上同名目录会返回一个非零的退出码，脚本里如果用了 `&&` 串联（第一章那个符号）就会在这里断掉。有了 `-p` 就可以无脑写 `mkdir -p 某个目录`，不用先判断在不在——这类「已经是想要的状态就当成功」的设计在运维脚本里到处都是。

## 小结

这一章的东西，按「它在回答哪个问题」重排一遍：

| 问题 | 命令 | 这一章新学到的点 |
| --- | --- | --- |
| 树长什么样 | `ls /` | 只有一棵树，`/root` 不是根目录 |
| 我在哪 | `pwd` | 输出的是绝对路径 |
| 怎么表达一个位置 | `/…` / `~/…` / `..` | `~` 是 **Shell** 替换的，不是目录名 |
| 那边有什么 | `ls -la` | 八列各是什么，属主不等于创建人 |
| 这个东西是什么 | `file` | 认内容，不认扩展名 |
| 在这里造东西 | `touch` / `mkdir -p` | `touch` 的本职是时间戳；`-p` 顺带解决幂等 |

两条线各自收一下。

**第一条是「位置」**：命令行里没有窗口，位置只能靠路径来说。而路径无非是选一个起点——树根 `/`、家 `~`、或者当前位置——然后描述怎么走过去。三种写法指向的是同一棵树上的同一批节点。

**第二条是「身份」**：`ls -l` 和 `file` 合起来回答「这个节点是什么」，而它们给的答案里**没有一个字来自文件名**。类型来自类型位和文件开头的字节，归属来自属主字段，年龄来自三个时间戳。名字在 Unix 里只是一个指向数据的标签，它不承载任何含义——这跟从 Windows 带过来的直觉正好相反，也是这一章最该扭过来的一个观念。
