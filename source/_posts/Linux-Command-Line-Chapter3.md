这一章开始进入文件系统，讲的是怎么在目录之间移动（navigation），以及怎么创建文件和文件夹。

这一章的命令并不多，只有 `pwd`、`ls`、`cd`、`touch`、`mkdir`，再加上一个 `file`。但是其中有一个前提，第一次接触时很难自己想到，那就是**整个 Linux 系统只有一棵目录树，并没有 C 盘、D 盘之分**。如果想不通这一点，`/` 和 `~` 这两个符号就会一直只是需要死记的写法，而不是表示位置的起点。

另外，这几条命令在 [Git 第零章](/2026/09/05/Git-Chapter0-Command-Line/) 里已经按照 Git 课程的需要讲过一遍了，「当前工作目录是每条命令的隐含参数」这一点在那边写过，这里就不再重复。这一篇再往深处讲两点，一是**路径到底是怎样表示位置的**，二是 **`ls -l` 输出的那一行密密麻麻的内容分别是什么**。

## 一、只有一棵树，树根是 `/`

先把一个最容易写错的地方说清楚。根目录是 `/`，这是**正斜杠**，而不是反斜杠。这个区别在别的地方也许无关紧要，但是在 Shell 里很重要，因为**反斜杠 `\` 在 Shell 里是转义符**，它完全是另一样东西。转义符的作用是让后面那个字符不再按特殊含义来解释，比如 `cd my\ folder` 里的那个空格。这两个符号一个是路径分隔符，一个是转义符，如果写混了，错误会非常彻底。

Windows 的思路是每块磁盘各有一棵树，`C:\` 和 `D:\` 各自独立，相互之间没有上下级关系。Linux 则不是这样，**整个系统只有一棵树，树根就是 `/`**。插进来的 U 盘、第二块硬盘或者网络存储，都不会长出新的树根，而是被「挂载」到这棵树的某个目录上（通常在 `/media` 或 `/mnt` 下面），从此就成了这棵树的一根树枝。

所以任何一个文件，都可以从 `/` 出发，用一条唯一的路径表示出来。下面看一下根目录下面有什么：

```bash
ls /
# bin  boot  dev  etc  home  lib  media  mnt  opt  proc  root  run  sbin  srv  sys  tmp  usr  var
```

*代码 1：树根下面这一层。*

这些目录的名字是有约定的，并不是各个发行版随便起的。其中经常打交道的有下面几个：

| 目录 | 装的是什么 |
| --- | --- |
| `/home` | 所有普通用户的家目录，例如 `/home/zby` |
| `/etc` | 系统和软件的配置文件，几乎全是纯文本 |
| `/usr` | 绝大多数软件本体，`/usr/bin` 里就是那些命令的可执行文件 |
| `/bin` | 基础命令。现代发行版上它已经是指向 `/usr/bin` 的符号链接了 |
| `/var` | 会不断变大的东西：日志（`/var/log`）、缓存、队列 |
| `/tmp` | 临时文件，重启后一般会被清空 |
| `/dev` | 设备，硬盘、终端这些在这里都表现成「文件」 |
| `/proc` | 内核和进程的实时状态，不是真实存在于磁盘上的文件 |
| `/root` | **root 用户的家目录** |

最后一行需要单独说明一下，**`/root` 并不是根目录**。根目录是 `/`，而 `/root` 只是超级用户 root 的家目录，它的地位和 `/home/zby` 完全一样，只是没有放在 `/home` 下面而已。两者只是名字相似，并没有任何关系。

如果想用图形界面看看根目录里有什么，可以执行：

```bash
xdg-open /
```

*代码 2：把「这个位置」交给图形界面打开。*

这条命令在不同的平台上写法不同（macOS 上是 `open`，WSL 上是 `explorer.exe`），[Git 第零章](/2026/09/05/Git-Chapter0-Command-Line/) 里有一张对照表。它并没有什么特别之处，只是把一个路径交给文件管理器打开。刚上手的时候，用它和 `ls` 的输出对照着看，比只看命令的输出更容易在脑子里建立起这棵树的样子。

## 二、家目录与 `~`：第二个起点

家目录是这棵树上属于用户自己的那一部分，一般位于 `/home/用户名` 下面。它的特殊之处并不只是东西都放在这里，更重要的是，**它基本上是普通用户唯一可以随意写入的地方**。树上的大部分位置（比如 `/etc`、`/usr`、`/var`）都需要 root 权限才能修改。所以文档、配置和项目全都放在家目录里，并不是一种习惯，而是由权限决定的。

因为家目录用得太频繁，所以它有一个专门的简写符号 `~`：

```bash
cd ~/projects        # 等于 cd /home/zby/projects
echo ~               # /home/zby
cd                   # 不带参数也是回家
```

*代码 3：`~` 的三种用法。*

这里有一个很容易想当然的地方。**`~` 并不是一个特殊的目录名，而是由 Shell 在启动命令之前替换掉的。** 这和第一章里 `$HOME` 那一节讲的是同一件事，命令收到的参数始终是 `/home/zby/projects` 这样的完整路径，它根本不知道用户输入的是一个波浪号。

验证的方法也很简单，用第一章的办法，给它加上单引号，替换就不会发生了：

```bash
echo ~        # /home/zby   —— Shell 替换了
echo '~'      # ~           —— 引号里的东西原样交给命令
```

*代码 4：引号是 Shell 的语法，所以它能阻止替换。*

这也解释了一个偶尔会遇到的现象，就是在某些配置文件里写 `~/xxx` 不起作用。这是因为那份配置文件并不是由 Shell 读取的，没有程序替它做这个替换，所以 `~` 就真的会被当成一个名叫「~」的目录去查找。为了保险起见，最好写完整的路径。

## 三、pwd / ls / cd：在树上问路和走路

这三条命令在 [Git 第零章](/2026/09/05/Git-Chapter0-Command-Line/) 里已经讲过，这里只补充一点最需要记住的内容，那就是它们的区别分别是「问」「看」「走」。`pwd` 用来询问当前所在的位置，`ls` 用来查看某个位置有什么（但人并不移动），只有 `cd` 才会真正改变位置。

在这一章的框架下，只需要再多理解一层，**路径有两种写法，它们的区别只在于从哪个节点出发**。

```bash
cd /home/zby/projects/linux-study    # 绝对路径：从树根 / 起步
cd projects/linux-study              # 相对路径：从当前位置起步
cd ..                                # 相对路径：向上一层
```

*代码 5：前两行是同一个目的地的两种写法，第三行是相对路径的另一种用法。*

**以 `/` 开头的路径就是绝对路径**，它从树根出发，所以无论在哪里执行，结果都一样。不以 `/` 开头的路径是相对路径，它的含义取决于 `pwd` 的当前值，换一个位置执行，就会到达完全不同的地方。`..` 之所以能回到上一层，并不是因为 `cd` 认识这个特殊符号，而是因为每个目录里都真的有一个名叫 `..` 的条目，它指向上一层目录。下一节还会再用到这一点。

## 四、`ls -l`：那一行到底在说什么

`ls` 默认只显示名字。加上 `-l`（long）之后，每一项都会展开成一行；加上 `-a`（all）之后，以点开头的隐藏文件也会一起列出来。这两个选项经常一起使用：

```bash
ls -la
```

*代码 6：出现频率最高的组合。*

`-l` 输出的每一行信息量都很大，拆开来看一共有八部分：

```
-rw-r--r-- 1 zby zby 1380 Sep  5 19:24 daily-learning2.md
```

*代码 7：一个普通文件的一行。*

| 段 | 这一行里的值 | 含义 |
| --- | --- | --- |
| 类型位 | `-` | `-` 普通文件，`d` 目录，`l` 符号链接 |
| 权限九位 | `rw-r--r--` | 属主 / 属组 / 其他人各三位，读写执行 |
| 硬链接数 | `1` | 有几个名字指向这份数据 |
| 属主 | `zby` | 这个文件属于谁 |
| 属组 | `zby` | 属于哪个用户组 |
| 大小 | `1380` | **字节数**，不是 KB |
| 时间 | `Sep  5 19:24` | 最后一次**修改内容**的时间 |
| 名字 | `daily-learning2.md` | 文件名 |

其中有三个部分特别容易看错或者被忽略，下面单独说明。

**第一，那一列表示的不是创建者，而是属主（owner）。** Linux 根本不会记录文件是谁创建的，这个信息从来都没有保存过。它记录的是文件现在归谁所有，而这一点是可以修改的（使用 `chown`），修改之后，原来那个人的痕迹就一点也不剩了。所以看到一个文件属于 `zby`，只能说明它现在归 `zby` 所有，并不能由此推断是他创建的。

**第二，显示的时间是最后一次修改内容的时间，而且一个文件其实有三个时间。**

| 时间 | 什么时候变 | 怎么看 |
| --- | --- | --- |
| mtime（modify） | 内容被改的时候 | `ls -l`（默认） |
| atime（access） | 内容被读的时候 | `ls -lu` |
| ctime（change） | 元数据被改的时候（改名、改权限、换属主） | `ls -lc` |

`ls -l` 默认显示的是 mtime。所以像修改文件名这样的操作，并不会改变 `ls -l` 显示的时间，真正改变的是那个看不到的 ctime。

**第三，目录那一行里的两个数字，含义都和字面上不一样。** 下面拿一个目录的输出来看：

```
drwxr-xr-x 3 zby zby 4096 Sep  5 21:45 a
```

*代码 8：一个目录的一行。*

- **`4096` 并不是目录里所有内容加起来的大小**，而是这个目录本身那张「名字到数据」的对照表所占的空间。如果想知道目录里的内容一共占了多少空间，需要使用 `du -sh 目录名`。
- **`3` 这个硬链接数也有它的道理。** 一个刚创建的空目录，这个数字是 2，其中一个来自它在上一层目录里的名字，另一个来自它自己里面的那个 `.`。之后每多一个子目录，这个数字就加一，因为那个子目录里的 `..` 又指回了它。所以这里的 `3` 说明 `a` 里面有 1 个子目录。上一节说过 `.` 和 `..` 是真实存在的条目，这个数字就是它们留下的痕迹。

另外再介绍两个常用的选项。`-h`（human-readable）会把字节数换算成 `1.4K`、`12M` 这样的形式；`-A` 和 `-a`几乎一样，只是不列出 `.` 和 `..`，查看隐藏文件时会更清爽一些。

## 五、touch 与 file：名字不决定内容

`touch` 可以在当前位置创建一个空文件：

```bash
touch notes.md
```

*代码 9：建一个空文件。*

不过它的本职工作**并不是创建文件，而是把文件的时间戳更新为当前时间**（touch 的意思就是「碰一下」），只有在目标文件不存在时，才会顺便创建一个空文件。这一点，以及「对已有的文件执行 `touch` 不会清空它」，在 [Git 第零章](/2026/09/05/Git-Chapter0-Command-Line/) 里已经写过了。这里再补充一点，正好可以和上一节联系起来，**`touch` 只能修改 atime 和 mtime，无法修改 ctime。** 因为 ctime 是在元数据发生变化时由内核自己写入的，而修改时间戳这个操作本身就是一次元数据的变化，所以 ctime 只会被更新成当前时间。如果想伪造一个文件的创建时间，前两个时间可以蒙混过去，第三个时间却骗不过去。

接下来是这一章里最值得记住的一条命令，`file`：

```bash
file notes.md
# notes.md: ASCII text

file a
# a: directory
```

*代码 10：`file` 报告的是「这是什么」。*

它的作用是查看一个文件到底是什么类型。关键在于，**它是通过读取文件开头的内容来判断的，而不是依据扩展名**。很多文件格式在开头几个字节里有固定的标志，这种标志叫作 magic number，`file` 识别的就是它。

这一点可以直接用实验来验证。把一个 SVG 图片改名成 `.txt` 文件：

```bash
cp pic.svg pic.txt
file pic.txt
# pic.txt: SVG Scalable Vector Graphics image
```

*代码 11：即使改了名字，`file` 照样能认出来。*

`file` 并没有被骗过去。这就是「在 Unix 里，扩展名对系统没有意义」这句话的证明。`.txt` 只是名字的一部分，系统从来没有用它来做过任何判断，真正在意扩展名的，是编辑器、浏览器和使用者自己。反过来也是一样，一个名叫 `README`、没有任何扩展名的文件，照样可以正常使用。

所以 `file` 的实际用途是，在下载了一个来历不明的文件，或者遇到一个明显打不开的文件时，**先用 `file` 检查一下**，看看它到底是什么。文件名可能会骗人，但是文件开头的那几个字节不会。

## 六、mkdir -p：把中间缺的层一次补齐

```bash
mkdir notes                # 建一个目录
mkdir -p 2026/09/linux     # 中间缺的层一并建出来
```

*代码 12：`mkdir` 与 `-p`。*

`mkdir` 是 make directory 的缩写。默认情况下，如果 `2026` 不存在，`mkdir 2026/09/linux` 就会直接报错，因为它只会创建最后一层目录，不会自动补全前面缺少的部分。加上 `-p`（parents）之后，缺少几层就会补上几层。

`-p` 还有一个不太显眼的作用，但它在脚本里反而更常用，那就是**目标目录已经存在时不会报错**。不加 `-p` 的 `mkdir` 遇到同名目录时，会返回一个非零的退出码。如果脚本里用 `&&`（第一章介绍过这个符号）把命令串联起来，执行就会在这里中断。而加上 `-p` 以后，就可以直接写 `mkdir -p 某个目录`，不需要事先判断它是否存在。这种「已经是想要的状态，就当作成功」的设计，在运维脚本里非常常见。

## 小结

把这一章的内容按照「它在回答哪个问题」重新排列一遍：

| 问题 | 命令 | 这一章新学到的点 |
| --- | --- | --- |
| 树长什么样 | `ls /` | 只有一棵树，`/root` 不是根目录 |
| 现在在哪 | `pwd` | 输出的是绝对路径 |
| 怎么表达一个位置 | `/…` / `~/…` / `..` | `~` 是 **Shell** 替换的，不是目录名 |
| 那边有什么 | `ls -la` | 八列各是什么，属主不等于创建人 |
| 这个东西是什么 | `file` | 认内容，不认扩展名 |
| 在这里造东西 | `touch` / `mkdir -p` | `touch` 的本职是时间戳；`-p` 顺带解决幂等 |

最后把两条线索分别总结一下。

**第一条线索是「位置」。** 命令行里没有窗口，所以位置只能用路径来描述。而一条路径无非是先选择一个起点，可以是树根 `/`、家目录 `~` 或者当前位置，然后再描述怎样从起点走过去。这三种写法指向的都是同一棵树上的同一批节点。

**第二条线索是「身份」。** `ls -l` 和 `file` 合起来回答了「这个节点是什么」，而它们给出的答案里，没有一个字来自文件名。文件的类型来自类型位和文件开头的字节，归属来自属主字段，年龄来自三个时间戳。在 Unix 里，名字只是一个指向数据的标签，本身不承载任何含义。这和从 Windows 带过来的直觉正好相反，也是这一章最需要扭转过来的一个观念。
