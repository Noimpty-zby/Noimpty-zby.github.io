[第三章](/2026/09/05/Linux-Command-Line-Chapter3/) 讲了怎样创建文件，[第四章](/2026/09/19/Linux-Command-Line-Chapter4/) 讲了怎样往文件里写内容，这一章处理剩下的三件事，也就是删除、移动和复制。

这一章只有 `rm`、`mv`、`cp` 三条命令，用法几行就能说完。但它们是这门课里**第一批会造成不可逆后果**的命令。它们没有回收站，也无法撤销，而且其中两条命令在覆盖文件时一句提示都没有。所以这一篇的重点并不是参数表，而是两个问题，一是**它们到底改动了什么**，二是**它们会在什么情况下悄悄做了一件你并不打算做的事**。

## 一、先看清楚一个「文件」是什么

这三条命令的行为，几乎都可以从同一张图里推导出来。

![目录里的一条记录、inode 与数据块，以及 rm/mv/cp 各动哪一层](/img/posts/linux-rm-mv-cp/name-vs-data.svg)

*图 1：文件的名字和数据是分开存放的，这是理解这一章的前提。*

目录本身也是一份数据，它的内容是**一张「名字到 inode 号」的对照表**。文件真正的属性（比如大小、权限、时间戳）以及数据块的位置，都记录在 inode 里，而文件名并不在 inode 里。[第三章](/2026/09/05/Linux-Command-Line-Chapter3/) 中 `ls -l` 显示的那个「硬链接数」，统计的就是有多少条记录指向同一个 inode。

这并不只是一种抽象的说法，可以直接观察到：

```bash
echo data > f1.txt
ln f1.txt f2.txt          # 建第二个名字，指向同一份数据
stat -c %h f1.txt         # 2   —— 链接数变成 2

rm f1.txt                 # 删掉第一个名字
cat f2.txt                # data —— 数据还在
stat -c %h f2.txt         # 1
```

*代码 1：`rm` 删除的是名字，只有当最后一个名字也被删除时，数据才会被回收。*

所以这三条命令的分工如下：

| | 动了什么 | 结果 |
| --- | --- | --- |
| `rm` | 划掉目录里的那条记录 | 和文件多大无关，删 500 MB 也只要 16 ms |
| `mv` | 同一分区内只改这条记录 | inode 都不变，200 MB 的文件改名 3 ms |
| `cp` | 新加一条记录，复制一整份数据 | 三条里唯一一个越大越慢、也唯一一个真的多占一份磁盘 |

## 二、rm：删掉就是删掉了

最基本的用法是删除一个文件：

```bash
rm notes.txt
```

*代码 2：没有确认，也没有提示，命令执行完，文件就不存在了。*

**`rm` 没有回收站。** 在图形界面里执行「删除」，其实是把文件移到了一个隐藏的目录里，而 `rm` 并不是这样，它会直接删除目录里的那条记录。在被覆盖之前，数据块也许还留在磁盘上，但是从命令行的角度来看，已经没有任何办法再访问到这个文件了。

### 2.1 目录要多给一个选项

如果直接用 `rm` 删除一个目录，会被拒绝：

```bash
rm d1
# rm: cannot remove 'd1': Is a directory
```

*代码 3：目录不能这样删除。*

针对两种不同的情况，有两个对应的选项：

```bash
rm -d empty_dir           # 只能删空目录
rm -d d3
# rm: cannot remove 'd3': Directory not empty

rm -r d3                  # 递归删，连里面的东西一起
```

*代码 4：`-d` 表示 directory，`-r` 表示 recursive。*

`-d` 之所以比较谨慎，正是因为它**删除不了非空的目录**。当你以为某个目录是空的、而实际上并不是时，它会拦住你。还有一条更老的命令 `rmdir`，做的也是同样的事情，报错信息也几乎一样（`rmdir: failed to remove 'd4': Directory not empty`）。

### 2.2 三道护栏

`rm` 自带的确认机制有三种，它们之间的区别很大：

```bash
rm -i t1/*
# rm: remove regular empty file 't1/a'?     ← 每个文件问一次

rm -I t2/*
# rm: remove 4 arguments?                   ← 总共只问一次

rm -ri t3
# rm: descend into directory 't3'?          ← 连「要不要进这个目录」都问
```

*代码 5：`-i` 对每个文件都询问一次，`-I` 只询问一次，`-r` 和 `-i` 可以合在一起写。*

从实际使用的情况来看，**大写的 `-I` 比 `-i` 有用得多**。用 `-i` 删除几十个文件时，需要按几十次 `y`，按到第五次左右，手就会不假思索地自动按下去，这道护栏也就形同虚设了。而 `-I` 只会在参数超过三个时询问一次，正好拦在批量删除这个真正危险的场景上。

还有一道护栏是默认就有的，那就是**删除只读文件时，即使不加任何选项，`rm` 也会先询问一句**：

```bash
rm ro.txt
# rm: remove write-protected regular empty file 'ro.txt'?
```

*代码 6：写保护的文件会触发确认。*

而 `-f`（force）的作用，就是**把上面这些护栏全部关掉**。加上它以后，`rm` 不会询问，也不会报错，即使目标不存在也会当作成功。`rm -rf` 之所以危险，就是因为它同时去掉了递归删除的限制和所有的确认步骤。

### 2.3 以 `-` 开头的文件名

```bash
rm -rf.txt
# rm: invalid option -- '.'
# Try 'rm ./-rf.txt' to remove the file '-rf.txt'.
```

*代码 7：文件名被当成了选项。*

如果一个文件的名字以 `-` 开头，`rm` 会把它当作选项来解析。解决的办法是写成 `rm -- -rf.txt`（`--` 表示后面的内容都不是选项），或者写成 `rm ./-rf.txt`。报错信息里其实已经直接给出了第二种写法。

## 三、mv：同一条命令，三种结局

`mv` 的语法是 `mv 源 目标`，对文件和目录都是一样的写法，**移动目录时也不需要加 `-r`**。

真正需要想清楚的是，**命令的结果取决于「目标」在执行的那一刻是什么**。

![mv 的目标是目录、不存在、还是已有文件，结果完全不同](/img/posts/linux-rm-mv-cp/target-decides.svg)

*图 2：在三种结果里，通常只有第一种是想要的。*

```bash
mv a.txt real/            # real 是已存在的目录 → 搬进去，real/a.txt
mv a.txt nope             # nope 不存在        → 把 a.txt 改名成 nope
mv a.txt dst.txt          # dst.txt 已存在     → 悄悄覆盖，原内容没了
```

*代码 8：同一条命令的三种结果。*

第二行是最容易吃亏的情况，**当目标目录不存在时，`mv` 并不会报错，而是会把文件改名**。比如本来想把文件移到 `backup/` 里，却把目录名敲成了 `backup2`，结果并不会得到一句「没有这个目录」的提示，而是当前目录下多出了一个名叫 `backup2` 的文件，原来的那个文件则不见了，看起来就像文件丢失了一样。

避免这个问题的办法很简单，那就是**在想把文件移进某个目录时，给目标加上结尾的斜杠**：

```bash
mv a.txt nope/
# mv: cannot move 'a.txt' to 'nope/': Not a directory
```

*代码 9：加上一个斜杠，悄悄改名的情况就变成了一条明确的报错。*

第三行的情况同样需要警惕。`mv` 覆盖已有的文件时不会给出任何提示，被覆盖的那份内容当场就消失了。`-i`（覆盖之前询问一次）和 `-n`（目标已存在时不做任何操作）都可以防止这种情况。

在目录之间移动时，规则也是一样的。如果 `t` 已经存在，`mv s t` 会得到 `t/s`；如果 `t` 不存在，就会把 `s` 改名为 `t`。

### 3.1 为什么 `mv` 那么快

```bash
# 同一个分区内改名
echo x > n.txt
stat -c %i n.txt          # 104359
mv n.txt n2.txt
stat -c %i n2.txt         # 104359 —— 同一个 inode
```

*代码 10：inode 没有变化，数据一个字节都没有移动过。*

在同一个分区内执行 `mv`，**只是修改了目录那张表里的一行记录**，所以速度和文件的大小完全无关。如果跨分区移动，情况就不一样了。因为目标分区上并没有这个 inode，所以只能真的复制一份数据，再把源文件删除：

| 操作 | 200 MB 文件耗时 | inode |
| --- | --- | --- |
| 同一分区内 `mv` | 3 ms | 不变 |
| 跨分区 `mv` | 154 ms | 变了 |

这也解释了另一件事。跨分区的 `mv` 如果在中途被打断，可能会出现「两边各有一份」的情况，或者源文件已经不完整了，因为它本质上就是 `cp` 加上 `rm`。

## 四、cp：真的复制一份

```bash
cp notes.txt notes-backup.txt      # 复制成一个新名字
cp notes.txt backup/               # 复制进某个目录
```

*代码 11：两种基本用法。*

源和目标必须是两个不同的名字，否则会被直接拦下：

```bash
cp x.txt x.txt
# cp: 'x.txt' and 'x.txt' are the same file
```

*代码 12：`cp` 不接受源和目标是同一个文件。*

**复制目录时必须加上 `-r`**，这一点和 `mv` 正好相反：

```bash
cp s d
# cp: -r not specified; omitting directory 's'

cp -r s d                 # 这才行
```

*代码 13：`mv` 移动目录时不需要 `-r`，而 `cp` 复制目录时必须加上它。*

造成这个差别的原因，还是要回到第一节那张图。`mv` 修改的只是一条记录，在那张表里，目录和文件并没有区别；而 `cp` 要真的把内容复制出来，遇到目录时就必须决定里面的东西要不要一起复制，`-r` 回答的就是这个问题。

`cp -r` 同样遵循图 2 中的规则，而且比 `mv` 更容易弄混：

```bash
cp -r s d_new             # d_new 不存在 → 复制成 d_new，内容是 s 里的东西
cp -r s d_exist           # d_exist 已存在 → 得到 d_exist/s
```

*代码 14：同一条命令，运行两遍，结果并不一样。*

如果连续执行两次 `cp -r s d`，就会得到 `d` 和 `d/s` 两层目录，因为第一次执行时目标还不存在，而第二次执行时它已经存在了。

`cp` 覆盖文件时也和 `mv` 一样没有任何提示，如果目标文件已经存在，就会直接覆盖它，不会询问。使用 `-n`（no-clobber）可以防止覆盖：

```bash
cp -n new.txt old.txt     # old.txt 已存在，这条什么也不做
```

*代码 15：`-n` 的意思是，目标已经存在时就不要动它。*

## 五、护栏一览

这三条命令的安全选项是一套相通的设计，最好放在一起记：

| 选项 | `rm` | `mv` / `cp` |
| --- | --- | --- |
| `-i` | 每个文件问一次 | 覆盖前问一次 |
| `-I` | 超过三个参数时问一次（更实用） | 没有这个选项 |
| `-n` | 没有这个选项 | 目标已存在就跳过，不覆盖 |
| `-f` | 关掉所有确认 | 覆盖时不问；`cp -f` 还会在目标打不开时先删掉它再重来 |
| `--` | 后面的都当文件名，不当选项 | 同左 |

真正值得养成的习惯其实只有两个，一是**给目录类型的目标加上结尾的斜杠**，二是**批量删除时使用 `-I`**。这两个动作几乎没有任何成本，却能避免这一章里最常见的两种事故。

## 小结

| 问题 | 命令 | 要点 |
| --- | --- | --- |
| 删一个文件 | `rm f` | 没有回收站；删的是名字，不是数据 |
| 删一个目录 | `rm -d` / `rm -r` | `-d` 只删空的，删不动的时候它是在提醒你 |
| 批量删之前拦一下 | `rm -I` | 比 `-i` 有用，因为 `-i` 会被连按成肌肉记忆 |
| 搬走 | `mv a b` | 目标是目录就搬进去，**目标不存在就变成改名** |
| 改名 | `mv a b` | 和搬走是同一条命令，因为改的都是那条记录 |
| 复制文件 | `cp a b` | 源和目标不能是同一个 |
| 复制目录 | `cp -r s d` | 目标存不存在，结果差一层 |
| 别覆盖 | `-n` | 目标在就不动手，比 `-i` 更适合写进脚本 |

这一章的内容可以用一句话来概括，那就是**这三条命令操作的都是文件的名字，而不是文件本身**。

`rm` 之所以快，是因为它只删掉了一行记录；`mv` 在同一个分区内快到和文件大小无关，是因为它只修改了一行记录；`cp` 之所以慢，是因为只有它在真正地复制数据。换一个角度来看，这一章的风险也正来自这里。修改一行记录是一个非常轻量的操作，轻到系统认为没有必要提醒用户。`mv` 覆盖文件时不询问，`cp` 覆盖文件时不询问，目标目录不存在时 `mv` 顺手把文件改了名，这三件事都源于这一点。
