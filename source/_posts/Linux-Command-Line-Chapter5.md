[第三章](/2026/09/05/Linux-Command-Line-Chapter3/) 把文件建了出来，[第四章](/2026/09/19/Linux-Command-Line-Chapter4/) 往里写了东西，这一章处理剩下的三件事：删掉、搬走、复制一份。

命令只有 `rm`、`mv`、`cp` 三条，用法几行就能说完。但它们是这门课里**第一批会造成不可逆后果**的命令——没有回收站，没有撤销，而且其中两条在覆盖东西的时候一个字都不会说。所以这一篇的重点不在参数表上，而在两个问题：**它们到底动了什么**，以及**什么时候它们会安静地做掉一件你没打算做的事**。

<!-- more -->

## 一、先看清楚一个「文件」是什么

这三条命令的行为，几乎都能从同一张图里推出来。

![目录里的一条记录、inode 与数据块，以及 rm/mv/cp 各动哪一层](/img/posts/linux-rm-mv-cp/name-vs-data.svg)

*图 1：名字和数据是分开存的，这是理解这一章的前提。*

一个目录本身也是一份数据，内容是**一张「名字 → inode 号」的表**。真正的文件属性（大小、权限、时间戳）和数据块的位置都记在 inode 里，名字不在其中。[第三章](/2026/09/05/Linux-Command-Line-Chapter3/) 里 `ls -l` 那个「硬链接数」，数的就是有多少条记录指向同一个 inode。

这不是抽象的说法，可以直接看出来：

```bash
echo data > f1.txt
ln f1.txt f2.txt          # 建第二个名字，指向同一份数据
stat -c %h f1.txt         # 2   —— 链接数变成 2

rm f1.txt                 # 删掉第一个名字
cat f2.txt                # data —— 数据还在
stat -c %h f2.txt         # 1
```

*代码 1：`rm` 删掉的是名字。只有当最后一个名字也没了，数据才会被回收。*

所以三条命令的分工是这样的：

| | 动了什么 | 结果 |
| --- | --- | --- |
| `rm` | 划掉目录里的那条记录 | 和文件多大无关，删 500 MB 也只要 16 ms |
| `mv` | 同一分区内只改这条记录 | inode 都不变，200 MB 的文件改名 3 ms |
| `cp` | 新加一条记录，复制一整份数据 | 三条里唯一一个越大越慢、也唯一一个真的多占一份磁盘 |

## 二、rm：删掉就是删掉了

最基本的形式是删一个文件：

```bash
rm notes.txt
```

*代码 2：没有确认，没有提示，命令执行完文件就不在了。*

**这里没有回收站。** 图形界面里的「删除」是把文件挪进一个隐藏目录，`rm` 不是——它直接把目录里那条记录去掉。数据块在被覆盖之前也许还躺在磁盘上，但从命令行的角度看，这个文件已经没有任何办法再引用到了。

### 2.1 目录要多给一个选项

直接 `rm` 一个目录会被拒绝：

```bash
rm d1
# rm: cannot remove 'd1': Is a directory
```

*代码 3：目录不能这么删。*

两个选项对应两种情况：

```bash
rm -d empty_dir           # 只能删空目录
rm -d d3
# rm: cannot remove 'd3': Directory not empty

rm -r d3                  # 递归删，连里面的东西一起
```

*代码 4：`-d` 是 directory，`-r` 是 recursive。*

`-d` 的谨慎之处正在于它**删不动非空目录**——当你以为某个目录是空的时候，它会拦住你。还有一条更老的命令 `rmdir` 做的是同一件事，报错也几乎一样（`rmdir: failed to remove 'd4': Directory not empty`）。

### 2.2 三道护栏

`rm` 自带的确认机制有三档，区别很大：

```bash
rm -i t1/*
# rm: remove regular empty file 't1/a'?     ← 每个文件问一次

rm -I t2/*
# rm: remove 4 arguments?                   ← 总共只问一次

rm -ri t3
# rm: descend into directory 't3'?          ← 连「要不要进这个目录」都问
```

*代码 5：`-i` 逐个问，`-I` 问一次，`-r` 和 `-i` 可以合起来写。*

实际用下来，**`-I`（大写）比 `-i` 有用得多**：`-i` 在删几十个文件时要敲几十次 `y`，敲到第五次手就自动了，护栏等于不存在；`-I` 只在参数超过三个时拦一次，正好卡在「批量删除」这个真正危险的场景上。

还有一道护栏是默认就在的：**删只读文件时，即使不加任何选项也会问一句。**

```bash
rm ro.txt
# rm: remove write-protected regular empty file 'ro.txt'?
```

*代码 6：写保护的文件会触发确认。*

而 `-f`（force）的作用就是**把上面这些全部关掉**：不问、不报错、目标不存在也当成功。`rm -rf` 之所以危险，是因为它同时关掉了递归的边界和所有确认。

### 2.3 以 `-` 开头的文件名

```bash
rm -rf.txt
# rm: invalid option -- '.'
# Try 'rm ./-rf.txt' to remove the file '-rf.txt'.
```

*代码 7：文件名被当成了选项。*

一个名字以 `-` 开头的文件，`rm` 会把它当参数解析。解法是 `rm -- -rf.txt`（`--` 表示「后面都不是选项」）或者 `rm ./-rf.txt`。报错信息里已经把第二种写法直接给出来了。

## 三、mv：同一条命令，三种结局

`mv` 的语法是 `mv 源 目标`，文件和目录都一样，**目录也不需要 `-r`**。

真正需要想清楚的是：**结果取决于「目标」在那一刻是什么。**

![mv 的目标是目录、不存在、还是已有文件，结果完全不同](/img/posts/linux-rm-mv-cp/target-decides.svg)

*图 2：三种结局里，只有第一种是大多数时候想要的。*

```bash
mv a.txt real/            # real 是已存在的目录 → 搬进去，real/a.txt
mv a.txt nope             # nope 不存在        → 把 a.txt 改名成 nope
mv a.txt dst.txt          # dst.txt 已存在     → 悄悄覆盖，原内容没了
```

*代码 8：同一条命令的三种结果。*

第二行是最容易吃亏的一种：**目标目录不存在时，`mv` 不会报错，它会把文件改名。** 想搬进 `backup/` 却把目录名敲成了 `backup2`，结果不是一句「没有这个目录」，而是当前目录下多出一个叫 `backup2` 的文件，原来那个文件消失了——看起来就像文件丢了。

对付它的办法很简单：**想搬进目录的时候，给目标带上结尾斜杠。**

```bash
mv a.txt nope/
# mv: cannot move 'a.txt' to 'nope/': Not a directory
```

*代码 9：一个斜杠就把「悄悄改名」变成了一声响。*

第三行的沉默同样值得警惕：`mv` 覆盖已有文件时没有任何提示，被覆盖的那份当场消失。`-i`（覆盖前问一句）和 `-n`（目标存在就不动手）都能挡住它。

目录之间移动的规则是一致的：`mv s t` 在 `t` 已存在时得到 `t/s`，`t` 不存在时就是把 `s` 改名成 `t`。

### 3.1 为什么 `mv` 那么快

```bash
# 同一个分区内改名
echo x > n.txt
stat -c %i n.txt          # 104359
mv n.txt n2.txt
stat -c %i n2.txt         # 104359 —— 同一个 inode
```

*代码 10：inode 没变，数据一个字节都没动过。*

同一个分区内的 `mv` **只是在目录那张表里改了一行**，跟文件多大完全无关。跨分区就不一样了，目标分区上没有这个 inode，只能真的复制一份再把源删掉：

| 操作 | 200 MB 文件耗时 | inode |
| --- | --- | --- |
| 同一分区内 `mv` | 3 ms | 不变 |
| 跨分区 `mv` | 154 ms | 变了 |

这也解释了一件事：跨分区的 `mv` 中途被打断，是可能出现「两边都有一份」或者源文件已经不完整的——因为它本质上是 `cp` 加 `rm`。

## 四、cp：真的复制一份

```bash
cp notes.txt notes-backup.txt      # 复制成一个新名字
cp notes.txt backup/               # 复制进某个目录
```

*代码 11：两种基本用法。*

源和目标必须是两个不同的名字，否则会被直接拦下：

```bash
cp x.txt x.txt
# cp: 'x.txt' and 'x.txt' are the same file
```

*代码 12：`cp` 不接受源和目标是同一个文件。*

**目录必须加 `-r`**，这一点和 `mv` 正好相反：

```bash
cp s d
# cp: -r not specified; omitting directory 's'

cp -r s d                 # 这才行
```

*代码 13：`mv` 搬目录不用 `-r`，`cp` 复制目录必须要。*

差别的根源还是第一节那张图：`mv` 改的是一条记录，目录和文件在那张表里没有区别；而 `cp` 要真的把内容复制出来，遇到目录就得决定「里面的东西要不要一起」——`-r` 就是在回答这个问题。

`cp -r` 也遵守图 2 那条规则，而且比 `mv` 更容易搞混：

```bash
cp -r s d_new             # d_new 不存在 → 复制成 d_new，内容是 s 里的东西
cp -r s d_exist           # d_exist 已存在 → 得到 d_exist/s
```

*代码 14：同一条命令，跑两遍结果不一样。*

连着跑两次 `cp -r s d` 会得到 `d` 和 `d/s` 两层——第一次目标不存在，第二次它已经存在了。

覆盖行为也和 `mv` 一样安静：目标文件已存在时直接盖掉，不问。`-n`（no-clobber）能拦住：

```bash
cp -n new.txt old.txt     # old.txt 已存在，这条什么也不做
```

*代码 15：`-n` 的意思是「目标在就别动」。*

## 五、护栏一览

三条命令的安全选项是一套，值得一起记：

| 选项 | `rm` | `mv` / `cp` |
| --- | --- | --- |
| `-i` | 每个文件问一次 | 覆盖前问一次 |
| `-I` | 超过三个参数时问一次（更实用） | 没有这个选项 |
| `-n` | 没有这个选项 | 目标已存在就跳过，不覆盖 |
| `-f` | 关掉所有确认 | 覆盖时不问；`cp -f` 还会在目标打不开时先删掉它再重来 |
| `--` | 后面的都当文件名，不当选项 | 同左 |

真正值得养成的习惯其实只有两个：**给目录目标带上结尾斜杠**，以及**批量删除时用 `-I`**。这两个动作的成本接近于零，挡掉的却是这一章里最常见的两种事故。

## 小结

| 问题 | 命令 | 要点 |
| --- | --- | --- |
| 删一个文件 | `rm f` | 没有回收站；删的是名字，不是数据 |
| 删一个目录 | `rm -d` / `rm -r` | `-d` 只删空的，删不动的时候它是在提醒你 |
| 批量删之前拦一下 | `rm -I` | 比 `-i` 有用，因为 `-i` 会被连按成肌肉记忆 |
| 搬走 | `mv a b` | 目标是目录就搬进去，**目标不存在就变成改名** |
| 改名 | `mv a b` | 和搬走是同一条命令，因为改的都是那条记录 |
| 复制文件 | `cp a b` | 源和目标不能是同一个 |
| 复制目录 | `cp -r s d` | 目标存不存在，结果差一层 |
| 别覆盖 | `-n` | 目标在就不动手，比 `-i` 更适合写进脚本 |

这一章可以收成一句话：**这三条命令操作的都是「名字」，而不是你以为的那个「文件」。**

`rm` 快，是因为它只划掉一行；`mv` 在同一分区内快到和文件大小无关，是因为它只改一行；`cp` 慢，是因为只有它真的在搬数据。同一个道理换个方向看就是这一章的风险所在——**改一行是很轻的操作，轻到系统觉得没必要提醒你。** `mv` 覆盖不问、`cp` 覆盖不问、目标目录不存在时 `mv` 顺手改名，三件事都源于此。
