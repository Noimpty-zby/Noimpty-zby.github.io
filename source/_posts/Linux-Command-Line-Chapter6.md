[第五章](/2026/09/19/Linux-Command-Line-Chapter5/) 讲的是三条会造成不可逆后果的命令，这一章的内容则轻松得多，讲的是命令敲到一半时，怎样快速移动光标、删掉一段内容、改正一个错字，以及怎样把以前输入过的命令找回来。

这一章的内容就是一串快捷键，逐个记住并不难。但是其中有几处和直觉不一样。比如同样叫「删除一个词」的两个键，删除的范围可能相差一整段路径；`Ctrl+L` 和 `clear` 看起来效果一样，其实并不相同；`!42` 也不会把当时的输出重新显示一遍。这一篇会把这几处逐一讲清楚。

## 一、这些键是谁在处理

在 Bash 里输入命令时，负责读取这一行输入的既不是终端，也不是 Bash 的主程序，而是一个叫作 **GNU readline** 的库。这一章介绍的快捷键全部由它处理，键位沿用了 Emacs 编辑器的习惯。文档里写的 `C-a` 表示 Ctrl+A，`M-f` 里的 M 表示 Meta，也就是现在键盘上的 Alt 键。

由此可以直接得出两个结论：

- **只要别的程序也使用了 readline，这些快捷键就同样可以使用。** 比如在 Python 的交互式解释器里，`Ctrl+A` 和 `Ctrl+W` 的效果和在 Bash 里完全相同。
- **每个按键都要先经过终端。** 有些按键在到达 readline 之前就被终端截走了，第六节讲的 `Ctrl+S` 就是这种情况。如果 Alt 组合键被终端软件占用了（比如按下 Alt+F 时弹出了「文件」菜单），可以先按一下 `Esc`，再按字母键，效果和 Alt 加字母键相同。

## 二、移动光标

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl+A` / `Ctrl+E` | 跳到行首 / 行尾 |
| `Ctrl+B` / `Ctrl+F` | 左移 / 右移一个字符 |
| `Alt+B` / `Alt+F` | 左移 / 右移一个词 |

这些字母都是有来历的。A 是字母表的第一个字母，E 是 end 的首字母，B 和 F 分别是 backward 和 forward 的首字母。按词移动时，有两个细节值得看清楚：

![光标在 cd /usr/local/share/doc 上按不同的键会落在哪里](/img/posts/linux-shortcuts-history/move.svg)

*图 1：`Alt+B` 会让光标停在词首，`Alt+F` 会让光标停在词尾。*

第一，**`Alt+F` 会停在当前词的末尾，而不是下一个词的开头。** 如果光标在 `share` 的开头，按一下 `Alt+F`，光标就会停在 `share` 后面的那个 `/` 上。

第二，**在 readline 看来，「词」只由字母和数字组成。** `/`、`.` 和 `-` 都被当作分隔符，所以 `/usr/local/share/doc` 在它看来是四个词，从行尾开始按 `Alt+B`，要按四下才能回到 `usr`。这一点在删除时的影响更大。

## 三、删除，其实是剪切

| 快捷键 | 删除范围 |
| --- | --- |
| `Ctrl+U` | 光标左边的全部内容 |
| `Ctrl+K` | 光标右边的全部内容 |
| `Ctrl+W` | 光标左边一个词（以空格为界） |
| `Alt+Backspace` | 光标左边一个词（以字母数字为界） |
| `Alt+D` | 光标右边一个词（以字母数字为界） |

`Ctrl+U` 和 `Ctrl+K` 以光标为分界线，一个删除左边的内容，一个删除右边的内容。所以**当光标不在行尾时，`Ctrl+U` 并不会清空整行**，光标右边的那一部分会保留下来。

### 3.1 两种「一个词」

表里有两个键都是「删除左边一个词」，它们的区别就在于第二节说的「词」的定义：

![同一行上，Ctrl+W、Alt+Backspace、Ctrl+U、Ctrl+K、Alt+D 各删掉哪一段](/img/posts/linux-shortcuts-history/kill.svg)

*图 2：`Ctrl+W` 以空格作为词的边界，`Alt` 系列以字母和数字作为词的边界。*

```bash
$ cd /usr/local/share/doc█        # 光标在行尾
# Ctrl+W         →  $ cd █
# Alt+Backspace  →  $ cd /usr/local/share/█
```

*代码 1：同样是「删除左边一个词」，结果却相差了一整段路径。*

`Ctrl+W` 只把空格当作边界，所以整条路径被当成了一个词，一次就全部删掉了；而 `Alt+Backspace` 使用的是 readline 的定义，所以只删掉了 `doc`。如果只想修改路径的最后一段，就用后者；如果整个参数都不要了，就用前者。

`Alt+D` 和 `Alt+Backspace` 的方向相反，它删除的是光标右边的一个词。**在 Ubuntu 上，`Ctrl+Delete` 绑定的也是这个功能**（在 readline 里叫作 `kill-word`），同样是向右删除，所以它和向左删除的 `Ctrl+W` 并不是一对：

```bash
$ bind -q kill-word
kill-word can be invoked via "\e[3;5~", "\ed".
```

*代码 2：`\e[3;5~` 是 Ctrl+Delete 发出的序列，`\ed` 是 Alt+D 发出的序列。*

### 3.2 Ctrl+Y：删掉的东西还在

用上面这些键删除的内容并没有被丢掉，而是进入了 readline 的**剪切环**（kill ring）。按下 `Ctrl+Y`，就可以把最近一次删除的内容粘贴到光标所在的位置。

它有三个特点，所以比「撤销」要有用得多：

- **连续的删除会合并成一次。** 比如连按两下 `Ctrl+W`，删掉了 `alpha beta`，那么按 `Ctrl+Y` 时，两个词会一起被粘贴回来。
- **换一条命令后，内容也还在。** 因为剪切环属于这个 Shell，而不属于某一行命令。
- **更早删除的内容也能找回来。** 按过 `Ctrl+Y` 之后，紧接着按 `Alt+Y`，粘贴上去的内容就会换成更早一次删除的内容。

第二个特点带来了一种很实用的用法。比如一条很长的命令输入到一半，突然发现需要先确认一下别的事情：

```bash
$ tar -czf backup.tgz notes█      # 敲到一半
# Ctrl+U                          → 整行剪走
$ ls /                            # 先办别的事
$ █
# Ctrl+Y                          → $ tar -czf backup.tgz notes█
```

*代码 3：先用 `Ctrl+U` 把内容收起来，之后再用 `Ctrl+Y` 拿回来。*

## 四、交换两个字符、两个词

`Ctrl+T` 会把光标前面的那个字符往后移一位，和光标所在位置的字符交换，同时光标也会前进一格；**当光标在行尾时，交换的是最后两个字符**。它最常见的用途就是改正打错的字：

```bash
$ gti█        # Ctrl+T  →  $ git█
```

*代码 4：在行尾直接按，不需要先移动光标。*

`Alt+T` 对词做同样的操作，它会交换光标前后的两个词；当光标在行尾时，交换的是最后两个词。

```bash
$ mv dst src█            # Alt+T  →  $ mv src dst█
$ cp new.txt old.txt█    # Alt+T  →  $ cp new.txt txt.old█
```

*代码 5：第二行交换的是 `old` 和 `txt`。*

第二行的结果又是「词」的定义在起作用。在 readline 看来，`old.txt` 是 `old` 和 `txt` 两个词，所以被交换的是这两个词，而不是两个文件名。**当参数里带有 `.` 或 `/` 时，`Alt+T` 基本上帮不上忙**，可是 `mv` 和 `cp` 把源和目标写反的时候，偏偏正是最想用它的时候。

## 五、清屏：Ctrl+L 和 clear 不完全一样

这两种方式都能清空屏幕，但是它们有两处不同。

第一，**`Ctrl+L` 会保留正在输入的这一行。** 如果命令输入到一半时想清屏，按下 `Ctrl+L` 之后，这半行内容会原样出现在清空后屏幕的最上方；而 `clear` 本身是一条命令，要执行它，就只能先把这一行让给它。

第二，**`clear` 还会清除回滚缓冲区，而 `Ctrl+L` 不会。** 两者发送给终端的字节相差了一段：

```text
Ctrl+L  →  \e[H \e[2J           光标回左上角，清空屏幕
clear   →  \e[H \e[2J \e[3J     再加一段：清空回滚缓冲区
```

*代码 6：`\e[3J` 是 xterm 系列终端用来清除滚动历史的控制序列。*

实际的效果是，先输出 60 行内容，按下 `Ctrl+L` 之后再往上滚动，这 60 行都还在；而执行 `clear` 之后，它们在滚动历史里也消失了。所以如果想清屏，又想保留往上翻看的余地，就使用 `Ctrl+L`，或者使用 `clear -x`（`-x` 的意思就是不清除回滚缓冲区）。

## 六、history：一份清单，不是录像

```bash
$ history
    1  echo one
    2  date +%T.%N
    3  ls /tmp > /dev/null
    4  history
```

*代码 7：每条命令前面的数字，是它在清单里的编号。*

这份清单里不只有当前这个终端里输入过的命令。Bash 启动时会先读入 `~/.bash_history`，所以以前会话里输入的命令也在里面。Ubuntu 默认的 `~/.bashrc` 里有几行设置，决定了历史记录的规则：

```bash
HISTCONTROL=ignoreboth    # 以空格开头的命令不记，与上一条相同的命令不记
shopt -s histappend       # 退出时追加到 ~/.bash_history，而不是覆盖
HISTSIZE=1000             # 内存里最多保留 1000 条
HISTFILESIZE=2000         # 文件里最多保留 2000 行
```

*代码 8：Ubuntu 默认的 `~/.bashrc` 中与历史记录相关的设置。*

其中有两点值得记住：

- **当前会话里的命令，要到退出时才会写进文件。** 在会话进行的过程中，`~/.bash_history` 里还没有这些命令；如果终端被直接关闭，没有正常退出，这些命令可能根本写不进去。
- **以空格开头的命令不会被记录到历史里。** 如果命令里带有密码之类的敏感信息，只要在最前面多输入一个空格就可以了。另外，连续输入两遍 `echo one`，历史里也只会留下一条。

当历史记录很长、一屏显示不下时，可以把它交给 [第二章](/2026/09/05/Linux-Command-Line-Chapter2/) 里 man 用来翻页的那个 `less`，写成 `history | less`。如果只想看最近的几条，也可以直接写一个数字，比如 `history 20` 就会显示最后 20 条。

### 6.1 `!编号`：重新执行，不是回放

知道了编号之后，用 `!` 加上编号，就可以再执行一次那条命令：

```bash
$ !2
date +%T.%N
14:19:50.628267300
$ !2
date +%T.%N
14:19:51.624028811
```

*代码 9：两次的输出并不相同。*

这里有三个细节需要注意：

- **`!` 和编号之间不能有空格。** `! 2` 在 Bash 里的含义完全不同，后面跟着空格的 `!` 表示把这条命令的执行结果取反，于是 Bash 会去寻找一个名叫 `2` 的命令，结果就是 `2: command not found`。
- **它会把那条命令重新运行一遍，而不是把当时的输出再显示一遍。** 代码 9 里两次得到的时间不同，就是证明。如果一条命令依赖于当时的状态（比如当前目录、文件内容或者时间），那么重新运行的结果完全可能不一样。
- **执行之前，它会先打印出展开后的命令**，历史里记录的也是展开后的 `date +%T.%N`，而不是 `!2`。

最常用的特殊写法是 `!!`，它代表上一条命令。比如忘记加 `sudo` 时，就可以输入 `sudo !!`。

### 6.2 Ctrl+R：边打边搜

按下 `Ctrl+R` 之后，提示符会变成下面这样：

```text
(reverse-i-search)`':
```

之后每输入一个字符，readline 就会从最近的历史记录开始往前查找，找到第一条包含这段文字的命令，并把它显示在冒号后面。这时可以进行的操作只有下面几种：

| 按键 | 作用 |
| --- | --- |
| 再按 `Ctrl+R` | 跳到更早的一条匹配 |
| `Enter` | **直接执行**这条命令 |
| `→` 或 `Ctrl+E` | 把它放到命令行上，改完再执行 |
| `Ctrl+G` | 放弃搜索，回到原来那一行 |

{% cast linux/ch6-ctrl-r 按下 Ctrl+R 输入 sort，再按两次 Ctrl+R 往更早翻；按 Ctrl+E 取出命令，光标落在行尾，补上 -r 后执行；最后按 Ctrl+G 放弃一次搜索 %}

如果已经找到了最早的一条，仍然没有匹配的命令，提示就会变成 `(failed reverse-i-search)`。需要注意的是，按下 `Enter` 会立刻执行命令，所以如果搜到的命令需要修改参数，应该先按 `→`。

如果搜索过了头，想往回找，自然会想到反方向的 `Ctrl+S`（向前搜索）。但是在大多数终端里，按下它之后，**屏幕就像卡死了一样，不再有任何反应**。这是因为 `Ctrl+S` 在到达 readline 之前，就先被终端当作流量控制中的「暂停输出」（XOFF）处理了。这时输入的按键其实仍然有效，只是看不到而已，**按下 `Ctrl+Q` 就能恢复**，暂停期间的输出也会一次性显示出来。只有执行一次 `stty -ixon`，关闭这个功能之后，`Ctrl+S` 才会变成向前搜索。

## 小结

| 想做的事 | 按键 / 命令 | 要点 |
| --- | --- | --- |
| 到行首 / 行尾 | `Ctrl+A` / `Ctrl+E` | A 是字母表开头，E 是 end |
| 按字符 / 按词移动 | `Ctrl+B` `Ctrl+F` / `Alt+B` `Alt+F` | `Alt+F` 停在词尾；Alt 被占用时用 `Esc` 加字母 |
| 删到行首 / 行尾 | `Ctrl+U` / `Ctrl+K` | 以光标为界，不是整行 |
| 删左边一个词 | `Ctrl+W` / `Alt+Backspace` | 前者以空格为界，后者以字母数字为界 |
| 删右边一个词 | `Alt+D`，`Ctrl+Delete` 相同 | 和 `Ctrl+W` 方向相反 |
| 贴回删掉的内容 | `Ctrl+Y`，再按 `Alt+Y` 换更早的 | 换一条命令也在，可以暂存半条命令 |
| 改相邻两个字符 | `Ctrl+T` | 行尾直接按 |
| 交换两个词 | `Alt+T` | 带 `.` `/` 的文件名会被拆开 |
| 清屏 | `Ctrl+L` | 保留当前行和回滚缓冲区；`clear` 两样都不保留 |
| 看历史 | `history`、`history 20`、`history \| less` | 退出时才写进 `~/.bash_history` |
| 重跑某一条 | `!42`、`!!` | 不能有空格；是重新执行，不是回放 |
| 搜历史 | `Ctrl+R` | `Enter` 立即执行，`→` 先编辑；屏幕卡住按 `Ctrl+Q` |

这一章的快捷键很多，但真正需要理解的只有两处。第一处是「词」有两种算法，`Ctrl+W` 只把空格当作边界，而 `Alt` 系列连 `/` 和 `.` 也当作分隔符。第二处是，这一章里的「删除」和「历史」都比字面意思宽松。删除的内容进入了剪切环，随时可以用 `Ctrl+Y` 取回来；历史里保存的是命令本身，所以每一次执行 `!编号`，都是把命令重新运行一遍。
