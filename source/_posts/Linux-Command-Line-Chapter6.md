[第五章](/2026/09/19/Linux-Command-Line-Chapter5/) 讲的是三条会造成不可逆后果的命令，这一章轻松得多：命令敲到一半，怎么快速挪光标、删掉一段、改个错字，以及怎么把以前敲过的命令找回来。

内容就是一串快捷键，逐个记并不难。但有几处和直觉不一样：同样叫「删一个词」的两个键，删掉的范围能差出一整段路径；`Ctrl+L` 和 `clear` 看起来一样，其实不一样；`!42` 也不会把当时的输出再放一遍。这一篇把这几处逐一拆开。

## 一、这些键是谁在处理

在 Bash 里敲命令时，负责「读这一行输入」的既不是终端，也不是 Bash 的主逻辑，而是一个叫 **GNU readline** 的库。这一章的快捷键全都属于它，键位沿用自 Emacs 编辑器：文档里写的 `C-a` 是 Ctrl+A，`M-f` 的 M 是 Meta，也就是现在键盘上的 Alt。

这件事有两个直接的推论：

- **别的程序只要也用了 readline，这些键就一样能用。** 比如 Python 的交互式解释器，`Ctrl+A`、`Ctrl+W` 的效果和在 Bash 里完全相同。
- **每个键都要先经过终端。** 有些键在到达 readline 之前就被截走了——第六节的 `Ctrl+S` 就是这样。Alt 组合键被终端软件占用时（比如 Alt+F 弹出了「文件」菜单），可以先按一下 `Esc` 再按字母，效果和 Alt+字母相同。

## 二、移动光标

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl+A` / `Ctrl+E` | 跳到行首 / 行尾 |
| `Ctrl+B` / `Ctrl+F` | 左移 / 右移一个字符 |
| `Alt+B` / `Alt+F` | 左移 / 右移一个词 |

字母都有来历：A 是字母表的开头，E 是 end，B 和 F 是 backward 和 forward。按词移动有两个细节值得看清楚：

![光标在 cd /usr/local/share/doc 上按不同的键会落在哪里](/img/posts/linux-shortcuts-history/move.svg)

*图 1：`Alt+B` 落在词首，`Alt+F` 落在词尾。*

第一，**`Alt+F` 停在当前词的末尾，而不是下一个词的开头。** 从 `share` 的开头按一下 `Alt+F`，光标落在 `share` 后面那个 `/` 上。

第二，**readline 眼里的「词」只由字母和数字组成。** `/`、`.`、`-` 都算分隔符，所以 `/usr/local/share/doc` 在它看来是四个词，从行尾按 `Alt+B` 要四下才能回到 `usr`。这一点到了删除的时候影响更大。

## 三、删除，其实是剪切

| 快捷键 | 删除范围 |
| --- | --- |
| `Ctrl+U` | 光标左边的全部内容 |
| `Ctrl+K` | 光标右边的全部内容 |
| `Ctrl+W` | 光标左边一个词（以空格为界） |
| `Alt+Backspace` | 光标左边一个词（以字母数字为界） |
| `Alt+D` | 光标右边一个词（以字母数字为界） |

`Ctrl+U` 和 `Ctrl+K` 以光标为界，一个删左边、一个删右边。所以**光标不在行尾时，`Ctrl+U` 并不会清空整行**，右边那部分会留下来。

### 3.1 两种「一个词」

表里有两个都叫「删左边一个词」的键，区别就在第二节说的那个定义上：

![同一行上，Ctrl+W、Alt+Backspace、Ctrl+U、Ctrl+K、Alt+D 各删掉哪一段](/img/posts/linux-shortcuts-history/kill.svg)

*图 2：`Ctrl+W` 以空格为界，`Alt` 系列以字母数字为界。*

```bash
$ cd /usr/local/share/doc█        # 光标在行尾
# Ctrl+W         →  $ cd █
# Alt+Backspace  →  $ cd /usr/local/share/█
```

*代码 1：同样是「删左边一个词」，结果差了一整段路径。*

`Ctrl+W` 只认空格，整个路径被当成一个词一次删掉；`Alt+Backspace` 用的是 readline 的定义，只删掉 `doc`。要改路径的最后一段用后者，整个参数都不要了用前者。

`Alt+D` 是 `Alt+Backspace` 的反方向，删光标右边的一个词。**`Ctrl+Delete` 在 Ubuntu 上绑定的也是这个功能**（readline 里叫 `kill-word`），同样是往右删，和往左删的 `Ctrl+W` 并不是一对：

```bash
$ bind -q kill-word
kill-word can be invoked via "\e[3;5~", "\ed".
```

*代码 2：`\e[3;5~` 是 Ctrl+Delete 发出的序列，`\ed` 是 Alt+D。*

### 3.2 Ctrl+Y：删掉的东西还在

用上面这些键删掉的内容并没有被丢弃，而是进了 readline 的**剪切环**（kill ring）。`Ctrl+Y` 把最近一次删掉的内容粘贴回光标处。

它有三个性质，让它比「撤销」有用得多：

- **连续的删除会合并成一次。** 连按两下 `Ctrl+W` 删掉 `alpha beta`，`Ctrl+Y` 会把两个词一起贴回来。
- **换一条命令也还在。** 剪切环属于这个 Shell，而不属于某一行。
- **更早的也能找回。** 按过 `Ctrl+Y` 之后紧接着按 `Alt+Y`，贴上去的内容会换成再早一次删掉的。

第二条带来一个很实用的用法：一条长命令敲到一半，发现得先确认点别的东西——

```bash
$ tar -czf backup.tgz notes█      # 敲到一半
# Ctrl+U                          → 整行剪走
$ ls /                            # 先办别的事
$ █
# Ctrl+Y                          → $ tar -czf backup.tgz notes█
```

*代码 3：`Ctrl+U` 先收起来，`Ctrl+Y` 再拿回来。*

## 四、交换两个字符、两个词

`Ctrl+T` 把光标前面的那个字符往后拖一位，和光标所在的字符交换，光标也跟着前进一格；**光标在行尾时，交换的是最后两个字符**。它最常见的用途就是改手误：

```bash
$ gti█        # Ctrl+T  →  $ git█
```

*代码 4：在行尾直接按，不用先挪光标。*

`Alt+T` 对词做同样的事：交换光标前后的两个词，在行尾时交换最后两个词。

```bash
$ mv dst src█            # Alt+T  →  $ mv src dst█
$ cp new.txt old.txt█    # Alt+T  →  $ cp new.txt txt.old█
```

*代码 5：第二行交换的是 `old` 和 `txt`。*

第二行又是「词」的定义在起作用：`old.txt` 在 readline 看来是 `old` 和 `txt` 两个词，被交换的是它们，而不是两个文件名。**参数里带 `.` 或 `/` 时，`Alt+T` 基本帮不上忙**——而 `mv`、`cp` 把源和目标写反，偏偏是最想用它的时候。

## 五、清屏：Ctrl+L 和 clear 不完全一样

两者都能把屏幕清空，区别在两个地方。

第一，**`Ctrl+L` 会保留正在输入的这一行。** 命令敲到一半想清屏，按下 `Ctrl+L` 后，这半行会原样出现在清空后的屏幕顶端；`clear` 本身是一条命令，要执行它，这一行就只能先让给它。

第二，**`clear` 还会清掉回滚缓冲区，`Ctrl+L` 不会。** 两者发给终端的字节差了一段：

```text
Ctrl+L  →  \e[H \e[2J           光标回左上角，清空屏幕
clear   →  \e[H \e[2J \e[3J     再加一段：清空回滚缓冲区
```

*代码 6：`\e[3J` 是 xterm 系终端「清除滚动历史」的控制序列。*

实际效果是：先输出 60 行，按 `Ctrl+L` 之后往上滚，这 60 行都还在；执行 `clear` 之后，它们从滚动历史里也消失了。想清屏又想留着往上翻的余地，用 `Ctrl+L`，或者 `clear -x`（`-x` 就是不动回滚缓冲区）。

## 六、history：一份清单，不是录像

```bash
$ history
    1  echo one
    2  date +%T.%N
    3  ls /tmp > /dev/null
    4  history
```

*代码 7：每条命令前面是它在清单里的编号。*

这份清单不只有当前这个终端里敲过的命令。Bash 启动时会先读入 `~/.bash_history`，所以以前会话里的命令也在里面。Ubuntu 默认的 `~/.bashrc` 里有几行决定了它的规则：

```bash
HISTCONTROL=ignoreboth    # 以空格开头的命令不记，与上一条相同的命令不记
shopt -s histappend       # 退出时追加到 ~/.bash_history，而不是覆盖
HISTSIZE=1000             # 内存里最多保留 1000 条
HISTFILESIZE=2000         # 文件里最多保留 2000 行
```

*代码 8：Ubuntu 默认 `~/.bashrc` 中与历史相关的设置。*

其中两点值得记住：

- **当前会话的命令在退出时才写进文件。** 会话进行中，`~/.bash_history` 里还没有这些命令；终端被直接关掉、没有正常退出时，它们可能根本写不进去。
- **以空格开头的命令不会进历史。** 命令里带了密码之类的东西，在最前面多敲一个空格即可。连着敲两遍 `echo one`，历史里也只会有一条。

历史一长，一屏放不下，就交给 [第二章](/2026/09/05/Linux-Command-Line-Chapter2/) 里 man 用来翻页的那个 `less`：`history | less`。只想看最近几条，可以直接写数字，`history 20` 就是最后 20 条。

### 6.1 `!编号`：重新执行，不是回放

看到编号之后，`!` 加编号就能再执行一次那条命令：

```bash
$ !2
date +%T.%N
14:19:50.628267300
$ !2
date +%T.%N
14:19:51.624028811
```

*代码 9：两次的输出不同。*

这里有三个细节：

- **`!` 和编号之间不能有空格。** `! 2` 在 Bash 里是另一回事——后面跟空格的 `!` 表示「把这条命令的成败取反」，于是 Bash 会去找一个叫 `2` 的命令，结果是 `2: command not found`。
- **它是把那条命令重新跑一遍，不是把当时的输出再放一遍。** 代码 9 里两次得到的时间不同就是证据。依赖当时状态的命令（当前目录、文件内容、时间），重跑的结果完全可能不一样。
- **执行前会先打印展开后的命令**，历史里记下的也是展开后的 `date +%T.%N`，而不是 `!2`。

最常用的特例是 `!!`，代表上一条命令，比如忘了加 `sudo` 时的 `sudo !!`。

### 6.2 Ctrl+R：边打边搜

按下 `Ctrl+R`，提示符会变成：

```text
(reverse-i-search)`':
```

之后每敲一个字符，readline 就从最近的历史往前找第一条包含这段文字的命令，显示在冒号后面。能做的操作只有几个：

| 按键 | 作用 |
| --- | --- |
| 再按 `Ctrl+R` | 跳到更早的一条匹配 |
| `Enter` | **直接执行**这条命令 |
| `→` 或 `Ctrl+E` | 把它放到命令行上，改完再执行 |
| `Ctrl+G` | 放弃搜索，回到原来那一行 |

找到最早一条还没有匹配时，提示会变成 `(failed reverse-i-search)`。要注意 `Enter` 是立刻执行的，搜到的命令如果需要改参数，先按 `→`。

搜过了头想往回找，很自然会想到反方向的 `Ctrl+S`（向前搜索）。但在大多数终端里按下去，**屏幕会像卡死了一样不再有任何反应**。这是因为 `Ctrl+S` 在到达 readline 之前，先被终端当成了流量控制里的「暂停输出」（XOFF）。此时敲的键其实照样在生效，只是看不到；**按 `Ctrl+Q` 就能恢复**，暂停期间的输出会一次性出现。执行一次 `stty -ixon` 关掉这个功能之后，`Ctrl+S` 才会变成向前搜索。

## 小结

| 想做的事 | 按键 / 命令 | 要点 |
| --- | --- | --- |
| 到行首 / 行尾 | `Ctrl+A` / `Ctrl+E` | A 是字母表开头，E 是 end |
| 按字符 / 按词移动 | `Ctrl+B` `Ctrl+F` / `Alt+B` `Alt+F` | `Alt+F` 停在词尾；Alt 被占用时用 `Esc` 加字母 |
| 删到行首 / 行尾 | `Ctrl+U` / `Ctrl+K` | 以光标为界，不是整行 |
| 删左边一个词 | `Ctrl+W` / `Alt+Backspace` | 前者以空格为界，后者以字母数字为界 |
| 删右边一个词 | `Alt+D`，`Ctrl+Delete` 相同 | 和 `Ctrl+W` 方向相反 |
| 贴回删掉的内容 | `Ctrl+Y`，再按 `Alt+Y` 换更早的 | 换一条命令也在，可以暂存半条命令 |
| 改相邻两个字符 | `Ctrl+T` | 行尾直接按 |
| 交换两个词 | `Alt+T` | 带 `.` `/` 的文件名会被拆开 |
| 清屏 | `Ctrl+L` | 保留当前行和回滚缓冲区；`clear` 两样都不保留 |
| 看历史 | `history`、`history 20`、`history \| less` | 退出时才写进 `~/.bash_history` |
| 重跑某一条 | `!42`、`!!` | 不能有空格；是重新执行，不是回放 |
| 搜历史 | `Ctrl+R` | `Enter` 立即执行，`→` 先编辑；屏幕卡住按 `Ctrl+Q` |

这一章的键很多，真正需要理解的只有两处。一是「词」有两种算法：`Ctrl+W` 只认空格，`Alt` 系列连 `/` 和 `.` 都当作分隔。二是这一章里的「删除」和「历史」都比字面意思宽松：删掉的内容进了剪切环，随时能用 `Ctrl+Y` 取回；历史里存的是命令本身，每一次 `!编号` 都是重新执行。
