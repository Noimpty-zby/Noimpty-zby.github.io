[第六章](/2026/09/26/Linux-Command-Line-Chapter6/) 讲的是怎样编辑命令行，这一章回到文件本身，讲的是不打开编辑器，只把文件的内容看一遍。[第四章](/2026/09/19/Linux-Command-Line-Chapter4/) 介绍的 nano 也能查看文件，但它毕竟是编辑器，手一滑就可能改动了内容。而这一章的八条命令全都是**只读**的，它们读取文件，把结果打印到屏幕上，文件本身一个字节都不会改变。比如 `sort` 排好了顺序，文件里的内容仍然是原来的顺序。

按照用途，这些命令可以分成三组。第一组是查看整个文件（`cat`、`less`），第二组是只查看一部分（`head`、`tail`），第三组是在查看的同时做一些处理（`tac`、`rev`、`wc`、`sort`）。大多数用法一看就懂，值得多停留一下的有三处，分别是 `sort` 中大小写的先后顺序、`sort -k` 到底比较的是哪一段，以及文件被改写之后 `tail -f` 会有什么表现。

## 一、cat：整份打印出来

```bash
cat notes.txt                 # 把整个文件打印到屏幕上
cat part1.txt part2.txt       # 按顺序一个接一个打印，中间不加任何分隔
cat -n notes.txt              # 每行前面加上行号
```

*代码 1：`cat` 的三种常见写法。*

`cat` 这个名字来自 concatenate（连接），它本来的作用是把几个文件首尾相接地输出，只查看一个文件是它最简单的用法。如果给了多个文件，即使其中一个不存在，整条命令也不会停下来，而是在报错之后接着打印后面的文件：

```bash
$ cat a.txt missing.txt b.txt
this is a
cat: missing.txt: No such file or directory
this is b
```

*代码 2：出错的只是中间那一个文件。*

`cat` 的问题在于它不会分页。如果文件有几千行，前面的内容一下子就滚出了屏幕，这时就应该换成 `less`。

## 二、less：一页一页地读

[第二章](/2026/09/05/Linux-Command-Line-Chapter2/) 介绍的 man 手册，在背后负责显示内容的就是 `less`，所以两者的翻页键完全一样。空格或 `f` 向后翻页，`b` 向前翻页，`/` 用来搜索，`n` 和 `N` 分别跳到下一个和上一个搜索结果，`g` 和 `G` 分别跳到开头和结尾，`h` 用来查看按键说明。`less 文件名` 只是把它直接用在了文件上。

有两点要在直接打开文件时才能看出来：

- **最下面一行显示的是状态。** 刚打开文件时，这一行显示文件名；翻动之后，它会变成一个冒号 `:`；翻到末尾时，它会显示 `(END)`。
- **`q` 是最先要记住的键。** 不知道怎么退出时，按 `q` 几乎总能退出。不过在按 `h` 打开的帮助页里，按 `q` 只是回到正文，要再按一次才会退出 `less`。

`less` 这个名字其实是一个玩笑。更早的分页程序叫作 `more`，它只能向后翻页；而 `less` 前后都可以翻，正所谓 less is more。

## 三、tac 和 rev：倒过来

```bash
$ cat t.txt
one
two
three
$ tac t.txt
three
two
one
$ rev t.txt
eno
owt
eerht
```

*代码 3：`tac` 把行的顺序倒过来，`rev` 把每一行里的字符倒过来。*

`tac` 就是把 `cat` 倒过来拼写。`rev` 是按「字符」翻转的，所以中文也能正确地倒过来，比如 `你好 世界` 会变成 `界世 好你`。不过这有一个前提，那就是当前的 locale（语言环境）必须是 UTF-8。在 `LC_ALL=C` 的环境下，它不认识多字节字符，会报出 `Invalid or incomplete multibyte or wide character` 的错误。第六节还会再遇到 locale，而且那时它的影响更大。

## 四、head 和 tail：只看开头或结尾

这两条命令默认都显示 10 行：

```bash
head notes.txt              # 前 10 行
head -n 30 notes.txt        # 前 30 行
head -30 notes.txt          # 同上，老式写法
head --lines=30 notes.txt   # 同上，长选项
tail -n 5 notes.txt         # 最后 5 行
```

*代码 4：`-n 30`、`-30` 和 `--lines=30` 表示的是同一个意思。*

这个长选项的正式名字是 `--lines`。写成 `--line 30` 也能用，这是因为 GNU 的命令接受长选项的**无歧义缩写**。由于 `--line` 和 `--li` 都只可能是 `--lines`，所以它们会被当作 `--lines` 来处理。

如果在数字前面加上一个符号，意思就变了：

| 写法 | 意思 |
| --- | --- |
| `head -n 30` | 前 30 行 |
| `head -n -5` | 除了最后 5 行，其余全部 |
| `tail -n 5` | 最后 5 行 |
| `tail -n +2` | 从第 2 行开始一直到结尾（跳过第一行的表头时很常用） |

`-c` 选项是按字节而不是按行来截取的，比如 `head -c 100`。对于英文来说，一个字节就是一个字符，但对于中文来说就不是这样了。在 UTF-8 编码里，一个汉字占 3 个字节，所以 `head -c 4` 截取到的是「你」字加上「好」字的第一个字节，终端上就会出现半个乱码字符。

如果同时给出多个文件，每一段内容前面都会加上 `==> 文件名 <==` 这样的标题，加上 `-q` 选项就可以去掉这些标题。

### 4.1 tail -f：盯着文件的结尾

`tail -f` 在打印完最后 10 行之后并不会退出，而是会一直等待。文件末尾每多出一行，屏幕上也会跟着多出一行。这种用法在查看不断增长的日志时最为常用，按 `Ctrl+C` 就可以结束。

「文件一变化，它就跟着变化」这句话，只有在文件被**追加**内容时才完全成立。如果文件被其他方式改写了，就要看 `tail` 有没有观察到文件变短，以及文件名是否换成了指向别的文件：

| 文件怎么变的 | 例子 | `tail -f` 的反应 |
| --- | --- | --- |
| 在末尾追加 | 程序往日志里写了一行 | 正常跟上 |
| 检测到原文件变短 | 截断日志后，`tail` 观察到文件大小缩小 | 提示 `file truncated`，从头继续读取 |
| 原地覆盖，但没有检测到变短 | 将一行替换为相同字节数的内容 | 可能完全没有新输出，不会自动重印被覆盖的内容 |
| 写一个新文件，再把名字换过去 | `sed -i` 这类命令 | 仍跟着旧文件，**不会跟上新文件的内容** |

所以，不能仅仅因为用 nano 保存了一次，就断定一定会看到 `file truncated` 的提示，这取决于 `tail` 有没有检测到文件变小。即使写入的过程中文件曾经被短暂地截断过，但是如果在 `tail` 下一次检查之前，文件又被写回了相同或者更大的长度，`tail` 也可能观察不到这个中间状态。

最后一种情况最容易让人以为 `tail` 卡住了。要理解它的原因，需要回到[第五章](/2026/09/19/Linux-Command-Line-Chapter5/)的结论，**文件名和文件是两回事**。`sed -i` 并不会在原文件上直接修改，而是先写出一个新文件，再把 `log.txt` 这个名字转移到新文件上。`tail -f` 一开始打开的就是旧文件本身，所以在名字被转移走之后，它仍然守着那个已经没有名字的旧文件，新文件里写了什么，它都看不到。

![sed -i 之后，tail -f 还开着旧文件，tail -F 按名字找到了新文件](/img/posts/linux-view-files/follow.svg)

*图 1：`-f` 跟踪的是打开时的那个文件，`-F` 跟踪的是文件名。*

如果换成大写的 `tail -F`，就能跟上新文件。它会按照文件名重新查找，当发现这个名字指向了另一个文件时，它会提示 `'log.txt' has been replaced; following new file`，然后接着跟踪新文件。文件被删除、过一会儿又重新出现时，它也能正确处理（依次提示 `has become inaccessible` 和 `has appeared`）。所以在查看日志时，使用 `-F` 更加稳妥。

## 五、wc：数行、词和字节

```bash
$ wc fruits.txt
 5  5 33 fruits.txt
```

*代码 5：三个数字依次是行数、单词数和字节数。*

| 选项 | 只输出 |
| --- | --- |
| `-l` | 行数 |
| `-w` | 单词数（以空白分隔） |
| `-m` | 字符数 |
| `-c` | 字节数 |

这几个选项可以一起使用，但是输出的顺序固定为「行、词、字符、字节」，和选项书写的先后顺序无关，比如 `wc -wl` 的输出仍然是行数在前。如果给出多个文件，最后还会多出一行 `total`，表示总计。

这里有两处需要看清楚。

**第一，`-l` 统计的是换行符的个数，而不是「行」的个数。** 如果最后一行的末尾没有换行符，这一行就不会被计算在内：

```bash
$ printf 'hello world\nsecond line' > nonl.txt   # 两行，第二行末尾没有换行
$ wc -l nonl.txt
1 nonl.txt
```

*代码 6：这里的 `>` 是下一章要讲的重定向，用来生成一个结尾没有换行符的文件。*

nano 保存文件时会自动在末尾补上一个换行符，所以用它写出来的文件不会有这个问题，但是其他程序生成的文件就不一定了。

**第二，`-m` 和 `-c` 在处理中文时结果不同，而且 `-m` 的结果取决于 locale：**

```bash
$ wc -m -c zh.txt            # 内容是「你好 世界」和一个换行
 6 14 zh.txt
$ LC_ALL=C wc -m zh.txt
14 zh.txt
```

*代码 7：4 个汉字各占 3 个字节，再加上空格和换行符，一共是 14 个字节。*

在 UTF-8 的 locale 下，统计的结果是 6 个字符；如果换成 `C`，`wc` 就不再认识多字节字符了，所以一个字节就会被当作一个字符。

## 六、sort：排序

`sort` 会按行排序，然后输出结果，**原文件不会改变**。它比较的是整行的内容，先比较第一个字符，如果相同，再比较第二个字符，以此类推，并不是只看首字母。

### 6.1 大小写谁在前，看 locale

同一个文件，在两台机器上排序的结果可能不一样：

```bash
$ LC_ALL=C.UTF-8 sort fruits.txt
Apple
Banana
apple
banana
cherry
$ LC_ALL=en_US.UTF-8 sort fruits.txt
apple
Apple
banana
Banana
cherry
```

*代码 8：同一个文件的两种排序结果（第二种要求机器上安装了 `en_US.UTF-8`）。*

`C` 这一类 locale 是按照字符的编码排序的，所以所有的大写字母（`A` 的编码是 65）都排在所有的小写字母（`a` 的编码是 97）前面。而 `en_US.UTF-8` 这一类语言 locale 则是按照词典的习惯排序的，先不区分大小写地比较字母，只有当字母相同时，才让小写字母排在前面。

**所以「小写字母在前」这个结论，只在后一种 locale 下才成立。** 很多服务器和容器默认使用的是 `C.UTF-8`，而桌面系统上常见的是 `en_US.UTF-8` 或 `zh_CN.UTF-8`。要查看当前使用的是哪一种，可以看 `locale` 命令输出中 `LC_COLLATE` 那一行。如果只是想不区分大小写地排序，可以加上 `-f`（fold case）选项，这样大小写不同的同一个词就会排在一起：

```bash
$ sort -f fruits.txt
Apple
apple
Banana
banana
cherry
```

*代码 9：`-f` 会把大写和小写当成同样的字母。至于 `Apple` 和 `apple` 谁排在前面，仍然由 locale 决定。*

### 6.2 数字：-n，以及 -r 要和谁一起用

```bash
$ sort nums.txt
10
100
2
33
9
$ sort -n nums.txt
2
9
10
33
100
```

*代码 10：如果不加 `-n`，数字也会被当成一串字符来比较。*

不加 `-n` 时，`100` 的第一个字符 `1` 比 `2` 小，所以 `100` 会排在 `2` 的前面。只有加上 `-n`，才会按照数值的大小来排序。

`-r` 的作用是把**当前的**排序结果反过来，它自己并不知道内容是不是数字：

```bash
$ sort -r nums.txt
9
33
2
100
10
$ sort -nr nums.txt
100
33
10
9
2
```

*代码 11：如果只写 `-r`，得到的是按字符顺序排列后的倒序。*

所以要让数字从大到小排列，应该写成 `-nr`（写成 `-rn` 也是一样的）。

### 6.3 -u：排序的同时去掉重复

`-u`（unique）选项会在排序的同时去掉重复的行，每一种内容只保留一行。比如文件里依次是 `b a b c a` 这五行，`sort -u` 就会输出 `a`、`b`、`c` 三行。

### 6.4 -k：按某一列排

当每一行都有好几列时（默认以空白来分隔列），可以用 `-k` 来指定按照哪一列排序。下面用这个文件来举例：

```text
alice 30 beijing
bob 5 shanghai
carol 30 aomen
dave 120 chengdu
```

`-k2` 从字面上看，好像是「按照第 2 列排序」，但实际上它的意思是**从第 2 列开始，一直比较到行尾**。如果只想比较第 2 列，要写成 `-k2,2`，意思是「从第 2 列开始，到第 2 列结束」。如果这一列是数字，还要再加上 `n`：

![sort -k2、-k2,2、-k2,2n 各自比较的部分和排序结果](/img/posts/linux-view-files/sort-keys.svg)

*图 2：同一个文件的三种排序方式，带下划线的部分是用来比较的内容。*

这张图里有三处值得看清楚：

- **对于 `30` 相同的两行，前两种排序方式给出的先后顺序不一样。** 使用 `-k2` 时，比较的范围还没有结束，所以会接着比较城市名，因为 `aomen` 排在 `beijing` 前面，所以 carol 排在前面。而使用 `-k2,2` 时，比较的范围已经结束了，`sort` 最后会拿整行再比较一次，所以 alice 排在前面。
- **在前两种排序方式里，`120` 都排在最前面。** 这仍然是因为按字符比较的缘故，`1` 比 `3` 和 `5` 都小。如果要按照数值大小排序，应该写成 `-k2,2n`。
- **排序条件可以接着往后写。** 比如 `sort -k2,2n -k3,3` 表示先按照第 2 列的数值排序，数值相同的行，再按照第 3 列排序。

如果分隔列的不是空格，而是别的符号（比如逗号），就要用 `-t` 来指定分隔符，比如 `sort -t, -k2,2n scores.csv`。如果拿不准 `-k` 到底比较的是哪一段，可以加上 `--debug` 选项，`sort` 会在每一行下面标出它实际比较的部分。

## 小结

| 想做的事 | 命令 | 要点 |
| --- | --- | --- |
| 整份打印 | `cat 文件` | 多个文件首尾相连；`-n` 加行号 |
| 分页阅读 | `less 文件` | 键和 man 里一样；`q` 退出 |
| 倒过来 | `tac` / `rev` | 倒行的顺序 / 倒每一行的字符；`rev` 要 UTF-8 locale 才认得中文 |
| 看开头 / 结尾 | `head -n 30` / `tail -n 5` | `head -n -5` 去掉最后 5 行，`tail -n +2` 从第 2 行起；`-c` 按字节，会切坏汉字 |
| 盯着日志 | `tail -F` | `-f` 跟文件，`-F` 跟名字；文件被换掉时只有 `-F` 跟得上 |
| 计数 | `wc -l` `-w` `-m` `-c` | `-l` 数的是换行符；`-m` 的字符数看 locale |
| 排序 | `sort` | 原文件不变；大小写谁在前看 locale，`-f` 忽略大小写 |
| 按数字排 | `sort -n`，倒序 `sort -nr` | 只写 `-r` 得到的是字符顺序的倒序 |
| 去重 | `sort -u` | 每种只留一行 |
| 按列排 | `sort -k2,2n` | `-k2` 是从第 2 列比到行尾；`-t,` 换分隔符 |

这一章的命令都很短，真正需要记住的是两件事。第一，**同一条命令的结果会随着环境而变化**。locale 决定了 `sort` 中大小写的先后顺序、`wc -m` 能数出几个字符，以及 `rev` 能不能正确处理中文。所以当排序的结果和预想的不一样时，应该先看一眼 `locale`。第二，第五章的那条结论「名字和文件是两回事」在这里又出现了一次，`tail -f` 跟踪的是文件本身，所以当名字被转移走时，它并不会察觉。

这八条命令的结果都只会显示在屏幕上。下一章讲[重定向，也就是怎样把这些结果保存到文件里，或者让命令从文件中读取输入](/2026/09/28/Linux-Command-Line-Chapter8/)。
