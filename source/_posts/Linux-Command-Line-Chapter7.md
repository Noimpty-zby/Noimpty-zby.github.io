[第六章](/2026/09/26/Linux-Command-Line-Chapter6/) 讲的是怎么编辑命令行，这一章回到文件本身：不打开编辑器，只把内容看一遍。[第四章](/2026/09/19/Linux-Command-Line-Chapter4/) 的 nano 也能看文件，但它是编辑器，手一滑就改了；这一章的八条命令全都**只读**——读文件、把结果打印到屏幕上，文件本身一个字节都不动。`sort` 排好了序，文件里还是原来的顺序。

按用途可以分成三组：整份看（`cat`、`less`），只看一部分（`head`、`tail`），看的同时加工一下（`tac`、`rev`、`wc`、`sort`）。大多数用法一看就懂，值得多停一下的是三处：`sort` 的大小写顺序、`sort -k` 到底比哪一段，以及 `tail -f` 在文件被改写之后会怎样。

## 一、cat：整份打印出来

```bash
cat notes.txt                 # 把整个文件打印到屏幕上
cat part1.txt part2.txt       # 按顺序一个接一个打印，中间不加任何分隔
cat -n notes.txt              # 每行前面加上行号
```

*代码 1：`cat` 的三种常见写法。*

名字来自 concatenate（连接）：它的本职是把几个文件首尾相连地输出，只看一个文件是它最简单的用法。给了多个文件时，其中一个不存在也不会让整条命令停下，报完错接着打印后面的：

```bash
$ cat a.txt missing.txt b.txt
this is a
cat: missing.txt: No such file or directory
this is b
```

*代码 2：出错的只是中间那一个。*

`cat` 的问题是不分页。文件有几千行时，前面的内容一下子就滚出了屏幕，这时换 `less`。

## 二、less：一页一页地读

[第二章](/2026/09/05/Linux-Command-Line-Chapter2/) 的 man 手册，背后显示内容的就是 `less`，翻页键完全一样：空格或 `f` 往后翻、`b` 往前翻、`/` 搜索、`n` / `N` 跳到下一个 / 上一个结果、`g` / `G` 到开头 / 结尾、`h` 看按键说明。`less 文件名` 只是把它直接用在文件上。

有两点是直接打开文件时才看得出来的：

- **最下面一行是状态。** 刚打开时显示文件名，翻动之后变成一个冒号 `:`，到了末尾显示 `(END)`。
- **`q` 是最先要记住的键。** 不知道怎么出来时，`q` 几乎总能退出；在 `h` 的帮助页里按 `q` 是回到正文，再按一次才退出 `less`。

名字是个玩笑：更早的分页程序叫 `more`，只能往后翻；`less` 前后都能翻，所谓 less is more。

## 三、tac 和 rev：倒过来

```bash
$ cat t.txt
one
two
three
$ tac t.txt
three
two
one
$ rev t.txt
eno
owt
eerht
```

*代码 3：`tac` 把行的顺序倒过来，`rev` 把每一行里的字符倒过来。*

`tac` 就是 `cat` 反着拼。`rev` 按「字符」翻转，中文也能正确倒过来：`你好 世界` 会变成 `界世 好你`。前提是当前的 locale（语言环境）是 UTF-8 的；在 `LC_ALL=C` 下它不认识多字节字符，会报 `Invalid or incomplete multibyte or wide character`。locale 在第六节还会再出现，而且影响更大。

## 四、head 和 tail：只看开头或结尾

两条命令默认都是 10 行：

```bash
head notes.txt              # 前 10 行
head -n 30 notes.txt        # 前 30 行
head -30 notes.txt          # 同上，老式写法
head --lines=30 notes.txt   # 同上，长选项
tail -n 5 notes.txt         # 最后 5 行
```

*代码 4：`-n 30`、`-30`、`--lines=30` 是同一个意思。*

长选项的正式名字是 `--lines`。写成 `--line 30` 也能用，那是因为 GNU 的命令接受长选项的**无歧义缩写**：`--line`、`--li` 都只可能是 `--lines`，就被当成了它。

数字前面加一个符号，意思就变了：

| 写法 | 意思 |
| --- | --- |
| `head -n 30` | 前 30 行 |
| `head -n -5` | 除了最后 5 行，其余全部 |
| `tail -n 5` | 最后 5 行 |
| `tail -n +2` | 从第 2 行开始一直到结尾（跳过第一行的表头时很常用） |

`-c` 按字节而不是按行取，比如 `head -c 100`。对英文来说一个字节就是一个字符，对中文不是：UTF-8 里一个汉字占 3 个字节，`head -c 4` 取到的是「你」再加上「好」的第一个字节，终端上会出现半个乱码字符。

同时给多个文件时，每一段前面会加上 `==> 文件名 <==` 这样的标题，加 `-q` 可以去掉。

### 4.1 tail -f：盯着文件的结尾

`tail -f` 打印完最后 10 行之后不退出，而是一直等着：文件末尾每多出一行，屏幕上就跟着多一行。看不断增长的日志时最常用，按 `Ctrl+C` 结束。

「文件一变它就跟着变」只对**追加**完全成立。文件被别的方式改写时，结果分三种：

| 文件怎么变的 | 例子 | `tail -f` 的反应 |
| --- | --- | --- |
| 在末尾追加 | 程序往日志里写了一行 | 正常跟上 |
| 在原文件上重写 | 用 nano 改完保存 | 提示 `file truncated`，把新内容从头再打印一遍 |
| 写一个新文件，再把名字换过去 | `sed -i` 这类命令 | **从此不再有任何输出** |

第三种最容易让人以为 `tail` 卡住了。原因要回到[第五章](/2026/09/19/Linux-Command-Line-Chapter5/)的结论：**文件名和文件是两回事。** `sed -i` 不在原文件上改，而是写出一个新文件，再把 `log.txt` 这个名字挪到新文件上。`tail -f` 一开始打开的就是旧文件本身，名字挪走之后，它仍然守着那个已经没有名字的旧文件，新文件里写了什么它看不到。

![sed -i 之后，tail -f 还开着旧文件，tail -F 按名字找到了新文件](/img/posts/linux-view-files/follow.svg)

*图 1：`-f` 跟的是打开时的那个文件，`-F` 跟的是名字。*

换成大写的 `tail -F` 就能跟上：它会按名字重新去找，发现名字指向了另一个文件时，提示 `'log.txt' has been replaced; following new file`，然后接着跟新文件。文件被删掉、过一会儿又重新出现时也一样（依次提示 `has become inaccessible` 和 `has appeared`）。所以盯日志时 `-F` 更稳妥。

## 五、wc：数行、词和字节

```bash
$ wc fruits.txt
 5  5 33 fruits.txt
```

*代码 5：三个数依次是行数、单词数、字节数。*

| 选项 | 只输出 |
| --- | --- |
| `-l` | 行数 |
| `-w` | 单词数（以空白分隔） |
| `-m` | 字符数 |
| `-c` | 字节数 |

几个选项可以一起用，但输出的顺序固定是「行、词、字符、字节」，和选项写的先后无关，`wc -wl` 照样是行数在前。给多个文件时，最后还会多一行 `total`。

有两处要看清楚。

**`-l` 数的是换行符，不是「行」。** 最后一行后面如果没有换行符，它就不算：

```bash
$ printf 'hello world\nsecond line' > nonl.txt   # 两行，第二行末尾没有换行
$ wc -l nonl.txt
1 nonl.txt
```

*代码 6：`>` 是下一章的重定向，这里用来造一个结尾不带换行的文件。*

nano 保存时会自动在末尾补一个换行，所以用它写的文件不会有这个问题；别的程序生成的文件就不一定了。

**`-m` 和 `-c` 在中文上不一样，而且 `-m` 的结果取决于 locale：**

```bash
$ wc -m -c zh.txt            # 内容是「你好 世界」和一个换行
 6 14 zh.txt
$ LC_ALL=C wc -m zh.txt
14 zh.txt
```

*代码 7：4 个汉字各占 3 个字节，加上空格和换行，一共 14 个字节。*

在 UTF-8 的 locale 下它是 6 个字符；换成 `C`，`wc` 不再认识多字节字符，一个字节就算一个字符。

## 六、sort：排序

`sort` 按行排序后输出，**原文件不变**。它比较的是整行：先比第一个字符，相同再比第二个，依此类推，并不是只看首字母。

### 6.1 大小写谁在前，看 locale

同一个文件，在两台机器上排出来可能不一样：

```bash
$ LC_ALL=C.UTF-8 sort fruits.txt
Apple
Banana
apple
banana
cherry
$ LC_ALL=en_US.UTF-8 sort fruits.txt
apple
Apple
banana
Banana
cherry
```

*代码 8：同一个文件的两种排法（第二种要求机器上装了 `en_US.UTF-8`）。*

`C` 一类的 locale 按字符的编码排，所有大写字母（`A` 是 65）都排在所有小写字母（`a` 是 97）前面；`en_US.UTF-8` 这类语言 locale 按词典的习惯排，先不分大小写地比字母，字母相同时才让小写在前。

**所以「小写在前」只在后一种 locale 下成立。** 很多服务器和容器默认是 `C.UTF-8`，桌面系统常见的是 `en_US.UTF-8` 或 `zh_CN.UTF-8`。当前用的是哪一种，看 `locale` 命令输出里 `LC_COLLATE` 那一行。只想不分大小写地排，加 `-f`（fold case），大小写不同的同一个词就会排到一起：

```bash
$ sort -f fruits.txt
Apple
apple
Banana
banana
cherry
```

*代码 9：`-f` 把大小写当成一样的字母。`Apple` 和 `apple` 之间谁先，仍然由 locale 决定。*

### 6.2 数字：-n，以及 -r 要和谁一起用

```bash
$ sort nums.txt
10
100
2
33
9
$ sort -n nums.txt
2
9
10
33
100
```

*代码 10：不加 `-n`，数字也被当成一串字符来比。*

不加 `-n` 时，`100` 的第一个字符 `1` 比 `2` 小，所以排在 `2` 前面。加上 `-n`，才按数值大小排。

`-r` 是把**当前的**排序结果反过来，它自己并不知道内容是数字：

```bash
$ sort -r nums.txt
9
33
2
100
10
$ sort -nr nums.txt
100
33
10
9
2
```

*代码 11：只写 `-r`，得到的是字符顺序的倒序。*

想要数字从大到小，要写 `-nr`（写成 `-rn` 也一样）。

### 6.3 -u：排序的同时去掉重复

`-u`（unique）在排序时把重复的行去掉，每种只留一行。文件里是 `b a b c a` 五行时，`sort -u` 输出 `a`、`b`、`c` 三行。

### 6.4 -k：按某一列排

每一行有好几列时（默认以空白分列），`-k` 指定按哪一列排。拿这个文件举例：

```text
alice 30 beijing
bob 5 shanghai
carol 30 aomen
dave 120 chengdu
```

`-k2` 字面看是「按第 2 列」，其实是**从第 2 列开始，一直比到行尾**。只比第 2 列要写 `-k2,2`，意思是「从第 2 列开始，到第 2 列结束」。数字列还要再加 `n`：

![sort -k2、-k2,2、-k2,2n 各自比较的部分和排序结果](/img/posts/linux-view-files/sort-keys.svg)

*图 2：同一个文件的三种排法，下划线是拿来比较的部分。*

图里有三处值得看清：

- **`30` 相同的两行，前两种排法分出的先后不一样。** `-k2` 的比较范围还没结束，接着比城市，`aomen` 在 `beijing` 前面，所以 carol 在前；`-k2,2` 的范围已经比完，`sort` 最后拿整行再比一次，alice 在前。
- **前两种里 `120` 都排在最前面。** 还是按字符比的缘故，`1` 比 `3` 和 `5` 都小。要按大小排，写 `-k2,2n`。
- **条件可以接着写。** `sort -k2,2n -k3,3` 表示先按第 2 列的数值排，数值相同的再按第 3 列排。

分隔列的不是空格而是别的符号时（比如逗号），用 `-t` 指定：`sort -t, -k2,2n scores.csv`。拿不准 `-k` 到底比了哪一段，可以加 `--debug`，`sort` 会在每一行下面画出它实际比较的部分。

## 小结

| 想做的事 | 命令 | 要点 |
| --- | --- | --- |
| 整份打印 | `cat 文件` | 多个文件首尾相连；`-n` 加行号 |
| 分页阅读 | `less 文件` | 键和 man 里一样；`q` 退出 |
| 倒过来 | `tac` / `rev` | 倒行的顺序 / 倒每一行的字符；`rev` 要 UTF-8 locale 才认得中文 |
| 看开头 / 结尾 | `head -n 30` / `tail -n 5` | `head -n -5` 去掉最后 5 行，`tail -n +2` 从第 2 行起；`-c` 按字节，会切坏汉字 |
| 盯着日志 | `tail -F` | `-f` 跟文件，`-F` 跟名字；文件被换掉时只有 `-F` 跟得上 |
| 计数 | `wc -l` `-w` `-m` `-c` | `-l` 数的是换行符；`-m` 的字符数看 locale |
| 排序 | `sort` | 原文件不变；大小写谁在前看 locale，`-f` 忽略大小写 |
| 按数字排 | `sort -n`，倒序 `sort -nr` | 只写 `-r` 得到的是字符顺序的倒序 |
| 去重 | `sort -u` | 每种只留一行 |
| 按列排 | `sort -k2,2n` | `-k2` 是从第 2 列比到行尾；`-t,` 换分隔符 |

这一章的命令都很短，真正需要记住的是两件事。一是**同一条命令的结果会随环境变**：locale 决定了 `sort` 的大小写顺序、`wc -m` 数出几个字符、`rev` 能不能处理中文，排出来的顺序和预想的不一样时，先看一眼 `locale`。二是第五章那条「名字和文件是两回事」又出现了一次：`tail -f` 跟住的是文件本身，名字挪走了它不会知道。

这八条命令的结果都只出现在屏幕上。下一章讲重定向：怎么把这些结果存进文件，或者直接交给下一条命令接着处理。
