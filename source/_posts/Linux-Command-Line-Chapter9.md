[第八章](/2026/09/28/Linux-Command-Line-Chapter8/) 讲的重定向，是把命令和文件连接起来。这一章讲的管道（pipe）在写法上和重定向很像，但是它连接的是两条命令，也就是把前一条命令的输出直接交给后一条命令处理，中间不需要经过任何文件。

有了管道以后，就可以把几条各自只做一件小事的命令串起来，完成一件比较复杂的事情。这一章还会介绍两条经常放在管道里使用的命令，一条是按字符替换和删除的 `tr`，另一条是在管道中间把数据另存一份的 `tee`。

## 一、管道 |：把输出交给下一条命令

管道的符号是竖线 `|`。`A | B` 的意思是，把命令 A 的标准输出作为命令 B 的标准输入。比如 `date` 会输出当前的时间，而[第七章](/2026/09/26/Linux-Command-Line-Chapter7/)介绍过的 `rev` 会把每一行倒过来。如果把这两条命令用管道连起来，就会得到一个倒着写的时间：

```bash
$ date | rev
6202 TSC 10:93:12 2  tcO irF
```

*代码 1：`date` 的结果没有显示在屏幕上，而是交给了 `rev`。*

这里的 `rev` 没有收到任何文件名，所以它会去读取标准输入，而它的标准输入已经被 Shell 连接到了 `date` 的标准输出上。和第八章的重定向一样，这一步连接也是 Shell 在启动命令之前就完成的。如果把三条命令串起来，那么中间那条命令的 0 号和 1 号都会连接在管道上：

```bash
$ echo hi | ls -l /proc/self/fd | cat
total 0
lr-x------ 1 zby zby 64 Oct  2 21:39 0 -> pipe:[1766811]
l-wx------ 1 zby zby 64 Oct  2 21:39 1 -> pipe:[1766813]
lrwx------ 1 zby zby 64 Oct  2 21:39 2 -> /dev/pts/2
lr-x------ 1 zby zby 64 Oct  2 21:39 3 -> /proc/193927/fd
```

*代码 2：`ls` 的 0 号连接着前一根管道，1 号连接着后一根管道，2 号仍然连接着终端。*

在第八章里，1 号连接的是一个文件，而这里连接的是 `pipe:[…]`。管道是内核里的一块缓冲区，前一条命令只能往里写，后一条命令只能从里面读。代码 2 里两根管道的编号不一样，这说明 `echo` 和 `ls` 之间、`ls` 和 `cat` 之间是两根互相独立的管道。

![date 的 1 号经过管道接到 rev 的 0 号，两条命令的 2 号都接着屏幕](/img/posts/linux-pipes/pipe.svg)

*图 1：管道连接的是前一条命令的 1 号和后一条命令的 0 号。*

### 1.1 管道和重定向的区别

因为管道和重定向的写法很像，所以两者很容易混用。重定向符号的后面是文件名，而管道符号的后面是命令。如果把 `date | rev` 误写成了 `date > rev`，Shell 并不会报错，而是会新建一个名叫 `rev` 的文件：

```bash
$ date > rev
$ ls
a.txt  fruits.txt  phones.txt  rev  sally.txt
$ cat rev
Fri Oct  2 21:39:03 CST 2026
```

*代码 3：`rev` 这条命令根本没有运行，当前目录里却多出了一个名叫 rev 的文件。*

另一个区别是，管道传过去的是数据的内容，而不是命令的参数。后一条命令只有在读取标准输入的时候，才能收到这些内容。比如 `ls` 只看参数，从来不读标准输入，所以即使把一个目录名通过管道交给它，它也不会理会，照样列出当前目录：

```bash
$ echo /usr/bin | ls
a.txt  fruits.txt  phones.txt  rev  sally.txt
```

*代码 4：`ls` 没有读取管道里的 `/usr/bin`，列出的仍然是当前目录。*

同样的道理，`echo fruits.txt | wc -l` 输出的是 1。这是因为 `wc` 数的是「fruits.txt」这一行文字，而不是这个文件里有几行。如果要统计文件的行数，应该写成 `wc -l fruits.txt` 或者 `cat fruits.txt | wc -l`。

## 二、只有标准输出会进入管道

管道连接的只是 1 号，2 号仍然连接着屏幕。所以前一条命令的报错不会进入管道，而是会直接显示出来：

```bash
$ cat a.txt missing.txt | wc -l
cat: missing.txt: No such file or directory
1
```

*代码 5：报错显示在屏幕上，`wc` 只数到了 a.txt 里的那一行。*

如果希望报错也一起进入管道，那么可以用第八章介绍过的 `2>&1`，让 2 号跟着 1 号走。bash 还提供了一个简写 `|&`，它和 `2>&1 |` 的效果是一样的：

```bash
$ cat a.txt missing.txt 2>&1 | wc -l
2
$ cat a.txt missing.txt |& wc -l
2
```

*代码 6：报错也进入了管道，所以 `wc` 数到了两行。*

第八章说过，Shell 是按照从左往右的顺序处理重定向的，所以 `2>&1` 要写在 `>` 的后面才有效。但是这里的 `2>&1` 写在 `|` 的前面，结果却是对的。这是因为 Shell 会先把管道接好，然后才处理这条命令自己的重定向。也就是说，当 Shell 处理到 `2>&1` 的时候，1 号已经连接在管道上了，于是 2 号跟过去的也是管道。

反过来，如果在 `|` 前面的命令里又把 1 号重定向到了文件，那么管道就收不到任何数据了：

```bash
$ ls > list.txt | wc -l
0
```

*代码 7：`ls` 的 1 号先接到了管道上，随后又被 `> list.txt` 改接到了文件，所以 `wc` 一行都没有收到。*

## 三、管道两边的命令同时运行

`A | B` 很容易被理解成先把 A 运行完，把结果存在某个地方，然后再运行 B。但是实际上，Shell 会同时启动管道两边的命令，A 一边往管道里写，B 一边从管道里读。下面这个例子可以看出这一点：

```bash
$ date +%T; sleep 3 | date +%T; date +%T
21:39:12
21:39:12
21:39:15
```

*代码 8：分号把三段命令隔开，按顺序执行；`+%T` 让 `date` 只输出时、分、秒。*

`sleep 3` 的作用是等待 3 秒。如果管道要等左边运行完才启动右边，那么第二行应该比第一行晚 3 秒。但是第二行和第一行是同一秒，这说明右边的 `date` 并没有等 `sleep` 结束。第三行比第一行晚了 3 秒，这是因为 Shell 要等管道里的所有命令都结束以后，才会接着执行后面的命令。

因为两边是同时运行的，所以即使左边的命令永远不会自己结束，管道也能正常工作。比如 `yes` 会不停地输出 `y`，直到被结束为止，而 `head -3` 只读取前三行：

```bash
$ yes | head -3
y
y
y
```

*代码 9：`yes` 本身不会停下来，但是这条命令立刻就结束了。*

`head` 读完三行就退出了，这时管道的另一头已经没有命令在读。于是 `yes` 再往管道里写的时候，系统就会直接结束 `yes`。如果管道真的要等左边运行完才启动右边，那么这条命令就会永远卡在那里。

### 3.1 同一个文件不要既读又写

第八章提到，`sort fruits.txt > fruits.txt` 会得到一个空文件，因为 `>` 在 `sort` 运行之前就已经清空了文件。如果换成管道的写法，问题仍然存在，而且结果变得不确定了：

```bash
cat fruits.txt | sort > fruits.txt
```

在这条命令里，`cat` 读取文件和 Shell 清空文件是同时进行的，谁先谁后要看当时的时机。用一个三行的文件重复运行 200 次，有 197 次得到的是空文件，只有 3 次内容完好。如果把文件换成 10 万行，还会出现只剩下两万多行的情况。所以处理同一个文件时，仍然要像第八章说的那样，先写到另一个文件里，确认无误以后再用 `mv` 替换回来。

## 四、tr：按字符替换和删除

`tr` 是 translate 的缩写。按照 `tr --help` 的说明，它从标准输入读取字符，经过替换、压缩或者删除以后，再写到标准输出。需要注意的是，`tr` 只读标准输入，不接受文件名参数。如果像 `cat` 那样把文件名写在后面，就会报错：

```bash
$ tr s S sally.txt
tr: extra operand ‘sally.txt’
Try 'tr --help' for more information.
```

*代码 10：`tr` 把 sally.txt 当成了一个多余的参数。*

所以要用管道或者 `<` 把文件的内容交给它：

```bash
$ cat sally.txt | tr s S
Sally SellS SeaShellS by the SeaShore
$ tr s S < sally.txt
Sally SellS SeaShellS by the SeaShore
$ cat sally.txt
Sally sells seashells by the seashore
```

*代码 11：两种写法的结果相同，而文件本身并没有改变。*

`tr` 只是把替换以后的结果写到了标准输出上，sally.txt 里的内容并没有改变。如果想保存结果，就要把输出重定向到另一个文件，比如 `tr s S < sally.txt > sally2.txt`。

### 4.1 一个字符对应一个字符

`tr s S` 里的 `s` 和 `S` 分别叫作 SET1 和 SET2。`tr` 会把输入中出现在 SET1 里的字符，换成 SET2 里同一位置上的字符。字符的范围可以用 `-` 来表示，所以 `tr a-z A-Z` 的作用就是把小写字母全部换成大写：

```bash
$ cat sally.txt | tr a-z A-Z
SALLY SELLS SEASHELLS BY THE SEASHORE
```

*代码 12：a 到 z 这 26 个字母，按顺序对应 A 到 Z。*

这里最容易想当然的地方在于，`tr` 处理的是单个字符，而不是字符串。比如想把 hello world 里的 world 换成大写，写成 `tr world WORLD` 看起来很自然，但是结果并不对：

```bash
$ echo 'hello world' | tr 'world' 'WORLD'
heLLO WORLD
```

*代码 13：hello 里的 l 和 o 也被换成了大写。*

这是因为 `tr world WORLD` 的意思是把 w 换成 W、o 换成 O、r 换成 R、l 换成 L、d 换成 D，它并不知道 world 是一个词。所以 hello 里的两个 l 和一个 o 也在表里，同样被换成了大写。如果要替换的是一个词或者一段字符串，那么就要换用别的工具（比如 `sed`），因为 `tr` 做不到这一点。

![tr world WORLD 的对照表，以及 hello world 里每个字符查表之后的结果](/img/posts/linux-pipes/tr-map.svg)

*图 2：`tr` 会对输入中的每一个字符单独查表。*

### 4.2 -d 删除，-s 压缩

加上 `-d` 选项以后，`tr` 只需要一个 SET1，作用是把其中的字符全部删除：

```bash
$ cat sally.txt | tr -d s
Sally ell eahell by the eahore
```

*代码 14：所有的小写 s 都被删掉了，而大写的 S 不受影响。*

`-s` 是 squeeze 的意思，它会把连续重复的同一个字符压缩成一个。比如一行文字里的空格有多有少，用 `tr -s ' '` 处理以后，每两个单词之间就只剩下一个空格：

```bash
$ echo 'a    b   c' | tr -s ' '
a b c
```

*代码 15：连续的几个空格被压缩成了一个。*

### 4.3 字符类要加引号

除了 `a-z` 这种范围以外，`tr` 还认识一些写成 `[:名字:]` 形式的字符类（character class）。常用的有下面这几个：

| 字符类 | 包含的字符 |
| --- | --- |
| `[:alpha:]` | 所有字母 |
| `[:digit:]` | 数字 0 到 9 |
| `[:upper:]`、`[:lower:]` | 大写字母、小写字母 |
| `[:blank:]` | 空格和制表符 |
| `[:space:]` | 空格、制表符、换行符等所有空白字符 |

比如下面这个文件里有名字和电话号码，删掉所有的字母和空格以后，就只剩下号码了：

```bash
$ cat phones.txt
Tom 138 0013 8000
Amy 139 1234 5678
$ cat phones.txt | tr -d '[:alpha:][:blank:]'
13800138000
13912345678
```

*代码 16：两个字符类可以写在同一个 SET1 里，一次就能删干净。*

这里也可以写成 `tr -d '[:alpha:]' | tr -d '[:blank:]'`，用两条 `tr` 分两步删除，结果是一样的。

但是字符类外面的引号不能省略。[第一章](/2026/08/25/Linux-Command-Line-Chapter1/)提到过，通配符是由 Shell 展开的。Shell 的通配符除了 `*` 以外还有方括号，比如 `[abc]` 表示 a、b、c 中的任意一个字符。所以对 Shell 来说，不加引号的 `[:alpha:]` 也是一个通配符，它匹配的是名字只有一个字符、而且这个字符是 `:`、`a`、`l`、`p`、`h` 之一的文件。如果当前目录里恰好有这样的文件，那么 Shell 在运行 `tr` 之前，就会先把它替换成文件名：

```bash
$ touch a
$ cat phones.txt | tr -d [:alpha:]
Tom 138 0013 8000
Amy 139 1234 5678
$ echo tr -d [:alpha:]
tr -d a
```

*代码 17：`[:alpha:]` 被展开成了文件名 `a`，所以 `tr` 只会删除小写字母 a，而文件里恰好一个小写 a 都没有。*

用 `echo` 把整条命令打印出来，就能看到 `tr` 实际收到的参数是 `a`。这个问题不会产生任何报错，而且只有当前目录里恰好有单个字母的文件名时才会出现，所以很难排查。如果给字符类加上了引号，Shell 就不会再去展开它。

`[:blank:]` 和 `[:space:]` 的区别在于换行符。因为 `[:space:]` 包含换行符，所以用它删除空白时，所有的行会被连成一行：

```bash
$ cat phones.txt | tr -d '[:alpha:][:space:]'
1380013800013912345678$
```

*代码 18：结尾的换行符也被删掉了，所以提示符 `$` 紧跟在了输出的后面。*

### 4.4 tr 和中文

Ubuntu 22.04 自带的 `tr`（GNU coreutils 8.32）是按字节处理的，而一个汉字在 UTF-8 编码下要占 3 个字节。所以 `echo '你好，世界' | tr -d '你'` 并不是只删掉「你」这一个字，而是把组成「你」的那 3 个字节从整行文字里全部删掉。「世」的第一个字节和「你」相同，「好」的最后一个字节和「你」的第二个字节相同，于是这两个字也被删坏了，输出变成了乱码。因此 `tr` 只适合处理英文字母、数字和符号这类单字节的字符。

## 五、tee：在管道中间另存一份

数据进入管道以后，会直接交给下一条命令，中间的结果并不会保存下来。`tee` 的作用就是在管道中间接出一个分支，它把经过的数据写进文件，同时原样交给下一条命令：

```bash
$ ls /usr/bin | tee cmds.txt | wc -l
949
$ wc -l cmds.txt
949 cmds.txt
```

*代码 19：`wc` 照常数出了 949 行，而 cmds.txt 里也保存了完整的 949 行。*

![ls 的输出经过 tee，一份写进 cmds.txt，另一份交给 wc -l](/img/posts/linux-pipes/tee.svg)

*图 3：tee 这个名字来自水管上的 T 形三通接头。*

`tee` 也可以放在管道的最后。这时它的标准输出就是屏幕，所以结果既会显示出来，也会保存进文件：

```bash
$ cat phones.txt | tr a-z A-Z | tee upper.txt
TOM 138 0013 8000
AMY 139 1234 5678
$ cat upper.txt
TOM 138 0013 8000
AMY 139 1234 5678
```

*代码 20：屏幕上能看到结果，upper.txt 里也保存了一份。*

`tee` 写文件的方式和 `>` 一样，也会先清空文件再写入。如果要追加到文件的末尾，就要加上 `-a` 选项，它的作用相当于 `>>`。另外，`tee` 后面可以写多个文件名，比如 `tee p1.txt p2.txt` 会把同样的内容分别写进两个文件。

和其他命令一样，`tee` 只能收到前一条命令的标准输出。如果想把报错也保存下来，就要在前面加上 `2>&1`，比如 `cat a.txt missing.txt 2>&1 | tee all.txt`。

## 小结

| 想做的事 | 写法 | 要点 |
| --- | --- | --- |
| 把输出交给另一条命令 | `A \| B` | 连接的是 A 的 1 号和 B 的 0 号，两边同时运行 |
| 报错也进入管道 | `A 2>&1 \| B` 或 `A \|& B` | 管道先接好，所以 `2>&1` 写在 `\|` 前面就可以 |
| 替换字符 | `tr a-z A-Z` | 只读标准输入；按字符一一对应，不能替换字符串 |
| 删除字符 | `tr -d '[:alpha:]'` | 字符类要加引号，否则可能被展开成文件名 |
| 压缩重复的字符 | `tr -s ' '` | 连续的同一个字符只留下一个 |
| 在中间另存一份 | `A \| tee 文件 \| B` | 会先清空文件，追加要用 `tee -a` |

这一章的几条命令都很短，但是它们背后是同一套规则。管道由 Shell 在命令启动之前接好，它连接的只是前一条命令的 1 号和后一条命令的 0 号。因为接好以后两边的命令是同时运行的，所以 `yes | head -3` 能够立刻结束，而 `cat f | sort > f` 的结果要看时机。又因为管道只连接 1 号，所以报错要加上 `2>&1` 才能进入管道，`tee` 也只能保存标准输出。至于 `tr` 和 `tee`，它们都从标准输入读取、往标准输出写，所以正好适合放在管道的中间。
