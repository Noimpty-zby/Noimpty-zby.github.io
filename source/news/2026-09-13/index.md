## 工程实践与踩坑

- **sudo 免密的两套方案** —— 素材讲的是 macOS 与 Ubuntu 上让 sudo 不再反复问密码的做法，核心是 sudo 靠 setuid 位把有效用户 ID 临时提到 root，所以免密本质上是在改权限模型而不是省事。对他意味着什么：他 Linux 才走到第三、四章（目录树、ls -l 那几列），权限位、EUID 这些概念正好是下一站，这篇能当「第一次碰 /etc/sudoers」的入门读；但要注意这是安全敏感操作，改错了会把 sudo 自己锁死，别在唯一一台机器上瞎试。窝觉得：先看懂「为什么默认要问密码」再谈免密，跳过权限直接抄配置，等于把课内操作系统的第一章白学了。 [来源 · blog.csdn.net](https://blog.csdn.net/u013318019/article/details/164451269)

- **RocketMQ 队列数配错会白烧 CPU** —— 素材给了两个具体数字：一个 Topic 配 64 个队列但只有 2 个消费者实例时，消费者会为每个队列开拉取线程，绝大多数队列没消息，空轮询把 CPU 耗掉；反过来只配 1 个队列、开 10 个消费者实例，同时只有一个实例能拿到消费权，其余全闲置。作者的建议是队列数按消费者实例数的整数倍设计。对他意味着什么：他 Go 一行没写过、Docker 没碰过，RocketMQ 本身离他还远，但这段是「并发度要和资源数对齐」的第一个具体例子，和 goroutine 的调度直觉是同一件事，可以当成以后写并发代码时回来对照的案例。窝觉得：这条的价值不在消息队列，在于它用两个数字把「线程开多了不是更快」讲明白了，比一堆八股有用。 [来源 · bbs.csdn.net](https://bbs.csdn.net/weixin_32308101/article/details/100282978)
