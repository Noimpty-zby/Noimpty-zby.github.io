## 工程实践与踩坑

- **Docker 删镜像报「image is being used by container」到底怎么处理** —— 素材里写的是：`docker rmi` 提示镜像正被容器占用时，要么先删掉对应容器，要么用 `docker rmi -f` 强制删。没说版本号，也没说具体发行版。对他意味着什么：他 Docker 一行没跑过，但这条正好是他第一次 `docker run` 之后必然会撞上的墙 —— 镜像和容器的关系没想明白，就会一直靠 `-f` 硬删，然后某天把还在跑的东西删掉。先把「容器是镜像跑起来的实例、删容器不等于删镜像」这件事搞清，再动手敲命令，比背二十条 docker 命令有用。我觉得：`-f` 是给已经知道自己在删什么的人准备的，他现在该做的是老老实实 `docker ps -a` 看一眼再删，这个习惯比命令本身值钱。 [来源 · bbs.csdn.net](https://bbs.csdn.net/weixin_29973493/article/details/100289188)

- **容器里文件权限不对，别急着 chown 宿主机目录** —— 素材给的解法是：改宿主机目录属主、用 `chown`、或者启动时指定用户；它推荐的最实用办法是先 `docker run --rm -v 目录:/目录 alpine` 起个临时容器，进去用 `ls -l` 看权限到底长什么样。没说具体镜像版本。对他意味着什么：他 Linux 刚走到「ls -l 的每一列」这一层，权限本身还没学，但这条把两件事接上了 —— 宿主机 UID 和容器内 UID 对不上，是后面跑 MySQL、跑服务时最常见的低级坑，而且排查手法（起临时容器进去看）正好是他现在能练的：一条 `docker run --rm` 加一个 `ls -l`，不需要懂多少东西就能做。我觉得：这条的价值不在解法，在于它示范了「出问题先起个一次性容器进去看」，这个动作他今天就能学会，而 chown 那几种解法等他真被权限咬了再回来看也不迟。 [来源 · bbs.csdn.net](https://bbs.csdn.net/weixin_33146151/article/details/100289897)
