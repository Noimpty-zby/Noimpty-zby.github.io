# 博客日报 · 配置说明

每晚北京时间 22:00，仓库里的定时任务会跑一遍：采数据 → 做检查 → 让娜娜莉写小结 → 发邮件给你。

访问统计等辅助来源失败时会在报告中标记。私密后端属于必需依赖：配置缺失、资料未迁移或读取失败时，任务停止，不把失败当成空日程、空日志或空账本。

---

## 一、这份报告里有什么

| 板块 | 数据来源 | 没配凭据时 |
|---|---|---|
| 访问情况 | GoatCounter 或 Umami API | 显示「没取到」，其余照常 |
| 新评论 + 垃圾筛查 | GitHub Discussions（Giscus 的后端） | 自动可用，无需配置 |
| 新文章 + 娜娜莉读后反馈 | 仓库里的 git 记录 | 自动可用；没有 DeepSeek key 则跳过反馈 |
| 私密日程、行动记录、模型用量 | 鉴权后端的 `schedule`、`journal`、`usage` 记录 | 停止任务并报告配置或读取失败 |
| 健康检查 | 你的线上站点 + GitHub API | 自动可用 |

### 模型用量那块怎么读

只报 token，**不报钱** —— 单价会变，各家计费口径也不一样，编一个金额出来比不给更糟。
要折算就拿这些数乘当时的单价。

盯**未命中缓存的输入**那一行：命中和未命中是两个价钱，涨钱基本都涨在这一列。
旁边的「七天日均」才是判断依据 —— 单看「昨天 26k」说明不了任何事，能看出问题的是「比平时多一倍」。
下面按任务分行（批注、回评、巡逻、资讯正文、小结……），走推理模型的会单独标「（推理）」，
因为那不是一个价钱。想省钱，从排在最上面那项开始看。

两个 job 分别暂存本次新增条目，结束时读取最新记录并通过版本比较保存；并发冲突会重新合并并有限次重试。不会提交 Git 或触发站点部署。
用量仅存入私密后端，不发布静态文件，也不进入公开内容生成提示词。
保留 90 天、最多 600 条，超了自动滚掉。

### 健康检查查什么

博客页面由 GitHub Pages 静态托管，私密资料与练习执行另有鉴权后端。日报健康检查主要关注泄漏和可用性，不能替代前端、后端及运行环境的安全审查：

1. **受保护页面泄漏** —— 标了 `privacy: protected` 的文章有没有混进 `atom.xml` / `sitemap.xml` / `search.xml` / 首页 / 归档页。**这条最重要**
2. **站点可用性** —— 首页能不能打开、SSL 证书还有多少天
3. **自动部署** —— 最近的构建有没有失败（红了你可能好几天发现不了）
4. **依赖漏洞** —— Dependabot 的新增告警，翻译成人话
5. **死链与坏图** —— 从锁清单出发爬一遍，检查站内链接和图片
6. **娜娜莉的模型** —— 今晚这几次调用有没有挂。她哑了的时候，这封邮件里的「人话」会悄悄全变成模板，不留一行的话没人发现得了

## 二、要往仓库 Secrets 里放什么

位置：仓库 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**

> Secrets 是加密存储的。**存进去之后连你自己都看不到明文**，也不会出现在 Actions 日志里。
> 这和娜娜莉在浏览器里那把 key 是同一把，但存的地方完全不同，互不影响。

### 必需的私密后端

| 名字 | 要求 |
|---|---|
| `NANALY_AGENT_URL` | 私密 API 的 HTTPS Origin，不含路径 |
| `NANALY_AGENT_TOKEN` | 后台令牌，可读取四种资料并更新日程、日志、用量；不能修改背景资料 |

先完成后端部署和四份资料迁移；即使是空数据，也须已写入后端并拥有非零版本。`/api/automation/context` 仍然只返回主人明确允许公开的记忆与经验。

### 发信凭据（不配就发不出邮件）

| 名字 | 值 | 怎么拿 |
|---|---|---|
| `GMAIL_USER` | 你的 Gmail 地址 | — |
| `GMAIL_APP_PASSWORD` | 16 位应用专用密码 | <https://myaccount.google.com/apppasswords>（需先开两步验证）。**不是你的登录密码** |
| `REPORT_TO` | 收件地址 | 不填就发给 `GMAIL_USER` 自己 |

### 建议配（不配则降级）

| 名字 | 值 | 不配的后果 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 和娜娜莉用的同一把 | 小结和读后反馈变成模板文字，健康检查里「娜娜莉的模型」会亮黄灯说明原因，其余不受影响 |

### 访问统计：二选一

**方案 A — GoatCounter（推荐，免费）**

| 名字 | 值 |
|---|---|
| `GOATCOUNTER_CODE` | 你注册时选的站点代号，也就是 `xxx.goatcounter.com` 里的 `xxx` |
| `GOATCOUNTER_TOKEN` | 设置 → API → 新建 token，勾选「读取统计」权限 |

**方案 B — Umami（API 需付费订阅）**

| 名字 | 值 |
|---|---|
| `UMAMI_API_KEY` | cloud.umami.is → Settings → API keys |
| `UMAMI_WEBSITE_ID` | 就是埋点脚本里的 `data-website-id` |

两个都不配也能跑，只是访问那一格显示「没取到」。

## 三、先手动跑一次

别等到晚上才发现配错了。

仓库 → **Actions** → 左侧选「博客日报」→ 右上 **Run workflow**：

- **勾上 `dry`** → 只生成不发送、不保存私密修改。公开仓库不会上传含私密日程的报告产物；需要预览时在自己的本地环境生成并打开
- **不勾** → 真发一封给你

先勾着跑一次，确认内容对了，再取消勾选跑一次验证发信。

## 六、已知限制

- **GitHub 定时任务会漂移**，几分钟到半小时都正常，尤其是整点。想要准时得换别的调度器
- **Dependabot 告警**默认的 `GITHUB_TOKEN` 读不到，需要额外权限。读不到时那一格会显示「先跳过」，不影响其他检查
- **死链检查**最多扫 60 个页面、400 个地址，够你现在的规模用，文章多了要调
- **新文章判据**是「git 里有改动 **且** front-matter 的 `date` 在两天内」。只改错别字不会重新触发点评；批量重构也不会被误判成发了十几篇新文章
