# 策划室 · 私有仓库

这个仓库存放游戏策划的全部内容。它**必须是私有的** —— 博客仓库是公开的，
里面一个字节都不会有这些东西。

## 目录结构

```
charter.md              总纲。你写，AI 每次必读，它不会改这个文件。
state.json              全局状态机。AI 维护，你一般不用管。
explore/                探索记录，每次探索一份，按日期命名。
projects/
  P01-<slug>/           每个立项一个文件夹
    meta.json           状态、版本号、负面反馈连击数
    00-pitch.md         立项书
    01-pillars.md       设计支柱
    02-core-loop.md     核心循环
    03-systems.md       系统设计
    04-content.md       内容与进程
    05-tech.md          技术方案
    06-production.md    生产计划
    07-competitive.md   竞品与风险登记
    CHANGELOG.md        每次改了什么、为什么
    POSTMORTEM.md       停更说明（只有停掉的项目才有）
feedback/
  inbox.json            你的反馈。策划室页面上写，AI 读完标记已处理。
```

## 它是怎么跑的

一周三次（周一 / 周四 / 周六晚上 9 点），每次跑**一件事**。做哪件由代码决定：

1. **有你的反馈没处理** → 修订。你的输入永远排第一。
2. **某个项目该停了** → 停更评估。及时止损比继续产出重要。
3. **有立项、文档没写完** → 深化，写下一份文档。
4. **有够格的候选方向（4 星以上）、活跃项目不满 2 个** → 立项。
5. **什么都没有** → 探索新方向。

一份完整的策划案是 8 份文档，一周三次的话大概三周写完一个项目。
中间你的反馈会插队 —— 那是设计如此，反馈比产量重要。

## 你要做的只有两件事

**第一件：把 `charter.md` 填了。** 这是唯一的地基。填得含糊，产出就是通用废话。

**第二件：读，然后给反馈。** 在博客的「策划室」页面上，每篇文档底部有反馈框。
评价四选一，加一段文字说明。下次跑的时候 AI 会逐条回应。

反馈里最有价值的不是「好」或「不好」，是**具体哪一句让你觉得不对**。
「第三节那个数值我做不出来」比「可行性差」有用得多。

## 几件值得知道的事

- **它可以不同意你。** 提示词里明确写了：如果它认为你的反馈判断有误，
  可以不改，但必须写清楚理由。一个唯唯诺诺的主策划没有用。
- **它可以说「这个方向不值得做」。** 立项书的最后一节允许写这个结论。
  在立项阶段发现不成立，比做两个月才发现便宜得多。
- **交白卷是合格的输出。** 探索那一步如果没找到值得写的方向，它会明说，
  而不是硬凑四个。
- **停更不是失败。** POSTMORTEM.md 里会写清楚什么条件下这个想法会重新成立 ——
  停掉的项目也是资产。

## 手动跑一次

```bash
# 演练，不写任何东西
node tools/studio/run.mjs --dry

# 强制某个动作
node tools/studio/run.mjs explore
node tools/studio/run.mjs expand
```

也可以在博客仓库的 Actions 里手动触发「策划室」这个工作流。
