# 策划室 · 私有仓库

这个仓库存放游戏策划的全部内容。它**必须是私有的** —— 博客仓库是公开的，
里面一个字节都不会有这些东西。

## 它在优化什么

⭐ 先说清楚，因为这一版最大的改动就是这个：

**这个游戏不是做给你自己玩的。它是参赛作品 + 简历作品。**

所以整套系统的目标函数不是「设计一个好玩的游戏」，是
**「设计一个能让评委停下来、能让面试官追问十分钟的东西」**。
这两个目标经常是冲突的，冲突的时候以评审为准。

具体的判据写在两份账本里，AI 每次都会带着它们跑：

- `tools/studio/ue5.mjs` —— UE5 能力账本：对你来说什么便宜、什么贵
- `tools/studio/audience.mjs` —— 评审视角账本：评委和面试官实际是怎么看的

## 目录结构

```
charter.md              总纲。你写，AI 每次必读，它不会改这个文件。
lessons.md              教训清单。AI 写，每次停更 / 否决往里追加一条。
                        探索时必读 —— 这是整套系统唯一的长期记忆。
state.json              全局状态机。AI 维护，你一般不用管。
explore/
  YYYY-MM-DD-N.md       探索记录（带轮次号，同一天跑两次不会互相覆盖）
  评比-YYYY-MM-DD-N.md  候选横向评比：排名、第一名、淘汰了谁
  审查-YYYY-MM-DD-N-x.md 立项前的硬约束校验记录
projects/
  P01-<slug>/           每个立项一个文件夹
    meta.json           状态、赛道、版本号、负面反馈连击数
    00-pitch.md         立项书
    01-showcase.md      参赛与展示方案 ← 排在这么前面是故意的，见下
    02-pillars.md       设计支柱
    03-core-loop.md     核心循环
    04-systems.md       系统设计
    05-content.md       内容与进程
    06-tech.md          技术方案
    07-production.md    生产计划
    08-competitive.md   竞品与风险登记
    CHANGELOG.md        每次改了什么、为什么
    AUDIT.md            硬约束重审的结果（跑过 audit 才有）
    POSTMORTEM.md       停更说明（只有停掉的项目才有）
experiments/
  <项目 id>.json        实验台：可证伪的主张 + 你回填的真实结果
feedback/
  inbox.json            你的输入。策划室页面上写，AI 读完标记已处理。
```

**为什么「参赛与展示方案」排在支柱和玩法之前**：因为目标函数是参赛和简历。
先把「评委看到的 90 秒」「面试官会问的 8 个问题」「简历上那一行」钉死，
后面每一份文档都有尺子可量。放到最后写的话，它就只能给已经做完的东西补一段说明。

## 它是怎么跑的

一周三次（周一 / 周四 / 周六晚上 9 点），每次跑**一件事**。做哪件由代码决定：

0. **你点名置顶的方向** → 立项（仍然要过一次独立的硬约束校验）
1. **有实验跑出了真实结果** → 修订。一手数据的分量高于任何一轮推理。
2. **某个项目该停了** → 停更评估。及时止损比继续产出重要。
3. **有你的反馈没处理** → 修订。
4. **有立项、文档没写完** → 深化，写下一份文档。
5. **有够格的候选方向（4 星以上）、活跃项目不满 2 个** → 立项。
6. **候选攒够 6 个但一个够格的都没有** → 横向评比，选出第一名。
7. **什么都没有** → 探索新方向。

一份完整的策划案是 9 份文档，一周三次的话大概三周多写完一个项目。
中间你的输入会插队 —— 那是设计如此。

## 你要做的三件事

**第一件：把 `charter.md` 填了。** 这是唯一的地基。填得含糊，产出就是通用废话。
特别是**第二节**（参赛与展示目标）—— 那一节定义了「什么叫做对了」。
比赛定下来之后回去补上截止时间和评分表，整套东西就有了真正的尺子。

**第二件：在方向阶段就插手。** 策划室页面的「候选方向」里，每个方向都有三个按钮：

- **就它了，立项** —— 跳过「扫够几轮」那道等待门槛，下次跑直接进立项流程。
  （活跃项目满员的话它会在候选池里置顶排队，一有空位自动立项，不用你再点一次。
  硬约束校验还是会跑 —— 撞了约束它会拦下并告诉你否在哪一条。）
- **加一星** —— 轻推
- **否掉** —— 移出候选池，写进否决清单，以后换个名字端上来也会被拦

上一版你唯一的入口是「读完某份文档给个评价」，也就是**必须先立项你才说得上话**。
而立项恰恰是最贵、最难回头的一步。这三个按钮就是补这个洞的。

**第三件：做实验，回填结果。** 每份文档末尾会附 1~3 条**可证伪的主张**：
做什么最小原型、看什么现象、什么结果算这条主张被推翻。它们在页面的「实验台」里。

你随便做掉一条，回来填上真实结果 —— 那是这套系统唯一能拿到的一手证据。
提示词里明说了：**数据面前不许辩论，直接按数据改。**

## 几件值得知道的事

- **探索的时候它看不到你的口味。** 总纲第六节（附录：我的口味）在探索阶段
  被系统整节删掉。原因是第一版把它留在上下文里，还配了三段「别看这一节」的警告，
  结果第一轮扫出来的三个方向全是那一节里那个例子的变体。
  告诉模型「别看这段」等于让它盯着这段看 —— 所以现在的做法是物理的。
- **多样性由代码保证，不由提示词保证。** 每个方向必须声明一条「赛道」
  （亮点来源：程序化生成 / 物理与破坏 / 运行时几何 / 材质与后处理 /
  大规模模拟 / 时间与因果 / 空间与视角 / 规则涌现）。
  同一轮里赛道撞车的会被自动降到 2 星。
  「纯代码表现层」（顿帧、镜头、打击感）**不能当主赛道** ——
  截图里看不见、面试问不深，两条评分维度同时归零。
- **星级是算出来的，不是它给自己打的。** 四维打分：一眼可辨 / 技术讲点 /
  可完成 / 独特，由代码汇总，**短板决定上限** —— 任何一维给到 1 或 2，
  这个方向就上不了 4 星，其它三维再高也补不回来。
- **它可以不同意你。** 提示词里明确写了：如果它认为你的反馈判断有误，
  可以不改，但必须写清楚理由。一个唯唯诺诺的主策划没有用。
  唯一的例外是实验数据 —— 那不是意见。
- **它可以说「这个方向不值得做」。** 立项书最后一节允许写这个结论。
- **交白卷是合格的输出。** 探索那一步如果没找到值得写的方向，它会明说。
- **停更不是失败。** POSTMORTEM.md 会写清什么条件下这个想法会重新成立，
  并且往 `lessons.md` 追加一条**可以拿去检查别的方向**的规则。

## 手动跑一次

```bash
# 演练，不写任何东西
node tools/studio/run.mjs --dry

# 强制某个动作
node tools/studio/run.mjs explore
node tools/studio/run.mjs shortlist   # 把现有候选摆一起比一次
node tools/studio/run.mjs expand
node tools/studio/run.mjs audit       # 拿硬约束把某个已立项的项目重审一遍
```

也可以在博客仓库的 Actions 里手动触发「策划室」这个工作流。
